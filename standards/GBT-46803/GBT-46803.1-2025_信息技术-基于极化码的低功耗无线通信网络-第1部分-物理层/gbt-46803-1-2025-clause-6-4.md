# 6.4 物理层数据信息传输

(gbt-46803-1-2025-clause-6-4-1)=
## 6.4.1 异步数据传输

(gbt-46803-1-2025-clause-6-4-1-1)=
### 6.4.1.1 异步数据传输的交互流程

:::{div}
:class: standard-paragraph

<p>异步数据传输支持数据单播传输、数据组播传输、反馈组播传输、双向组播传输。</p>

:::

:::{div}
:class: standard-paragraph

<p>异步数据传输用于系统 G 节点与 T 节点以及两个 T 节点间进行可靠传输。在异步数据传输过程中,对于发送端发送的数据包,按不同的无线帧类型分别有如下规定。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于无线帧类型1有如下规定:</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 如果接收端接收正确并反馈正确信息,发送端接收到该反馈信息,发送端可继续发送后续数据,此时数据包的发送序列号翻转;</p>
</li>
<li><p>b) 如果接收端接收正确并反馈正确信息,发送端没有接收到该反馈信息,发送端需要重传该数据包,此时重传数据包的发送序列号不变;接收端接收到该发送序列号不变的数据包时,需要反馈正确信息;</p>
</li>
<li><p>c) 如果接收端接收错误并反馈错误信息,发送端接收到该反馈信息,发送端需要重传该数据包,此时重传数据包的发送序列号不变,接收端接收到该发送序列号不变的数据包时,根据该数据包的控制信息进行数据接收;</p>
</li>
<li><p>d) 如果接收端接收错误并反馈错误信息,发送端没有接收到反馈信息,发送端需要重传该数据包,此时重传数据包的发送序列号不变,接收端接收到该发送序列号不变的数据包时,根据该数据包的控制信息进行数据接收;</p>
</li>
<li><p>e) 如果接收端没有接收该数据包,也不反馈任何信息,发送端没有接收到接收端的反馈信息,发送端需要重传该数据包,此时重传数据包的发送序列号不变,接收端接收到数据包时,根据该数据包的控制信息进行数据接收。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>对于无线帧类型2有如下规定:</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 如果接收端接收正确并反馈正确信息,发送端接收到该反馈信息,发送端可继续发送后续数据,此时数据包的发送序列号翻转,MCS不配置为15;</p>
</li>
<li><p>b) 如果接收端接收正确并反馈正确信息,发送端没有接收到该反馈信息,发送端需要重传该数据包,此时重传数据包的发送序列号不变,MCS不配置为15;接收端接收到该发送序列号不变的数据包时,需要反馈正确信息;</p>
</li>
<li><p>c) 如果接收端接收错误并反馈错误信息,发送端接收到该反馈信息,发送端需要重传该数据包,此时重传数据包的发送序列号不变,MCS不配置为15,接收端接收到该发送序列号不变的数据包时,根据该数据包的控制信息进行数据接收;</p>
</li>
<li><p>d) 如果接收端接收错误并反馈错误信息,发送端没有接收到反馈信息,发送端需要重传该数据包,此时重传数据包的发送序列号不变,MCS不配置为15;接收端接收到该发送序列号不变的数据包时,根据该数据包的控制信息进行数据接收;</p>
</li>
<li><p>e) 如果接收端没有接收该数据包,也不反馈任何信息,发送端没有接收到接收端的反馈信息,发送端需要重传该数据包,此时重传数据包的发送序列号不变,MCS不配置为15;接收端接收到数据包时,根据该数据包的控制信息进行数据接收。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>对于无线帧类型3和无线帧类型4有如下规定。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 如果接收端接收正确并反馈正确信息,发送端接收到该反馈信息,发送端可继续发送后续数据,此时数据包的发送序列号翻转,MCS不配置为15。</p>
</li>
<li><p>b) 如果接收端接收正确并反馈正确信息,发送端没有接收到该反馈信息,发送端需要重传该数据包,此时重传数据包的发送序列号不变,MCS不配置为15,接收端接收到该发送序列号不变的数据包时,需要反馈正确信息;或者,当发送端之前接收到接收端针对该数据包的基于CBG 的部分正确反馈信息时,发送端需要重新发送该数据包最近一次信道编码后的数据,此时重传数据包的发送序列号不变,MCS配置为15,接收端接收到该发送序列号不变的数据包时,须根据该数据包最近一次信道编码时的配置进行数据接收。</p>
</li>
<li><p>c) 如果接收端接收错误并反馈错误信息,发送端接收到该反馈信息,发送端需要重传该数据包,此时重传数据包的发送序列号不变,MCS不配置为15,接收端接收到该发送序列号不变的数据包时,根据该数据包的控制信息进行数据接收;或者发送端需要重新发送该数据包最近一次信道编码后的数据,此时重传数据包的发送序列号不变,MCS配置为15,接收端接收到该发送序列号不变的数据包时,须根据该数据包最近一次信道编码时的配置进行数据接收。</p>
</li></ol>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="4">
<li><p>d) 如果接收端接收错误并反馈错误信息,发送端没有接收到反馈信息,发送端需要重传该数据包,此时重传数据包的发送序列号不变,MCS不配置为15;接收端接收到该发送序列号不变的数据包时,根据该数据包的控制信息进行数据接收;或者,当发送端之前接收到接收端针对该数据包的基于 CBG 的部分正确反馈信息时,发送端需要重新发送该数据包最近一次信道编码后的数据,此时重传数据包的发送序列号不变,MCS配置为15,接收端接收到该发送序列号不变的数据包时,须根据该数据包最近一次信道编码时的配置进行数据接收。</p>
</li>
<li><p>e) 如果接收端没有接收到发送节点发送的数据包,也即发送节点物理层控制信息的 CRC校验不通过时,该接收端也不反馈任何信息,发送端没有接收到接收端的反馈信息,发送端需要重传该数据包,此时重传数据包的发送序列号不变,MCS不配置为15,接收端接收到数据包时,根据该数据包的控制信息进行数据接收;或者发送端需要重新发送该数据包最近一次信道编码后的数据,此时重传数据包的发送序列号不变,MCS配置为15,接收端接收到该发送序列号不变的数据包时,须根据该数据包最近一次信道编码时的配置进行数据接收。</p>
</li>
<li><p>f) 对于一个事件,当后发节点没有接收到先发节点发送的数据包,也即先发节点物理层控制信息的CRC校验不通过时,该后发节点在本次事件中不发送任何信息。从而,先发节点也不能在本次事件中接收到后发节点发送的数据包,也即后发节点物理层控制信息的 CRC 校验不通过。此时,先发节点和后发节点都停止在本次事件组中交互数据,并在下一次事件组中继续交互数据。在下一次事件组中的第一事件中,先发节点需要重传数据包。当先发节点配置为基于 TB进行反馈时,8位 HARQ 字段应配置为希望后发节点传输数据包的序列号,当先发节点配置为基于 CBG 进行反馈时,8位 HARQ 字段应配置为上一次发送数据包时物理层控制信息中8位 HARQ 字段相同的数值。</p>
</li>
<li><p>g) 对于一个事件,当先发节点没有接收到上一个事件中后发节点发送的数据包,也即后发节点物理层控制信息的 CRC校验不通过时,该先发节点在本次事件中不发送任何信息。从而,后发节点也不能在本次事件中接收到先发节点发送的数据包,也即先发节点物理层控制信息的CRC校验不通过。此时,先发节点和后发节点都停止在本次事件组中交互数据,并在下一次事件组中继续交互数据。在下一次事件组中的第一事件中,先发节点需要重传数据包。当先发节点配置为基于 TB进行反馈时,8位 HARQ 字段应配置为希望后发节点传输数据包的序列号,当先发节点配置为基于 CBG 进行反馈时,8位 HARQ 字段应配置为上一次发送数据包时物理层控制信息中8位 HARQ 字段相同的数值。</p>
</li>
<li><p>h) 当节点配置为基于 CBG 进行反馈,该节点发送的物理层控制信息中8位 HARQ 字段中对应的 CBG 指示全部为1,也即所有 CBG 全部正确接收,但该节点没有收到对端节点发送的数据包时,该节点需要重传数据包,同时物理层控制信息中的8位 HARQ 字段中对应的CBG 指示全部为0,也即所有 CBG 全部没有正确接收。</p>
</li>
<li><p>i) 当节点配置为基于 CBG 进行反馈,并且该节点发送的物理层控制信息中8位 HARQ 字段配置为全零时,对端节点需根据之前信息的交互过程判断传输新包还是重传旧包,当之前信息的交互已经指示部分 CBG 接收正确时,对端节点判断需传输新包,当之前信息的交互没有指示任何一个 CBG 接收正确时,对端节点判断需重传旧包。当对端节点传输新包时,发送序列号不变,MCS不配置为15,当对端节点重传旧包时,发送序列号反转,MCS不配置为15。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>对于单播传输,指示相邻两个事件中前一个事件的结束时刻与后一个事件的开始时刻的时间差根据事件间间隔确定。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于组播传输,事件的开始时刻根据高层信令配置。</p>

:::

(gbt-46803-1-2025-clause-6-4-1-3)=
### 6.4.1.3 异步数据传输流控

:::{div}
:class: standard-paragraph

<p>对于单播有如下规定。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 对于先发节点,当满足如下两种条件之一,先发节点不使用事件组中之后的事件发送消息。其</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>他情况先发节点自行决定是否在当前事件组中之后的事件中发送消息:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>● 一个事件中,先发节点发送流控信息为0的消息,且收到后发节点的消息中:流控信息为“0”、反馈信息为“成功”、数据长度指示信息为“0”;</p>
<ul class="standard-list">
<li><p>● 一个事件中,先发节点发送了消息,且未收到后发节点发送的消息。</p>
</li></ul>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="2">
<li><p>b) 对于后发节点,一个事件中,后发节点未收到先发节点发送的消息,则不在当前事件以及事件组中之后的事件发送消息。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>对于数据组播的半可靠传输模式有如下规定:</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 对于组长节点,当满足如下条件时,组长节点不在事件组中之后的事件发送消息:组长节点发送流控信息为“0”的消息,且未收到任何组员节点的接收错误反馈;</p>
</li>
<li><p>b) 其他情况组长节点自行决定是否在当前事件组中之后的事件中发送消息。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>对于数据组播的非半可靠传输模式,以及双向组播:</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 对于组长节点,当满足如下条件时,组长节点不在事件组中之后的事件发送消息:一个事件中,组长节点发送流控信息为“0”的消息,收到所有组员节点的消息,且每一条组员节点发送的消息中:流控信息为“0”、反馈信息为“成功”、数据长度指示信息为“0”;</p>
</li>
<li><p>b) 其他情况组长节点自行决定是否在当前事件组中之后的事件中发送消息。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>对于反馈组播:</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">

## 6.4.2 同步数据传输

(gbt-46803-1-2025-clause-6-4-2-1)=
### 6.4.2.1 概述

:::{div}
:class: standard-paragraph

<p>同步数据传输支持数据单播传输、数据组播传输、反馈组播传输、双向组播传输、异步广播传输、同步广播传输。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于同步数据传输,发送节点的每一个数据包只有有限次发送机会,发送节点只能在有限的时间内重传发送该数据包。数据包重传到一定时间后,发送节点不再重传该数据包。对于单播传输、数据组播传输、反馈组播传输、双向组播传输,接收节点支持给发送节点发送数据包确认信息。</p>

:::

:::{div}
:class: standard-paragraph

<p>单播传输、数据组播传输、反馈组播传输、双向组播传输通过异步数据传输建立,每一条同步数据传输绑定一条异步数据传输,同步数据传输的参数变更消息由异步数据传输。异步数据传输断开时,与之绑定的同步数据传输也相应断开。</p>

:::

:::{div}
:class: standard-paragraph

<p>异步广播传输、同步广播传输通过扩展广播配置和变更。</p>

:::

(gbt-46803-1-2025-clause-6-4-2-2)=
### 6.4.2.2 同步数据传输参数

:::{div}
:class: standard-paragraph

<p>同步数据传输的参数如下:</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 事件组起始时刻:事件组包含的多个事件中,最早的事件起始时刻;</p>
</li>
<li><p>b) 事件组周期:两个相邻的事件组起始时刻的时间差;</p>
</li>
<li><p>c) 事件周期:两个相邻的事件起始时刻的时间差;</p>
</li>
<li><p>d) 事件内间隔:在一次事件中,先发节点的传输结束时刻与后发节点传输开始时刻间的时间;</p>
</li>
<li><p>e) 事件间间隔:在一个事件组内的相邻两个事件中,前面事件的传输结束时刻与后面事件的传输开始时刻间的时间;</p>
</li>
<li><p>f) 事件组间间隔:对于相邻的两个事件组,前面事件组最后一个事件的传输结束时刻与后面事件组第一个事件的传输开始时刻间的时间;</p>
</li>
<li><p>g) 事件总数:1个事件组包含的事件的最大值;</p>
</li></ol>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="8">
<li><p>h) 事件编号:一个事件组周期间隔内的事件编号值;</p>
</li>
<li><p>i) 新包个数:一个事件组周期内可传输的新数据包的最大个数;</p>
</li>
<li><p>j) 新包编号$:N$个事件组周期内传输的新数据包的顺序编号,取值范围为$[0,31],N$的数值为(32/新包个数);</p>
</li>
<li><p>k) 有效载荷计数:有效载荷的编号累加值;</p>
</li>
<li><p>l) 数据丢弃周期:单个数据包可跨越的最大事件组周期间隔个数;</p>
</li>
<li><p>m) 业务适配方式指示:表示服务数据是周期适配方法还是非周期适配方法;</p>
</li>
<li><p>n) 先发后发指示:指示信令接收方在事件中先发送数据还是后发送数据;</p>
</li>
<li><p>o) 先发节点协议数据单元最大值:先发节点发送的数据包的协议数据单元的最大值,以字节为单位;</p>
</li>
<li><p>p) 后发节点协议数据单元最大值:后发节点发送的数据包的协议数据单元的最大值,以字节为单位;</p>
</li>
<li><p>q) 先发节点最大传输时长:先发节点发送的数据包的最大时长,以微秒为单位;</p>
</li>

</li>
<li><p>s) 先发时间偏移量:从先发节点发送数据的起始时刻开始,经过先发节点传输时长,到事件内间隔为止,然后按照时隙向后对齐后的总时间,以时隙为单位;</p>
</li>
<li><p>t) 后发时间偏移量:从后发节点发送数据的起始时刻开始,经过后发节点传输时长,到事件间间隔为止,然后按照时隙向后对齐后的总时间,以时隙为单位;</p>
</li>
<li><p>u) 先发最大时间偏移量:从先发节点发送数据的起始时刻开始,经过先发节点最大传输时长,到事件内间隔为止,然后按照时隙向后对齐后的总时间,以时隙为单位;</p>
</li>
<li><p>v) 后发最大时间偏移量:从后发节点发送数据的起始时刻开始,经过后发节点最大传输时长,到事件间间隔为止,然后按照时隙向后对齐后的总时间,以时隙为单位;</p>
</li>
<li><p>w) 事件最大长度:每一个事件的最大时长,事件长度$=$先发最大时间偏移量+后发最大时间偏移量,事件最大长度应小于或等于事件周期;</p>

<li><p>x) 先发节点服务数据单元最大值:事件组对应的先发节点服务数据单元最大值,一个服务数据单元可分段成多个协议数据单元;</p>

### 6.4.2.4 数据丢弃机制

:::{div}
:class: standard-paragraph

<p>同步数据传输支持主动数据丢弃机制。发送节点可自主决定数据包的重传次数,可选择丢弃该数据包,直接发送下一个数据包。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于无线帧类型1和无线帧类型2,接收节点通过事件组编号和新包个数计算本地基准值,再通过该基准值和数据包的发送序列号得到传输有效载荷的计数值,从而判断接收到的数据包是新传包还是重传包。其中,发送序列号表示一个事件组周期间隔内数据包的编号,相同编号的数据包对应相同的有效载荷,不同事件组周期间隔内不同编号的数据包可能相同,也可能不同,其赋值方法为:</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 发送序列号从0开始计数;</p>
</li>
<li><p>b) 收到接收正确信息,发送序列号等于(发送序列号+1);</p>
</li>
<li><p>c) 收到接收错误信息或没有收到回复,发送序列号保持不变;</p>
</li>
<li><p>d) 跨事件组时,发送序列号等于(发送序列号-新包个数);</p>
</li>
<li><p>e) 若出现小于0,则发送序列号等于0。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>本地基准值表示在某一个事件组内能收到的最小的有效载荷计数值,其计算方法如下所示:</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 当[事件组编号&lt;数据丢弃周期]时,本地基准值等于0;</p>
</li>
<li><p>b) 当[事件组编号$\geq$数据丢弃周期]时,本地基准值等于[新包个数$\times ($事件组编号-数据丢弃周期+1)]。</p>
</li></ol>

:::

(gbt-46803-1-2025-clause-6-4-2-5)=
### 6.4.2.5 事件组与事件组集合

:::{div}
:class: standard-paragraph

<p>多个事件组可配置成事件组集合,事件组集合包含的多个事件组应在应用的业务层面具有时间关联性。事件组集合的参数如下:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 事件组数量:一个事件组集合包含的具有相同事件组周期的事件组的数量,[1,31];</p>
</li>
<li><p>——— 事件组间隔:事件组集合包含的多个事件组中,相邻两个事件组之间开始时刻的时间偏移值,以系统基础时隙为单位。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>事件组集合的起始时刻是该事件组集合包含的多个事件组中最早的事件组起始时刻。</p>

:::

:::{div}
:class: standard-paragraph

<p>事件组集合的结束时刻是该事件组集合包含的多个事件组中最晚的传输的结束时刻。事件组集合的时间资源不能交叠。</p>

:::

:::{div}
:class: standard-paragraph

<p>事件组集合有一个时间同步参考点和时间同步锚点。每一个事件组集合不能早于时间同步参考点,不能晚于时间同步锚点。</p>

:::

:::{div}
:class: standard-paragraph

<p>当事件组被关闭时,不再进行本事件组中的后续事件。</p>

:::

### 6.4.2.10 广播传输

(gbt-46803-1-2025-clause-6-4-2-10-1)=

:::{div}

:::

:::{div}
:class: standard-paragraph

<p>同步广播传输支持多个事件组组成一个事件组集合。每个事件组内包含一个或多个同步单向事件和最多一个控制事件。控制事件在每一个事件组内非必要存在。</p>

## 6.4.3 同步数据传输业务适配

(gbt-46803-1-2025-clause-6-4-3-1)=
### 6.4.3.1 概述

:::{div}
:class: standard-paragraph

<p>同步数据传输业务适配支持两种适配方法,分别为周期适配方法和非周期适配方法。当采用周期适配方法时,物理层的传输事件组周期是业务层的数据到达周期的倍数关系;当采用非周期适配方法时,物理层的传输事件组周期与业务层的数据到达周期不需要严格的倍数关系。</p>

:::

(gbt-46803-1-2025-clause-6-4-3-2)=
### 6.4.3.2 周期适配方法

(gbt-46803-1-2025-clause-6-4-3-2-1)=
#### 6.4.3.2.1 分段和级联流程

:::{div}
:class: standard-paragraph

<p>当采用周期适配方法时,每一个传输事件组中发送的物理层数据包个数为:向上取整运算(服务数据单元最大值/协议数据单元最大值$)\times ($事件组周期/服务数据单元周期)。每一个服务数据单元需产生向上取整运算(最大业务数据单元/最大协议数据单元)个分段,也即需要在物理层传输向上取整运算(最大业务数据单元/最大协议数据单元)个无线帧。如果一个服务数据单元的大小是0,传输该服务数据单元的无线帧指示的数据部分长度为0。</p>

:::

(gbt-46803-1-2025-clause-6-4-3-2-2)=
#### 6.4.3.2.2 时间同步流程

:::{div}
:class: standard-paragraph

<p>发送端的无线帧个数通过以下方式确定。</p>

:::

:::{div}
:class: standard-paragraph

<p>向上取整运算(服务数据单元最大值/协议数据单元最大值$)\times ($事件组周期/服务数据单元周期)。</p>

:::

:::{div}
:class: standard-paragraph

<p>其中,按照顺序每向上取整运算(服务数据单元最大值/协议数据单元最大值)个无线帧的数据包组合成一个服务数据单元,共可组合成(事件组周期/服务数据单元周期)。</p>

:::

:::{div}
:class: standard-paragraph

<p>发送端将(事件组周期/服务数据单元周期)个服务数据单元对应的向上取整运算(服务数据单元最大值/协议数据单元最大值$)\times ($事件组周期/服务数据单元周期)个无线帧在一个传输事件组中传输。</p>

:::

:::{div}
:class: standard-paragraph

<p>发送端从t0时刻开始接收从高层递交的(事件组周期/服务数据单元周期)个服务数据单元中的第一个服务数据单元,并按照顺序接收后续的服务数据单元。</p>

:::

:::{div}
:class: standard-paragraph

<p>发送端从t1时刻开始在一个传输事件组中传输包含(事件组周期/服务数据单元周期)个服务数据单元的向上取整运算(服务数据单元最大值/协议数据单元最大值$)\times ($事件组周期/服务数据单元周期)个无线帧。</p>

:::

:::{div}
:class: standard-paragraph

<p>t0时刻为:[t1-(事件组周期/服务数据单元周期$-1)\times$服务数据单元周期-事件组时间同步参考点时延]时刻之后接收的第一个服务数据单元的时刻。</p>

:::


:::{div}
:class: standard-paragraph

<p>接收端从r0时刻开始进行一个传输事件组的接收,该传输事件组对应该(事件组周期/服务数据单元周期)个服务数据单元的传输,包含向上取整运算(服务数据单元最大值/协议数据单元最大值$)\times ($事件组周期/服务数据单元周期)个无线帧,其中r0时刻是该传输事件组的起始时刻。</p>

:::

:::{div}
:class: standard-paragraph

<p>接收端从r1时刻开始向高层递交(事件组周期/服务数据单元周期)个服务数据单元中的第一个服务数据单元,并按照顺序以及业务到达周期的周期向高层递交后续的服务数据单元,其中r1时刻为:[r0+事件组时间同步锚点时延+(数据丢弃周期$-1)\times$事件组周期]。</p>

:::

:::{div}
:class: standard-paragraph

<p>周期适配方法的时间同步见图21,其中:①最大分组时延,②事件组集合时间同步参考点时延,③事件组集合时长,④事件组集合时间同步锚点时延,⑤最大空口重传时延。发送到接收的业务时延$=$①最大分组时延+②事件组集合时间同步参考点时延+③事件组集合时长+④事件组集合时间同步锚点时延+⑤最大空口重传时延。</p>

(gbt-46803-1-2025-clause-6-4-3-3-1)=
#### 6.4.3.3.1 分片和重组流程

:::{div}
:class: standard-paragraph

<p>采用非周期适配方法时,无线帧数据部分包括一个或者多个分片,每个分片都包括分片帧头和数据部分。如果分片的数据部分是一个服务数据单元的开头部分,分片帧头包括时间偏移量信息,该时间偏移量信息指示相关服务数据单元与时间参考点的相对时间。采用非周期适配方法时,无线帧数据部分可包括多个服务数据单元。</p>

:::

:::{div}
:class: standard-paragraph

<p>接收端接收一个或多个无线帧,根据无线帧的指示组合服务数据单元。</p>

:::

(gbt-46803-1-2025-clause-6-4-3-3-2)=
#### 6.4.3.3.2 时间同步流程

:::{div}
:class: standard-paragraph

<p>发送端接收从高层递交的一个服务数据单元,该服务数据单元对应一个参考时刻t0,该参考时间可为服务数据单元帧头里面的时间戳指示的时间信息或者其他通过实现方法获取的时间。</p>

:::

:::{div}
:class: standard-paragraph

<p>发送端从t1时刻开始在一个事件组中的一个传输事件中发送无线帧,该无线帧中包含该服务数据单元的第一个分片,该无线帧中包含该服务数据单元的时间偏移量信息,时间偏移量的值是服务数据单元的参考时间与该无线帧所在的事件组的事件同步参考点的差值。</p>

:::

:::{div}
:class: standard-paragraph

<p>接收端从r0时刻开始接收一个事件组中的各事件的无线帧,r0时刻是该事件组的起始时刻。</p>

:::

:::{div}
:class: standard-paragraph

<p>接收端从r1时刻开始向高层递交该服务数据单元,其中r1时刻为:(r0 +事件组时间同步锚点时延+数据丢弃周期$\times$事件组周期+服务数据单元周期-服务数据单元的时间偏移量信息)。</p>

:::

:class: standard-paragraph
