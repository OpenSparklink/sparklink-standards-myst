# 9 视频流媒体封装与传输协议

:::{div}
:class: standard-paragraph

<p>视频应用数据传输协议可参考 RTP（Real⁃time Transport Protocol）传输机制和消息格式。</p>

:::

:::{div}
:class: standard-paragraph

<p>视频应用实时流媒体数据格式可根据视频应用具体用例选择为一个或多个网络抽象层（Network Abstraction Layer，NAL）单元、基本码流（Elementary Stream，ES）、打包基本流（Packetized Elementary Stream，PES）或 MPEG⁃TS 其中一种格式，并封装成 RTP 报文通过轻量化传输协议或 TCP/IP 协议传输。</p>

:::

:::{div}
:class: standard-paragraph

<p>基础服务层数据传输通道上传输应基于 IP 封装的 RTP 协议报文。在视频应用设备间传输视频数据前提前建立 IP 媒体数据基础服务层传输通道，且该媒体数据传输通道应满足视频应用 IP 数据 QoS要求。</p>

:::

:::{div}
:class: standard-paragraph

<p>轻量化传输协议和网络协议应承载 RTP 协议报文传输。视频流打包发送过程为如下。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 应用层：将编解码器压缩后视频数据进行 RTP 封包，允许每个 RTP 报文的有效载荷中封装一个或多个网络抽象层（NAL）单元，且允许有效载荷中封装 PES audio/video 或 MPEG2⁃TS 编码数据。本文件支持的音频编解码方式以及对应的参数配置应符合附录 F 的要求。</p>
</li>
<li><p>—— 网络与传输功能：轻量化传输协议按基础服务层最大传输单元（Maximum Transmission Unit，MTU）拆包和封包；然后可通过网络协议进行转发传输。</p>
</li>
<li><p>—— 基础服务层：TCID 帧头封包（可选分片或聚合），按照基础服务层传输模式（Transparent Mode，TM）进行传输。</p>
</li></ul>

:::
