# 8.3 组播视频配置与传输管理流程

(gbt-48336-405-2026-clause-8-3-1)=
## 8.3.1 通则

:::{div}
:class: standard-paragraph

<p>组播视频组播源将相同的视频流数据通过组播视频数据通道发送给多个属于该组播组中的视频宿，并保证数据传输的可靠性。组播视频数据通道可为组播传输通道，也可为接入层的逻辑信道或组播链路。</p>

:::

:::{div}
:class: standard-paragraph

<p>组播组内的视频宿称为该组播组的组成员。组播组的形成和组播组成员加入、离开和组成员查询需通过设备集合管理和同步管理原子能力以及组播组成员管理服务实现。</p>

:::

:::{div}
:class: standard-paragraph

<p>针对任意组播视频应用，可通过设备集合管理和同步管理原子能力以及组播组成员管理服务形成一个或多个组播组。每个组播组包括一个组播视频源和一个或多个组播视频宿。组播视频源与相同组播组内一个或多个组播视频宿应逐一建立用于传输控制面信令的连接（默认承载）。组播视频源还应与组内一个或多个组播视频宿建立视频组播传输通道。</p>

:::

:::{div}
:class: standard-paragraph

<p>如图 17 所示，组播视频配置与传输管理同样基于服务管理 SSAP 流程。流程由四个阶段组成，分别为：</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a） 组播视频组成员加入与视频应用参数配置阶段；</p>
</li>
<li><p>b） 视频流组播传输开始与组播传输性能查询与管理阶段；</p>
</li>
<li><p>c） 视频流组播传输暂停与重配置阶段；</p>
</li>
<li><p>d） 组播视频组成员查询或离开以及组播视频应用终止阶段。</p>
</li></ol>

:::

## 8.3.3 组播视频组成员加入

:::{div}
:class: standard-paragraph

<p>组播视频组成员加入过程是组播视频宿向特定组播视频源申请加入特定组播视频应用所关联的组播组的过程。通过该过程，组播源（即组播组管理者）生成并维护“组播组成员管理表项”，用于指导组播视频流发送。</p>

:::

:::{div}
:class: standard-paragraph

<p>组成员加入过程是后续组播视频配置与传输管理操作的前提。基于组播视频组成员加入过程生成“组播组成员管理表项”，组播视频管理服务客户端可向组播视频管理服务服务端进行后续的组播视频应用参数配置、组播视频数据通道开启与传输等其他组播视频配置与传输管理流程操作。</p>

:::

:::{div}
:class: standard-paragraph

<p>如图 18 所示，该示例中组成员管理服务服务端承载组播成员管理服务，并定义组播视频源作为该服务服务端，组播视频宿作为该服务的客户端。流程应按以下步骤进行设置。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a） 一个或多个组成员管理服务客户端（组播视频宿）向组成员管理服务服务端发送组成员加入请求信令，该信令携带该服务客户端设备层二标识（L2ID）、希望加入的特定组播应用标识以及组成员差异特性信息。</p>
</li>
<li><p>b） 组成员管理服务服务端（组播视频源、组播组管理者）收到组成员加入请求信令后，根据组成员加入请求信令中携带的信息，将组成员管理服务客户端（组播视频宿）纳入当前已建立的组播组中或新建立组播组中，并本地生成维护“组播组成员管理表项”，该表项作为组播数据的转发依据。</p>
</li>
<li><p>c） 组成员管理服务服务端（组播视频源、组播组管理者）根据生成的“组播组成员管理表项”，向组成员管理服务客户端（组播视频宿）回复组成员加入响应信令，信令中携带成功加入的组播组标识和加入响应结果。</p>
</li></ol>

:::

<p>如图 19 所示，该示例中组播视频管理服务端承载视频配置管理服务和视频属性公开服务。针对组播视频管理服务端/客户端对应组播视频源/宿关系的不同，分别定义组播视频应用参数配置流程如下。</p>

:::{div}

<ol class="alpha-list" start="1">
<li><p>a） 组播视频管理服务端为组播视频宿，组播视频管理客户端为组播视频源。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>组播视频应用参数配置流程应按以下步骤进行设置。</p>

:::

:::{div}
:class: standard-list-block

<ol class="decimal-list" start="1">
<li><p>1） 当组播视频管理客户端（组播视频源）收到 1 个或多个组播视频管理服务端（组播视频宿）回复的能力信息查询响应信令后，组播视频管理客户端决策并向 1 个或多个组播视频管理服务端发送视频应用参数配置请求信令，并携带针对具体视频应用用例相同的优选视频应用参数集，例如音视频编解码类型、媒体数据封装格式、流媒体传输协议等。</p>
<ol class="decimal-list" start="2">
<li><p>2） 当组播视频管理服务端接收到视频应用参数配置请求信令中指定的配置参数后，若接受该配置参数，则应向组播视频管理客户端回复视频应用参数配置响应信令，并携带配置成功响应结果；反之，若拒绝该配置参数，则应在视频应用参数配置响应信令中携带配置失败结果及其失败原因，并终止配置流程。</p>
</li></ol>
</li>
<li><p>b） 组播视频管理服务端为组播视频源，组播视频管理客户端为组播视频宿。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>组播视频应用参数配置流程如下所述。</p>

:::

:::{div}
:class: standard-list-block

<ol class="decimal-list" start="1">
<li><p>1） 当组播视频管理客户端（组播视频宿）收到组播视频管理服务端（组播视频源）回复的能力信息查询响应信令后，组播视频管理客户端决策并向组播视频管理服务端发送视频应用参数配置请求信令，并携带针对具体视频应用用例该组播视频管理客户端本地优选的视频应用参数集，例如音视频编解码类型、媒体数据封装格式、流媒体传输协议等。</p>
</li>
<li><p>2） 当组播视频管理服务端（组播视频源）接收到组播视频管理客户端（组播视频宿）发送的视频应用参数配置请求信令后，立即分别向组播视频管理客户端（组播视频宿）发送视频应用参数配置等待通知信令，以告知组播视频管理客户端（组播视频宿）等待接收应用参数配置响应信令。</p>
</li>
<li><p>3） 当组播视频管理服务端（组播视频源）接收到全部组播组中组播视频管理客户端（组播视频宿）发送的视频应用参数配置请求信令后，综合 1 个或多个组播视频管理客户端请求的配置参数决策最优配置参数集。若接受该配置参数，则应向组播视频管理客户端回复视频应用参数配置响应信令，并携带配置成功响应结果；反之，若拒绝该配置参数，则应在视频应用参数配置响应信令中携带配置失败结果及其失败原因，并终止配置流程。</p>
</li></ol>

(gbt-48336-405-2026-clause-8-3-5)=
## 8.3.5 组播视频数据通道开启与视频流组播传输开始

:::{div}
:class: standard-paragraph

<p>如图 20 所示，组播视频数据通道开启与组播视频流传输开始流程应按以下步骤进行设置。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a） 当视频应用参数配置完成后，组播视频管理服务客户端发送视频流传输通道开启请求信令向组</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

</li>
<li><p>—— 此外，可选的由组播视频管理服务服务端向组播视频管理服务客户端发送视频传输暂停通知信</p>
</li></ul>

:::

</li>
<li><p>b） 当组播视频管理服务服务端根据接收到的视频应用参数重配置请求信令后，若接受重配置参数，则应向组播视频管理服务客户端回复视频应用参数重配置响应信令，并携带重配置成功响应结果；反之，若重配置失败，则应携带重配置失败响应结果及其失败原因，并终止重配置流程。</p>
</li></ol>

:::

## 8.3.10 组播视频流传输停止与应用释放

:::{div}
:class: standard-paragraph

<p>如图 26 所示，组播视频流传输停止可有两种方式。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 在组播视频流传输过程中，组播视频管理服务客户端可发送视频应用终止请求信令。组播视频管理服务服务端收到该信令后，立即回复视频应用终止响应信令。若接受终止操作，则回复应用终止成功响应；反之，回复应用终止失败响应，并指示失败原因。</p>
</li>
<li><p>—— 或者，可选的由组播视频管理服务服务端向组播视频管理服务客户端发送视频应用终止通知信令，组播视频管理服务客户端收到该通知信令后，即可终止组播视频传输。</p>
</li></ul>

:::

:::{div}
:class: standard-diagram

```{mermaid}
sequenceDiagram
  participant A as 组播视频管理服务客户端
  participant B as 组播视频管理服务服务端
  alt 视频流传输停止请求-响应信令
  A->>B: SSAP_CALL_METHOD_REQ (<br/>操作码：0x05（视频传输停止）；<br/>视频源/宿数量：1；<br/>视频源/宿标识：ID-x<br/>)
  B->>A: SSAP_CALL_METHOD_RSP (<br/>操作码：0x05（视频传输停止）；<br/>视频源/宿数量：1；<br/>视频源/宿标识：ID-x；<br/>参数 {视频流传输终止响应结果}<br/>)
  else 视频流传输停止通知
  B->>A: SSAP_VALUE_NTF (<br/>操作码：0x02（视频传输停止通知）；<br/>视频源数量：1；<br/>视频源标识：ID-s<br/>)
```

<p>当视频应用终止响应成功后，组播视频管理服务客户端可向组播视频管理服务服务端请求释放该视频应用占用的资源，如配置信息、链路资源等。如图 27 所示，组播视频应用释放流程应按以下步骤进行设置。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a） 组播视频管理服务客户端向组播视频管理服务服务端发送视频应用释放请求信令，若组播视频</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>管理服务服务端接受释放请求操作，则向基础服务层连接管理功能单元触发进行指定视频组播传输通道释放。若视频组播传输通道释放成功，则组播视频管理服务服务端回复应用释放成功响应，并在本地删除对应的视频配置信息。若组播视频管理服务服务端向视频客户端回复应用释放失败响应，则需携带失败原因指示。此时，视频应用释放流程停止。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="2">
<li><p>b） 当组播视频管理服务客户端收到资源释放成功响应后，组播视频管理服务客户端向基础服务层连接管理功能单元触发进行指定视频组播传输通道释放。并在本地删除对应的视频配置信息。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>此外，除了客户端与服务端间通过请求⁃响应方式进行视频应用释放以外，可选的视频应用释放操作方式为组播视频管理服务服务端向组播视频管理服务客户端发送视频应用释放通知信令。组播视频管理服务客户端收到该通知信令后，即可向基础服务层连接管理功能单元触发进行指定视频组播传输通道释放，并本地删除相应的视频配置信息。</p>
