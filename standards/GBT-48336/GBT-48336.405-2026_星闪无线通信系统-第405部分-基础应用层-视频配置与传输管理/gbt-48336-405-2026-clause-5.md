(gbt-48336-405-2026-clause-5-1)=
## 5.1 视频应用协议体系架构

:::{div}
:class: standard-paragraph

<p>视频应用协议体系架构如图 1 所示。视频应用协议包括全景环视、无线投屏、无线摄像头监控、扩展桌面、桌面协同、VR 游戏/影院/展馆等场景。视频应用相关的应用层原子能力协议包括视频配置与传输管理原子能力协议、合作设备集合管理原子能力协议以及媒体播放控制原子能力协议。</p>

:::

:::{div}
:class: standard-paragraph

<p>网络和传输功能分为 TCP/IP 协议体系和非 IP 协议体系，因此视频应用可分为通过 TCP/IP 协议传输的 IP 视频应用数据和通过传输功能单元和网络功能单元传输的非 IP 视频应用数据。其中，后者具有传输协议报文头精简、无需等待建连和接收确认机制等特点，相比 TCP/IP 协议传输可提高有效载荷比且降低首包延迟，相比 UDP/IP 协议传输可提高传输的可靠性。轻量化网络功能单元支持基础转发和满足 QoS 要求的高级转发。</p>

:::

```{image} ../../../assets/structured/GBT-48336.405-2026/regions/p0012-figure-01-203.png
:alt: 图 1　视频应用协议体系架构
:class: source-figure
:width: 533px
```

(gbt-48336-405-2026-figure-1)=
:::{div}
:class: standard-caption

<p>图 1　视频应用协议体系架构</p>

:::

:::{div}
:class: standard-paragraph

<p>基础服务层控制面通过 SLB/SLE 通用管理传输通道（CMTC）和服务管理传输通道（SMTC）实现设备间控制面信令交互，提供设备发现、服务管理、QoS 管理、连接管理和测量管理功能，包括但不限于：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 根据设备能力灵活配置 SLB 设备发现或 SLE 辅助设备发现；</p>
</li>
<li><p>—— 通过基础服务层 QoS 管理单元和连接管理单元建立、重置或释放满足视频应用 QoS 要求的数据传输通道（含单播、组播、广播）；</p>
</li>
<li><p>—— 通过测量管理单元获知特定视频流粒度的传输性能、视频流传输经过的传输通道性能或视频设备空口传输性能。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>基础服务层数据面可分别为其上层非 IP 和 IP 两类视频服务数据单元（SDU）提供包括基础传输、流传输或可靠传输等多种传输模式，以满足不同视频服务数据单元的要求，如实时性、可靠性等。</p>

:::

:::{div}
:class: standard-paragraph

<p>本文件定义了基础应用层视频配置与传输管理原子能力协议，包括如下内容。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a） 视频配置与传输管理相关服务应支持：</p>
<ul class="standard-list">
<li><p>• 单播、组播、广播视频应用设备间能力信息查询；</p>
</li>
<li><p>• 视频应用参数配置与重配置；</p>
</li>
<li><p>• 视频数据通道开启；</p>
</li>
<li><p>• 视频流传输开始、暂停；</p>
</li></ul>
</li></ol>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>• 视频传输性能反馈；</p>
<ul class="standard-list">
<li><p>• 组播视频组成员加入和离开；</p>
</li>
<li><p>• 视频流传输停止与应用释放。</p>
</li></ul>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="2">
<li><p>b） 针对单播传输、组播传输和广播传输的不同通信方式，应通过使用星闪服务交互协议（SSAP）</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>实现单播视频应用、组播视频应用以及广播视频应用的视频配置与传输管理流程。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="3">
<li><p>c） 视频应用的媒体编解码类型、媒体流封装与传输协议应分别支持音视频编解码类型（包括</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>H.264，H.265 等）、实时传输协议（Real⁃time Transport Protocol，RTP）。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="4">
<li><p>d） 音画分离设备同步播放管理应支持音频、视频分离接收设备间的播放同步，满足视频应用音画</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>同步要求。</p>

</li></ol>

:::

:::{div}
:class: standard-paragraph

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>• 对于 IP 音视频应用，基于不同的应用类型，基础服务层 QoS 管理单元根据 IP QoS 指示信息（如 DSCP）确定星闪 QoS 参数。连接管理单元根据星闪 QoS 参数建立特定 IP 视频应用数据传输通道。</p>
</li></ul>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="4">
<li><p>d） 视频应用配置与传输管理（包括视频流传输开始、暂停，应用参数重配置，视频流传输终止与应</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>用释放）：当视频应用数据传输通道建立成功后，视频源或视频宿可通过视频配置与传输管理相关服务的服务管理流程进行视频流传输开始与暂停、传输性能反馈、应用参数重配置、视频流传输终止与应用释放的控制。</p>

(gbt-48336-405-2026-clause-5-3)=
## 5.3 视频应用角色及其功能定义

(gbt-48336-405-2026-clause-5-3-1)=
### 5.3.1 视频发送端

:::{div}
:class: standard-paragraph

<p>视频发送端功能包括：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 支持单个视频源；</p>
</li>
<li><p>—— 支持多个视频源；</p>
</li>
<li><p>—— 支持单播、组播或广播通信方式；</p>
</li>
<li><p>—— 当包括单个视频源时，支持与单个视频宿或多个视频宿同时建立连接；</p>
</li>
<li><p>—— 当包括多个视频源时，支持与单个视频宿或多个视频宿同时建立连接；</p>
</li>
<li><p>—— 当同时包括视频源和音频源，支持将音频流和视频流分别向至少两个或多个视频接收端传输。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>其中多个视频接收端包括仅支持解码视频数据的视频接收端和仅支持解码音频数据的音频接收端。</p>

:::

(gbt-48336-405-2026-clause-5-3-2)=
### 5.3.2 视频接收端

:::{div}
:class: standard-paragraph

<p>视频接收端功能包括：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 支持单个视频宿；</p>
</li>
<li><p>—— 支持多个视频宿；</p>
</li>
<li><p>—— 支持单播、组播或广播通信方式；</p>
</li>
<li><p>—— 当包括单个视频宿时，支持与单个视频源建立连接；</p>
</li>
<li><p>—— 当包括多个视频宿时，支持与多个视频源建立连接。</p>
</li></ul>

:::

(gbt-48336-405-2026-clause-5-3-3)=
### 5.3.3 视频源

:::{div}
:class: standard-paragraph

<p>视频源功能包括：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 支持发送仅视频流，或音频数据和视频数据的混合媒体流数据；</p>
</li>
<li><p>—— 支持选择和更改视频编解码类型和编解码器参数；</p>
</li>
<li><p>—— 支持选择和更改媒体流封装格式类型；</p>
</li>
<li><p>—— 支持选择和更改媒体流传输协议类型。</p>
</li></ul>

:::

(gbt-48336-405-2026-clause-5-3-4)=
### 5.3.4 视频宿

:::{div}
:class: standard-paragraph

<p>视频宿功能包括：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 支持接收仅视频流，或音频数据和视频数据的混合媒体流数据；</p>
</li>
<li><p>—— 支持视频源选择或更改的视频编解码类型和编解码器参数；</p>
</li>
<li><p>—— 支持接收和解析视频源发送的使用特定编码封装格式封装的视频流或混合媒体流数据；</p>
</li>
<li><p>—— 支持接收和解析视频源发送的使用特定媒体流传输协议类型的视频流或混合媒体流数据。</p>
</li></ul>

:::

(gbt-48336-405-2026-clause-5-3-5)=
### 5.3.5 源宿共身份

:::{div}
:class: standard-paragraph

<p>源宿共身份设备功能包括支持同时作为视频接收端和视频发送端。其中，视频发送端的功能和视频接收端的功能分别见 5.3.1 和 5.3.2。</p>

:::

(gbt-48336-405-2026-clause-5-3-6)=
### 5.3.6 组播源

:::{div}
:class: standard-paragraph

<p>组播源功能包括：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 支持采用一种类型编码器处理由视频源产生的视频数据，并应以组播通信方式向一个或多个视</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>频宿发送；</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 支持组播组管理者逻辑功能，负责对其所在的组播组成员进行管理。组成员管理应包括组成员加入、组成员离开和组播组变更通知。</p>
</li></ul>

:::

(gbt-48336-405-2026-clause-5-3-7)=
### 5.3.7 组播组管理者

:::{div}
:class: standard-paragraph

<p>组播组管理者功能包括：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 支持作为组播组管理者角色；</p>
</li>
<li><p>—— 支持生成和维护“组播组成员管理表项”。</p>
</li></ul>

:::

(gbt-48336-405-2026-clause-5-3-8)=
### 5.3.8 组播宿

:::{div}
:class: standard-paragraph

<p>组播宿功能包括：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 支持作为组播组成员角色；</p>
</li>
<li><p>—— 支持通过组成员加入方法信令和流程主动向组播源申请加入特定视频应用组播组，成为特定视频应用组播组成员；</p>
</li>
<li><p>—— 支持通过组成员离开方法信令和流程主动向组播源申请离开特定视频应用特定组播组；</p>
</li>
<li><p>—— 支持接收组播源发送的组播组变更通知，可通过组成员加入方法或组成员离开信令进行特定视频应用组播组加入或离开的变更。</p>
</li></ul>

:::
