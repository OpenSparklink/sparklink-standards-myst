# 8.2 单播视频配置与传输管理流程

(gbt-48336-405-2026-clause-8-2-1)=
## 8.2.1 概述

:::{div}
:class: standard-paragraph

<p>如图 9 所示，单播视频配置与传输管理流程主要分为四个阶段：</p>

:::

:::{div}
:class: standard-list-block

<ol class="decimal-list" start="1">
<li><p>1） 视频设备能力信息查询与视频应用参数配置阶段；</p>
</li>
<li><p>2） 视频流传输开始与传输性能查询与管理阶段；</p>
</li>
<li><p>3） 视频流传输暂停与重配置阶段；</p>
</li>
<li><p>4） 视频流传输停止与应用释放阶段。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>图中服务端定义为承载单播视频配置与传输管理相关服务（包括视频配置管理服务和视频属性公开服务）的承载方，用于接收和响应客户端的请求，简称“单播视频管理服务服务端”；客户端定义为单播视频配置与传输管理相关服务（即配置与管理服务）的使用方，用于向服务端提交访问请求，获取并接收服务端返回的响应，简称“单播视频管理服务客户端”。</p>

:::

(gbt-48336-405-2026-clause-8-2-4)=
## 8.2.4 单播视频应用参数配置

:::{div}
:class: standard-paragraph

<p>如图 10 所示，该示例中单播视频管理服务端承载视频配置管理服务和视频属性公开服务。视频设备能力与视频应用参数配置流程如下所述。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a） 若单播视频管理服务客户端收到单播视频管理服务服务端回复的能力查询响应信令后，单播视频管理服务客户端决策并向单播视频管理服务服务端发送视频应用参数配置请求信令，并携带针对具体视频应用用例的优选视频应用参数集，例如音视频编解码类型、媒体数据封装格式、流媒体传输协议等。</p>
</li>
<li><p>b） 当单播视频管理服务服务端接收到视频应用参数配置请求信令中指定的配置参数后，若接受该配置参数，则应向单播视频管理服务客户端回复视频应用参数配置响应信令，并携带配置成功响应结果；反之，若拒绝该配置参数，则应在视频应用参数配置响应信令中携带配置失败结果及其失败原因，并终止配置流程。</p>
</li></ol>

:::

(gbt-48336-405-2026-clause-8-2-5)=
## 8.2.5 单播视频数据通道开启与单播视频流传输开始

:::{div}
:class: standard-paragraph

<p>如图 11 所示，单播视频数据通道开启与单播视频流传输开始应按以下流程进行设置。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a） 当视频应用参数配置完成后，单播视频管理服务客户端发送视频数据通道开启请求信令向单播</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>视频管理服务服务端发起目标视频应用单播传输通道建立。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="2">
<li><p>b） 当单播视频管理服务服务端收到该信令后，应向单播视频管理服务客户端回复视频数据通道开</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>启响应信令，携带传输通道开启响应结果。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 若接收到传输通道开启成功响应，则单播视频管理服务客户端的视频应用配置与传输管理功能单元应根据视频应用相关的 QoS 参数，向基础服务层 QoS 管理功能单元提交服务传输请求。QoS 管理功能单元指示连接管理功能单元建立满足单播视频应用 QoS 要求的单播传输通道，并向视频应用配置与传输管理功能单元反馈传输通道创建结果 srcTCID（源端传输通道标识）和 dstTCID（目的端传输通道标识）信息。</p>
<ul class="standard-list">
<li><p>—— 若接收到传输通道开启失败响应，则视频单播传输通道开启流程立即终止。单播视频管理服务客户端可以根据返回的失败原因，进行信令参数修正等操作。随后可再次发送视频数据通道开启请求信令。</p>
</li></ul>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="3">
<li><p>c） 在单播视频数据通道开启成功之后，则可通过视频流传输开始信令交互指示开始视频流单播传</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>输。如图 11 所示，视频流传输开始信令交互可有两种方式。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 单播视频管理服务客户端向单播视频管理服务服务端发送视频流传输开始请求信令。那么，当单播视频管理服务服务端收到该信令后，回复视频流传输开始响应信令，携带视频流传输开始响应结果。</p>
<ul class="standard-list">
<li><p>• 若回复视频流传输开始成功响应，则可开始视频流单播传输。</p>
</li>
<li><p>• 若回复视频流传输开始失败响应，则携带响应结果及其失败原因。</p>
</li></ul>
</li>
<li><p>—— 或者，可选由单播视频管理服务服务端向单播视频管理服务客户端发送视频流传输开始通知信令，即可开始视频流单播传输。</p>
</li></ul>

:::

:::{div}
:class: standard-diagram

## 8.2.6 视频流单播传输性能查询与管理

:::{div}
:class: standard-paragraph

<p>视频流单播传输性能查询与管理过程是单播视频传输性能反馈服务客户端与单播视频传输性能反馈服务端相互交换视频发送端或视频接收端的传输性能属性的过程。</p>

:::

:::{div}
:class: standard-paragraph

<p>该过程是视频传输性能管理的前提，也可作为视频应用参数配置的前提。当单播视频传输性能反馈服务客户端获取到单播视频传输性能反馈服务服务端视频属性信息后，可结合自身的能力和应用的要求选择合适的参数通过调用传输性能管理方法定义的信令对单播视频传输性能反馈服务服务端进行缓冲区大小配置和/或重要数据丢弃优先级配置。视频应用参数重配置流程见 8.2.7。</p>

:::

:::{div}
:class: standard-paragraph

<p>如图 12 所示，该示例中单播视频管理服务端承载视频传输性能反馈服务，则单播视频管理客户端可通过调用传输性能反馈信令与单播视频管理服务端间交互单播视频发送端和单播视频接收端的传输性能信息。</p>

## 8.2.7 视频流单播传输暂停与重配置

:::{div}
:class: standard-paragraph

<p>如图 14 所示，视频流传输暂停可有两种方式。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 在视频流数据在进行传输过程中，单播视频管理服务客户端可发送视频流传输暂停请求信令。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>单播视频管理服务服务端收到该信令后，立即回复视频传输暂停响应信令。若接受暂停操作，则回复传输暂停成功响应；反之，回复传输暂停失败响应，并指示失败原因。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 或者，可选由单播视频管理服务服务端向单播视频管理服务客户端发送视频传输暂停通知信</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>令，单播视频管理服务客户端收到该通知信令后，即可暂停单播视频流数据传输。</p>

:::

:::{div}
:class: standard-diagram

```{mermaid}

  B->>A: SSAP_CALL_METHOD_RSP (<br/>操作码：0x03（视频流传输开始）；<br/>视频源数量：1；<br/>视频源标识：ID-s；<br/>参数 {视频流传输开始响应结果}<br/>)
  else 视频流传输继续通知
  B->>A: SSAP_VALUE_NTF (<br/>操作码：0x01（视频流传输开始通知）；<br/>视频源数量：1；<br/>视频源标识：ID-s<br/>)
```

</li></ol>

</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>频管理服务服务端收到该信令后，立即回复视频流传输停止响应信令。若接受停止操作，则回复传输停止成功响应；反之，回复传输停止失败响应，并指示失败原因。</p>

:::{div}

<p>如图 16 所示，单播视频应用释放流程应按以下步骤进行设置。</p>

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a） 单播视频管理服务客户端向单播视频管理服务服务端发送视频应用释放请求信令，若单播视频管理服务服务端接受释放请求操作，则向其本地基础服务层连接管理功能单元触发进行指定视频单播传输通道释放。若视频单播传输通道释放成功，则单播视频管理服务服务端回复单播视频应用释放成功响应，并在本地删除相应的视频配置信息。若单播视频管理服务服务端向视频客户端回复应用释放失败响应，则需携带失败原因指示。此时，视频应用释放流程停止。</p>
</li>
<li><p>b） 若单播视频管理服务客户端收到视频应用释放成功响应后，单播视频管理服务客户端则向其基础服务层连接管理功能单元触发进行指定视频单播传输通道释放，并在本地删除对应的视频配置信息。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>此外，除了客户端与服务端间通过请求-响应方式进行视频应用释放以外，可选的视频应用释放操作方式为单播视频管理服务服务端向单播视频管理服务客户端发送视频应用释放通知信令。单播视频管理服务客户端收到该通知信令后，即可向基础服务层连接管理功能单元触发进行指定视频单播传输通道释放，并本地删除相应的视频配置信息。</p>
