# 10 音画分离设备同步播放

:::{div}
:class: standard-paragraph

<p>如表 50 所示，根据 ITU⁃R BT.1359⁃1 中定义，音画时延分为超前与滞后两种，超前指音频先于视频出现，采用正数表示；滞后指音频慢于视频出现，采用负数表示。根据时延差值划分为四个用户体验等级，即 A：极致（无感知）、B：优秀（轻微感知）、C：良好：可接受、D：不可接受。</p>

:::

:::{div}
:class: standard-paragraph

<p>本文件参考 RFC 3550 规定发送端在 RTP header 中携带 1 个 32 bits 的 RTP timestamp 字段，该时戳记录了 RTP 报文 payload 中第一个字节对应的数据采样时刻，时间单位基于时钟参考（Program Clock Reference，PCR clock）。接收端接收 RTP 报文并解析 RTP 报文 header 中的 RTP timestamp 判断音频数据和视频数据的相对时间关系；并分别解析音频数据 PES 报文、视频数据 PES 报文中的播放时间标记（Presentation Time Stamp，PTS）/解码时间标记（Decoding Time Stamp，DTS）时戳后，按序解码音频和视频的压缩数据，进而播放。</p>

:::

:::{div}
:class: standard-paragraph

<p>音画分离设备同步播放管理的流程如下。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a） 视频源端设备通过接入层空口向多个视频宿端设备分别独立发送音频数据 RTP 报文和视频RTP 报文，并分别相应发送 RTCP 报文。在 RTCP SR 报文中携带一组“时间对”，即〈设备时间信息，RTP timestamp〉，其中“设备时间信息”字段为多设备时间同步管理维护的时间信息，RTP timestamp 为对应该设备时间信息的编解码器系统时钟（PCR clock）的当前时序值 S_TS⁃FN。</p>
</li>
<li><p>b） 视频宿端根据 RTCP SR 报文中携带这一组“时间对”，可得到〈设备时间信息，RTP timestamp〉</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>间的线性关系，即“设备时间信息”$=f(S\_\mathrm{TSFN})=k*S\_\mathrm{TSFN}+b$。目的是将音频帧和视频帧的相对时间关系统一对齐在相同的设备时间信息时间轴上，以达到音画同步目的。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="3">
<li><p>c） 在视频源发送携带音视频数据的 RTP 报文时，分别在音频 RTP 报文和视频 RTP 报文中的</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>RTP timestamp 字段携带基于 PCR 时钟的时序号 S_TSFN_video 和 S_TSFN_audio。则可分别按照上述线性关系转化并与已经获取同步的设备时间信息对齐。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="4">
<li><p>d） 解码器接收到 RTP 报文后，根据第三步获取“设备时间信息”和 RTP timestamp，恢复并维持</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>PCR 时钟定时，并根据 PES 报文中携带的 PTS 时序分别对视频压缩数据和音频压缩数据进行解码和播放。</p>

:::
