# 9 广播音频流配置与管理

(gbt-48336-401-2026-clause-9-1)=
## 9.1 角色定义

:::{div}
:class: standard-paragraph

<p>广播音频流的配置与管理中分为音源、音宿、配置代理、管理代理四个角色。</p>

:::

:::{div}
:class: standard-paragraph

<p>在广播音频流的配置与管理中，音源通过广播直接对音宿进行配置，音宿上可承载音频属性公开服务，配置代理可通过访问该服务为音宿匹配音源。</p>

:::

:::{div}
:class: standard-paragraph

<p>为减小音宿长期扫描音源配置广播带来的功耗上升，设置配置代理和管理代理角色。管理代理角色应承载广播音频流管理服务，配置代理负责对音源进行扫描发现，获取音频流的配置信息，作为客户端对广播音频流管理服务进行访问，对管理代理进行配置。广播音频流配置、管理角色与客户端/服务端关系见表 59。</p>

:::

## 9.3 广播音频流配置信息

:::{div}
:class: standard-paragraph

<p>广播音频流配置信息主要承载广播音频流集合的编解码器类型和参数、子集合构成信息、音频流业务信息、音频通道和端口号信息。若设备能力允许，音源可同时发送多个广播音频流集合实例的音频数据，此时，音源也应发送多个广播音频流配置信息，广播音频流配置信息应与广播音频流集合一一对应。</p>

:::{div}
:class: standard-paragraph

<p>广播音频流配置信息承载在广播业务传输通道控制信息中，通过通用控制广播传输通道发送。广播音频流配置信息见表 60。</p>

:::

:::{div}
:class: standard-paragraph

<p>一种示例型的配置方法是，一个广播音频流集合为一个内容源，如一部电影的音频。子集合为多种语言的音轨，语言信息通过子集合的音频流语言字段指示。子集合内的音频流为多个声道的音频数据，声道信息通过音频通道字段指示。通过广播音频流的配置信息，音源能够清晰表达广播音频流集合的结构和内容。音宿能够根据该信息接收需要的音源流。</p>

(gbt-48336-401-2026-clause-9-5)=
## 9.5 音频流配置与管理流程

(gbt-48336-401-2026-clause-9-5-1)=
### 9.5.1 概述

:::{div}
:class: standard-paragraph

<p>广播是指通过使用接入层的广播传输能力，音源将一个或多个广播音频流集合以广播方式发送，在该音源无线信号覆盖范围内的设备均可进行接收。</p>

:::

:::{div}
:class: standard-paragraph

<p>广播音频流的配置与管理流程分为两种方式，即：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 音源直接对音宿进行配置的方式，音源和音宿不必建立连接，配置信息通过广播传输；</p>
</li>
<li><p>—— 音源借助配置代理和管理代理对音宿进行配置的方式，配置信息需通过面向连接的数据通道传输。</p>
</li></ul>

:::

(gbt-48336-401-2026-clause-9-5-2)=
### 9.5.2 音源⁃音宿拓扑的配置与管理流程

(gbt-48336-401-2026-clause-9-5-2-1)=
#### 9.5.2.1 广播音频流配置与重配置

:::{div}
:class: standard-paragraph

<p>广播音频流配置是指音源发送广播音频流配置信息，音宿接收和解析广播音频流配置信息的过程。</p>

:::

:::{div}
:class: standard-paragraph

<p>解析配置信息后，音宿应检查是否能够接受音频流的编解码器类型和参数，决定需要接收的广播音频流，并进行必要的配置。</p>

:::

:::{div}
:class: standard-paragraph

<p>广播音频流重配置是指音源更新了广播音频流的配置信息，音频流音宿接收该信息后，可按照需要重新对编解码器进行配置或重新选择需要接收的音频流。</p>

:::

:::{div}
:class: standard-paragraph

<p>音源应发送通用控制广播传输通道发送请求给连接管理功能单元，携带广播音频流配置信息，连接管理功能单元应将广播音频流配置信息由通用控制广播传输通道发送。</p>

:::

:::{div}
:class: standard-paragraph

<p>音宿应向连接管理功能单元发送通用控制广播传输通道接收查询，该信令会指示接入层进行扫描和发现，接收音源发送的广播音频流配置信息。</p>

:::

(gbt-48336-401-2026-clause-9-5-2-2)=
#### 9.5.2.2 广播音频流传输

:::{div}
:class: standard-paragraph

<p>音源应指示 QoS 管理功能单元执行广播业务传输，携带广播音频流集合的业务 QoS 参数。QoS 管理功能单元应将业务 QoS 参数转换为传输 QoS 参数，指示连接管理功能单元建立广播业务传输通道。</p>

:::

:::{div}
:class: standard-paragraph

<p>当音源在本端建立广播业务传输通道完成后，音源发送通用控制广播传输通道发送请求，携带广播音频流配置信息时，连接管理功能单元应将非链接态广播链路配置信息和广播音频流配置信息同时发送。当音源收到连接管理功能单元的通用控制广播传输通道发送确认后，音源开始通过广播业务传输通道发送音频数据。</p>

:::

:::{div}
:class: standard-paragraph

<p>音宿应向连接管理功能单元发送通用控制广播传输通道接收查询，该信令会指示接入层进行扫描和发现，接收音源发送的广播音频流配置信息和非链接态广播链路配置信息。音宿指示 QoS 管理功能单元建立广播业务传输通道并接收需要的音频流。当广播业务传输通道建立完成后，QoS 管理功能单元应返回反馈广播通道结果，音宿从广播业务传输通道上接收数据。</p>

:::

:::{div}
:class: standard-paragraph

<p>音源⁃音宿的建立广播业务通道的流程应符合 GB/T 48336.301。其中，音源作为广播传输通道的发送方的基础应用层，音宿作为广播传输通道的接收方的基础应用层。</p>

:::

(gbt-48336-401-2026-clause-9-5-2-3)=
#### 9.5.2.3 广播音频流释放

:::{div}
:class: standard-paragraph

<p>当音源不再发送音频数据时，应发送通用控制广播传输通道停止发送请求，停止发送广播音频流配置信息。当音源收到通用控制广播传输通道停止发送响应后，应向 QoS 管理功能单元指示停止广播业务，释放广播业务传输通道。</p>

:::

:::{div}
:class: standard-paragraph

<p>当音宿不再接收广播数据时，应向 QoS 管理功能单元发送停止广播业务的指示，释放广播业务传输通道。</p>

:::

:::{div}
:class: standard-paragraph

<p>广播业务传输通道的释放流程应符合 GB/T 48336.301。其中，音源作为广播传输通道的发送方的基础应用层，音宿作为广播传输通道的接收方的基础应用层。</p>

:::

(gbt-48336-401-2026-clause-9-5-2-4)=
#### 9.5.2.4 广播音频流异常断开

:::{div}
:class: standard-paragraph

<p>当音宿的广播业务传输通道异常断开时，音宿可执行音源的配置，重新建立广播业务传输通道。</p>

:::

(gbt-48336-401-2026-clause-9-5-3)=
### 9.5.3 配置代理和管理代理参与的配置与管理流程

(gbt-48336-401-2026-clause-9-5-3-1)=
#### 9.5.3.1 发现与连接行为

:::{div}
:class: standard-paragraph

<p>管理代理应作为服务端，承载广播音频流管理服务，配置代理应作为客户端，访问广播音频流管理服务。管理代理应作为被发现方，在设备公开信息中携带标准服务信息，该信息中包含广播音频流管理服务的 UUID。作为发现方，配置代理发现和连接管理代理。连接建立后，配置代理应对管理代理进行服务发现，获取管理代理承载的广播音频流管理服务的服务结构。</p>

:::

:::{div}
:class: standard-paragraph

<p>配置代理也应对音宿设备进行设备发现和连接，发现与连接的流程应遵循音频应用标准的定义。</p>

:::

(gbt-48336-401-2026-clause-9-5-3-2)=
#### 9.5.3.2 音频流属性获取

:::{div}
:class: standard-paragraph

<p>管理代理访问音宿承载的音频属性公开服务，获取音频服务端上指定属性，见表 57。</p>

:::

(gbt-48336-401-2026-clause-9-5-3-3)=
#### 9.5.3.3 代理扫描开始

:::{div}
:class: standard-paragraph

<p>配置代理向管理代理发送代理扫描开始请求，管理代理应回复广播音频流控制响应。若结果码为配置成功，配置代理应开始扫描广播音频流配置信息，发现广播音源，管理代理可停止自行扫描广播音频流配置信息。</p>

:::

(gbt-48336-401-2026-clause-9-5-3-4)=
#### 9.5.3.4 代理扫描结束

:::{div}
:class: standard-paragraph

<p>配置代理向管理代理发送代理扫描结束请求，管理代理应回复广播音频流控制响应。若结果码为配置成功，配置代理应停止扫描广播音频流配置信息。</p>

:::

:::{div}
:class: standard-paragraph

<p>管理代理可开始自行扫描广播音频流配置信息。</p>

:::

(gbt-48336-401-2026-clause-9-5-3-5)=
#### 9.5.3.5 广播音源的匹配与筛选

:::{div}
:class: standard-paragraph

<p>配置代理应解析音源的广播音频流配置信息，并将编解码器类型和参数与音宿的能力、音频流类型、音频通道信息与音宿的音频流属性进行比对，为代理扫描的音宿筛选出合适的音源。</p>

:::

(gbt-48336-401-2026-clause-9-5-3-6)=
#### 9.5.3.6 广播音源配置

:::{div}
:class: standard-paragraph

<p>配置代理通过音源配置请求将合适的音源信息发送给管理代理，管理代理应回复广播音频流控制响应，若结果码为配置成功，应在附加信息中携带本地广播音频流集合标识。本地广播音频流标识是管理代理（即，广播音频流管理服务的服务端）生成的、用于在管理代理侧唯一标识配置代理添加的广播音频流集合。配置代理获取该标识后，后续对广播音频流集合的操作均通过本地广播音频流标识进行；若管理代理不接受音源配置，则应回复结果码为配置失败的广播音频流控制响应。</p>

:::

:::{div}
:class: standard-paragraph

<p>管理代理通过广播音频流接收通知信令反馈数据的接收状况。若音频数据是加密的，则需要在数据状态字段返回 0x01，表示“接收成功，数据需解密”，提示配置代理发送口令。</p>

:::

(gbt-48336-401-2026-clause-9-5-3-7)=
#### 9.5.3.7 音频流接收重配置

:::{div}
:class: standard-paragraph

<p>配置代理使用音频流接收重配置请求改变音宿需接收的音频流。管理代理收到该信令后，回复广播音频流控制响应。</p>

:::

:::{div}
:class: standard-paragraph

<p>音宿根据音频流接收重配置请求中的接收指示来进行广播音频流接收的更新。音宿应停止接收请求中接收指示位图中音频流序号为 0b 的广播音频流，应开始接收请求中接收状态位图中音频流序号为1b 的广播音频流。</p>

:::

:::{div}
:class: standard-paragraph

<p>管理代理应反馈广播音频流状态变更事件，报告音频流接收重配置后的执行结果。</p>

:::

(gbt-48336-401-2026-clause-9-5-3-8)=
#### 9.5.3.8 口令设置

:::{div}
:class: standard-paragraph

<p>若配置代理接收到接收成功，数据需解密的广播音频流接收通知时，应通过口令设置请求将口令配置给管理代理。管理代理应回复广播音频流控制响应。</p>

:::

:::{div}
:class: standard-paragraph

<p>音宿应使用被配置的口令对音频数据进行解密，并将解密结果通过数据状态通知事件反馈给配置代理。</p>

:::

(gbt-48336-401-2026-clause-9-5-3-9)=
#### 9.5.3.9 音源移除

:::{div}
:class: standard-paragraph

<p>配置代理通过音源移除请求指示管理代理移除指定的广播音频源集合信息，并释放相关配置资源。</p>

:::

:::{div}
:class: standard-paragraph

<p>管理代理可将本地广播音频流集合标识回收并重复使用。</p>

:::

:::{div}
:class: standard-paragraph

<p>若音宿正在接收音频数据时，配置代理不应发送音源移除请求。否则，管理代理应回复结果为配置失败的广播音频流控制响应。</p>

:::

(gbt-48336-401-2026-clause-9-5-3-10)=
#### 9.5.3.10 音源流异常断开

:::{div}
:class: standard-paragraph

<p>若音宿的广播业务传输通道异常断开，与该音宿匹配的管理代理应发送数据状态为接收失败的广播音频流接收通知给配置代理。配置代理可重新进行音源配置流程，指示音宿重新建立广播业务传输通道并接收音频数据。</p>

:::
