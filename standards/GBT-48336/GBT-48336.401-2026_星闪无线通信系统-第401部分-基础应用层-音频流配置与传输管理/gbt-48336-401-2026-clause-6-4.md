# 6.4 音频流混音服务

(gbt-48336-401-2026-clause-6-4-1)=
## 6.4.1 服务概述

:::{div}
:class: standard-paragraph

<p>音频流混音服务用于客户端配置服务端的混音功能和开启/关闭混音代理功能，混音功能仅用于来自多个音源设备的音频流。</p>

:::

:::{div}
:class: standard-paragraph

<p>音频流混音服务的服务端应为音宿。音频流混音服务的客户端为混音配置器或混音代理。混音配置器负责混音策略的配置，混音周期的配置，以及接收溢出提醒。混音代理可代替音宿接收多路音频流并混音，再将混音后的单路音频流以单播方式传输给音宿。混音代理访问音频流混音服务中的混音代理属性。设备的混音策略为预置时，无法修改。此时服务中不应设置混音策略控制点方法。当含有混音策略控制点时，混音策略可被动态配置。</p>

:::

:::{div}
:class: standard-paragraph

<p>音频流混音服务和广播音频流管理服务不应在同一设备上共存。</p>

:::

:::{div}
:class: standard-paragraph

<p>当音频流混音服务中含有混音代理属性时，服务端应发送广播，在设备公开信息中的标准服务数据信息中携带音频流混音服务的 UUID。设备公开信息及标准服务数据信息应符合 GB/T 48336.301。</p>

:::

:class: standard-paragraph

</tr>
</table>

::::

:::{div}
:class: standard-paragraph

<p>混音策略属性中可含有多个音频流类型及对应的权重系数。</p>

:::

:::{div}
:class: standard-paragraph

<p>混音策略影响客户端的混音行为和混音效果。混音行为的影响指的是，不接收权重系数为 0 的类型的音频流，以及接收独占区的音频流时，若该音频流类型的权重系数大于当前正在播放的独占音频流的权重系数或当前播放的音频流为混音音频流时，则进行抢占。被抢占音频流应停止播放。</p>

:::

:::{div}
:class: standard-paragraph

<p>混音效果的影响指的是，权重系数表示该类型音频流在混音音频流的输出占比，权重系数越大，输出占比越大。</p>

:::

:::{div}
:class: standard-paragraph

<p>音频流混音服务应给出默认的混音策略，在混音策略属性中呈现。</p>

:::

:::{div}
:class: standard-paragraph

<p>混音策略的可配置音频流类型范围由音宿能力的支持音频流类型指示。若混音策略中音频流类型的权重系数为 0，则音宿能力的可接收音频流类型字段中该音频流类型对应的比特应置 0。若当前接收的是独占区音频流，则比该音频流类型权重系数小的音频流类型在音宿能力中的可接收音频流类型字段对应的比特应置 0。</p>

:::

(gbt-48336-401-2026-clause-6-4-7)=
## 6.4.7 溢出提醒

:::{div}
:class: standard-paragraph

<p>当混音后的音频流发生溢出时，服务端使用溢出提醒对客户端进行通知。客户端接收到该事件后可调整权重系数或整体增益来避免溢出的持续发生。溢出提醒携带混音音频流中占比最大的音频流类型。</p>

:::

(gbt-48336-401-2026-clause-6-4-8)=
## 6.4.8 配置过程

:::{div}
:class: standard-paragraph

<p>音频流混音配置过程主要涉及读取、配置和溢出通知过程。客户端使用 SSAP 读取操作读取混音策略属性的属性值，即获取当前服务端默认的混音策略。</p>

:::

:::{div}
:class: standard-paragraph

<p>混音配置请求用于客户端修改服务端的混音策略，服务端接收混音配置请求后，应回复配置响应。</p>

:::

:::{div}
:class: standard-paragraph

<p>溢出通知用于服务端通知客户端有溢出发生，此时服务端可内部处理此溢出，但仍需将溢出通知发送给客户端，客户端可重新发起混音配置请求进行调整。</p>

<p>混音代理过程主要分为：</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a） 服务端（音宿）发送含有音频流混音服务 UUID 的广播报文，客户端（混音代理）进行扫描，发现音宿设备并连接；</p>
</li>
<li><p>b） 客户端通过 SSAP 读取操作获取服务端的混音策略属性值；</p>
</li>
<li><p>c） 客户端通过 SSAP 读取操作获取服务端的音频属性公开服务中的音宿能力属性值；</p>
</li>
<li><p>d） 客户端通过 SSAP 写入操作开启或关闭混音代理功能。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>当混音开启后，客户端需要按照服务端的混音策略进行混音，混音后产生的音频流需要符合服务端的音宿能力。</p>
