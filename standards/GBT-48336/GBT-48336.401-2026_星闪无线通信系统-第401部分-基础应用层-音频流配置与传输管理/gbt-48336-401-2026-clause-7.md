## 7.2 音频流配置与管理流程

(gbt-48336-401-2026-clause-7-2-1)=
### 7.2.1 通则

:::{div}
:class: standard-paragraph

<p>音频流的配置与管理流程应基于服务管理流程。音频客户端通过 SSAP 信令访问音频服务端进行配置与管理。音频服务端通过信令响应、通知及指示等方式反馈配置的结果和信息变更。音频客户端在访问音频服务端之前，应先对音频服务端进行服务发现流程。服务发现应符合 GB/T 48336.301。</p>

:::

:::{div}
:class: standard-paragraph

<p>音频服务端与客户端通过服务管理传输通道，传输上述的控制面信令，音频服务端与客户端还应建立音频流数据通道，进行音频数据的传输。</p>

:::

:::{div}
:class: standard-paragraph

<p>音频流配置与管理流程主要分为：音频属性获取、音频流配置、音频流数据通道开启、音频流传输、音频流停止、音频流释放，以及可选的音频流重配置。一个完整的交互示例见图 4。</p>

:::

(gbt-48336-401-2026-clause-7-2-3)=
### 7.2.3 音频流配置

:::{div}
:class: standard-paragraph

<p>音频访问点未对任何配置项进行配置时，应进行音频流配置。配置项为音频元信息、编解码器、数据通道要求、音频流端口号。配置项可通过单个音频流配置请求一次性进行配置，也可通过多个音频流配置请求分步进行配置。配置项均配置完成后，该音频访问点的音频流配置过程结束。其中，无需配置的配置项代表配置完成。</p>

:::

:::{div}
:class: standard-paragraph

<p>音频客户端可使用单步配置或分步配置，音频服务端应支持两种配置方式。</p>

:::

(gbt-48336-401-2026-clause-7-2-4)=
### 7.2.4 单次配置

:::{div}
:class: standard-paragraph

<p>音频客户端通过音频流配置请求一次性对音频访问点的所有配置项进行配置，音频服务端通过音频流配置响应对该请求进行响应。</p>

:::

:::{div}
:class: standard-diagram

```{mermaid}
sequenceDiagram
  participant A as 音频客户端
  participant B as 音频服务端
  A->>B: SSAP_CALL_METHOD_REQ (<br/>操作码：0x01（音频流配置）；<br/>音频访问点数量：0x01；<br/>音频访问点标识：x<br/>配置项：<br/>{音频元信息<br/>编解码器，<br/>数据通道要求<br/>端口号}<br/>)
  B->>A: SSAP_CALL_METHOD_RSP (<br/>操作码：0x01（音频流配置）；<br/>音频访问点数量：0x01；<br/>音频访问点标识：x<br/>结果码；<br/>附加信息<br/>)
```

:::

:::{div}
:class: standard-caption

<p>图 5　音频流配置和响应</p>

:::{div}
:class: standard-paragraph

<p>如图 5 所示，音频客户端发送音频流配置请求给音频服务端，音频服务端应回复对应操作码的音频流控制响应。</p>

:::

<ul class="standard-list">

</li>
<li><p>—— 若音频服务端不接受被配置的一个或多个参数，音频服务端应在结果码中给出操作失败的结果码和指示失败原因的附加信息，结果码可指示任一不接受的音频参数。配置流程终止。此时，音频访问点处于未经配置的状态。</p>
</li></ul>

:::

(gbt-48336-401-2026-clause-7-2-5)=
### 7.2.5 分步配置

:::{div}
:class: standard-paragraph

<p>音频客户端按照特定的顺序通过多次音频流配置请求完成对音频访问点的所有配置项进行配置，音频服务端通过音频流配置响应对音频客户端的每个请求进行响应，并根据当前配置项的参数给出音频客户端下一步配置的配置项的推荐参数。音频客户端再根据推荐参数进行下一步配置项的配置，该下一步配置项的参数可使用推荐参数，也可由推荐参数得出，具体步骤进行如下详述。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a） 音频客户端通过音频流配置请求配置音频元信息。音频元信息应包含音频流类型、音频持续时长、媒体实例标识及其他上层应用配置标准要求的音频元信息，音频服务端的处理如下：</p>
<ul class="standard-list">
<li><p>• 若音频服务端接受被配置的参数，应在音频流控制响应中携带操作成功的结果码（0x01），并在附加信息中携带编解码器推荐参数，由音频服务端根据音频元信息及自身实际情况给出推荐的编解码器参数；</p>
</li>
<li><p>• 若音频服务端不接受被配置的参数，应在音频流控制响应中携带“无效的元信息”或“元信息配置失败”的结果码。</p>
</li></ul>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>音频客户端可重新执行步骤 a）以重新配置音频元信息。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="2">
<li><p>b） 音频客户端通过音频流配置请求配置编解码器，音频服务端的处理如下：</p>
<ul class="standard-list">
<li><p>• 若音频服务端接受被配置的参数，应在音频流控制响应中携带操作成功的结果码（0x01），并在附加信息中携带数据通道要求推荐参数，由音频服务端根据编解码器参数及自身实际情况给出推荐的数据通道要求参数；</p>
</li>
<li><p>• 若音频服务端不接受被配置的参数，可在音频流控制响应中携带“不支持或无效的编解码器</p>
</li></ul>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>参数”或“编解码器参数配置失败”的结果码。</p>

:::

:::{div}
:class: standard-paragraph

<p>音频客户端可重新执行步骤 b）以重新配置编解码器。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="3">
<li><p>c） 音频客户端通过音频流配置请求配置数据通道要求和音频流端口号。其中，音频流端口号参数可不配置，音频服务端的处理如下：</p>
<ul class="standard-list">
<li><p>• 若音频服务端接受被配置的参数，应在音频流控制响应中携带操作成功的结果码（0x00）；</p>
</li>
<li><p>• 若音频服务端不接受被配置的参数，可在音频流控制响应中携带“不支持或无效的数据通道要求”或“数据通道要求配置失败”的结果码。</p>
</li></ul>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>音频客户端可重新执行步骤 c）以重新配置数据通道要求。</p>

:::

:::{div}
:class: standard-paragraph

<p>若执行 a）、b）、c）任一步骤失败，音频客户端应重新执行该步骤，以继续完成音频流配置过程。音频客户端也可通过音频流释放请求将已配置的音频参数移除。</p>

:::

(gbt-48336-401-2026-clause-7-2-6)=
### 7.2.6 音频流数据通道开启

:::{div}
:class: standard-paragraph

<p>音频客户端与音频服务端通过音频流数据通道开启流程将音频访问点关联到满足要求的数据通道上。在执行该流程之前，对应的音频访问点的所有配置项应配置完成。音频服务端收到该请求后，应回复对应操作码的音频流控制响应：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 若音频服务端接受该请求，音频服务端应在音频流控制响应携带“操作成功”的结果码；</p>
</li>
<li><p>—— 若音频参数配置未完成，音频服务端应在音频流控制响应携带“音频流控制请求无法执行”的结果码。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>以上过程执行成功，则：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 使用不透传方式时，关联到基础服务层的传输通道；</p>
</li>
<li><p>—— 使用 SLE 透传方式时，关联到接入层逻辑链路。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>数据通道关联完成，则该流程结束。此时，可进行音频流重配置、音频流传输或音频流释放流程。</p>

:::

:::{div}
:class: standard-paragraph

### 7.2.7 音频流传输

:::{div}
:class: standard-paragraph

<p>音频流传输流程用于音宿通知音源，开始传输对应音频访问点的音频数据。在执行该流程之前，音频访问点应关联到满足要求的数据通道上。</p>

:::

:::{div}
:class: standard-paragraph

<p>音频流传输的交互有两种方式：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 方式一，音频客户端发送音频流传输请求给音频服务端；</p>
</li>
<li><p>—— 方式二，音频服务端发送音频流传输变更事件给音频客户端。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>对于方式一，若音频服务端已做好接收音频数据的准备，应在音频流控制响应中携带操作成功的结果码。音频客户端接收到该响应后，开始传输音频流数据。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于方式二，若音频客户端接收到该事件后，开始传输音频流数据。</p>

:::

:::{div}
:class: standard-paragraph

<p>若音频流传输请求中的音频访问点未建立音频流传输通道，对于方式 1，音频服务端应在音频流控制响应中携带“音频流控制请求不可执行”的音频流控制响应；对于方式 2，音频客户端应直接忽略音频流传输变更事件。</p>

:::

:::{div}
:class: standard-paragraph

<p>若音频流开始传输，可进行音频流停止、音频流重配置或音频流释放流程。</p>

:::

:::{div}
:class: standard-paragraph

<p>音频流传输流程的示例见图 7。</p>

:::

:::{div}
:class: standard-diagram

### 7.2.8 音频流停止

:::{div}
:class: standard-paragraph

<p>音频流停止流程用于停止相关音频访问点正在传输的音频数据，音频流停止的交互有两种方式：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 方式一，音频客户端发送音频流停止请求给音频服务端，音频服务端应返回对应操作码的音频流控制响应；</p>
</li>
<li><p>—— 方式二，音频服务端发送音频流停止变更事件给音频客户端。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>该流结束后，音频访问点的音频数据传输应停止。此时，音频数据通道仍保持关联。</p>

:::

:::{div}
:class: standard-paragraph

<p>若音频流停止请求中的音频访问点未传输音频数据，对于方式一，音频服务端应在音频流控制响应中携带“音频流控制请求不可执行”的音频流控制响应；对于方式二，音频客户端应直接忽略音频流停止变更事件。</p>

:::

:::{div}
:class: standard-paragraph

(gbt-48336-401-2026-clause-7-2-9)=
### 7.2.9 音频流释放

:::{div}
:class: standard-paragraph

<p>音频流释放流程用于移除音频数据通道的关联，并且可移除音频访问点的音频参数配置信息。音频流释放的交互有两种方式：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 方式一，音频流客户端发送音频流释放请求给音频服务端，音频服务端返回对应操作码的音频流控制响应；</p>
</li>
<li><p>—— 方式二，音频服务端发送音频流释放变更给音频客户端。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>该流程结束后，应移除音频数据通道的关联。若音频流释放参数指示音频服务端释放音频参数配置信息，音频访问点的音频参数应清除，音频访问点回到未配置状态。</p>

:::

:::{div}
:class: standard-paragraph

<p>若音频流释放请求中的音频访问点处于未配置状态，对于方式一，音频服务端应在音频流控制响应中携带“音频流控制请求不可执行”的音频流控制响应；对于方式二，音频客户端应直接忽略音频流释放变更事件。</p>

:::

:::{div}
:class: standard-paragraph

<p>音频流释放流程的示例见图 9。</p>

:::

:::{div}
:class: standard-diagram

```{mermaid}

  A->>B: SSAP_CALL_METHOD_REQ (<br/>操作码：0x05（音频流释放）；<br/>音频访问点数量：0x01；<br/>音频访问点标识：x<br/>释放指示<br/>)
  B->>A: SSAP_CALL_METHOD_RSP (<br/>操作码：0x05（音频流释放）；<br/>音频访问点数量：0x01；<br/>音频访问点标识：x<br/>结果码<br/>)
  B->>A: SSAP_VALUE_NTF (<br/>操作码：0x03（音频流释放变更）；<br/>音频访问点数量：0x01；<br/>音频访问点标识：x<br/>)
  A<<->>B: 移除数据通道关联
```

### 7.2.10 音频流重配置

:::{div}
:class: standard-paragraph

<p>音频流重配置流程用于在已关联音频数据通道后，音频客户端对音频服务端相关音频访问点的配置项进行更新的过程。</p>

:::

(gbt-48336-401-2026-clause-7-2-11)=
### 7.2.11 音频元信息重配置

:::{div}
:class: standard-paragraph

<p>在已关联音频数据通道后，音频客户端可发起音频流配置请求对音频元信息进行重配置。音频服务端应回复对应操作码的音频流控制响应：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 若音频服务端接受被配置的参数，应在音频流控制响应中携带操作成功的结果码（0x00），并更新音频访问点属性；</p>
</li>
<li><p>—— 若音频服务端不接受被配置的参数，应在音频流控制响应中携带“无效的元信息”或“元信息配置失败”的结果码。</p>
</li></ul>

:::

(gbt-48336-401-2026-clause-7-2-12)=
### 7.2.12 音频流码率更新

:::{div}
:class: standard-paragraph

<p>在音频数据传输过程中，音频客户端或音频服务端可发起音频流码率更新过程，对码率进行更新。</p>

:::

:::{div}
:class: standard-paragraph

<p>由音频客户端触发，音频客户端可发送音频流码率更新请求给音频服务端，音频服务端应回复对应操作码的音频流控制响应：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 若音频服务端接受被配置的参数，应在音频流控制响应中携带操作成功的结果码（0x00），并更新音频访问点属性；</p>
</li>
<li><p>—— 若音频服务端不接受被配置的参数，应在音频流控制响应中携带“不支持或无效的编解码器参</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>数”或“编解码器参数配置失败”的结果码。</p>

:::

:::{div}
:class: standard-paragraph

<p>由音频服务端触发，音频服务端可发送音频流码率更新事件给音频客户端，音频客户端若接受该变更，后续过程与由音频客户端触发一致。若音频客户端不接受该变更，则忽略该事件。</p>

:::

:::{div}
:class: standard-paragraph

<p>音频流码率更新的能力依赖音频编解码器，音频编解码器宜说明对该能力的支持情况。</p>

:::

(gbt-48336-401-2026-clause-7-2-13)=
### 7.2.13 音频流数据通道异常断开

:::{div}
:class: standard-paragraph

<p>音频数据通道异常断开后，解除与音频数据通道的关联。</p>
