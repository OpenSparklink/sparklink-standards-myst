# 6.7 数据转发机制

:::{div}
:class: standard-paragraph

<p>融合系统类型二中，T 节点通过 G 节点建立 PDU 会话，T 节点与 5G 核心网之间的数据需要在 G节点中转。</p>

:::

:::{div}
:class: standard-paragraph

<p>融合系统类型二数据转发示意见图 31，5G 核心网为每个 G 节点建立的 PDU 会话个数有限（系统最大支持 15 个），而 G 节点最大可与数百个 T 节点保持连接，即 G 节点根据 T 节点需求所建立的 PDU会话中存在一个 PDU 会话由多个 T 节点共享的情况。在该过程中，G 节点管理 T 节点的 PDU 会话，并将 G 节点与 T 节点的对应关系上报给 5G 核心网，5G 核心网可基于 IP 或端口区分 PDU 会话中不同T 节点的数据，详见 6.7.1 和 6.7.2。</p>

(gbt-48336-304-2026-clause-6-7-1)=
## 6.7.1 基于 IP 的数据转发机制

:::{div}
:class: standard-paragraph

<p>融合系统基于 IP 的数据转发机制见图 32，基于该机制区分一个 PDU 会话中的不同 T 节点数据，具体描述如下。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a） 5G 核心网为 G 节点分配公网 IP 地址，一个 PDU 会话可关联 G 节点的多个公网 IP 地址。</p>
</li>
<li><p>b） G 节点为 T 节点分配标识或 IP 地址：</p>
<ol class="decimal-list" start="1">
<li><p>1） T 节点标识 G 节点覆盖或管理的 T 节点；</p>
</li>
<li><p>2） G 节点把公网 IP 地址直接分配给 T 节点，或者 G 节点为 T 节点分配私有 IP 地址。</p>
</li></ol>
</li></ol>

:::

:::{admonition} 注
:class: note

<p>G 节点为 T 节点是分配临时标识还是 IP 地址，由 G 节点设备实现，协议不做规定。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="3">
<li><p>c） 基于 6.5.2.2 步骤 4 中的 PDU 会话修改请求消息（不限定采用其他的 NAS 消息），G 节点可把T 节点标识与 G 节点公网 IP 地址的对应关系发送给 5G 核心网。</p>
</li>
<li><p>d） G 节点在 PDU 层用 G 节点公网 IP 地址封装数据包，5G 核心网可基于 G 节点公网 IP 地址区分 PDU 会话中不同 T 节点的数据。</p>
</li></ol>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="5">
<li><p>e） UDM 或 MDF 网元可维护 T 节点标识等用户数据，MDF 的定义详见 7.2.3。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>不同 T 节点的数据包可承载在不同的 QoS 流上，通过 QoS 流区分不同的 T 节点。</p>

:::

(gbt-48336-304-2026-clause-6-7-2)=
## 6.7.2 基于端口的数据转发机制

:::{div}
:class: standard-paragraph

<p>融合系统基于端口的数据转发机制见图 33，该机制区分一个 PDU 会话中的不同 T 节点数据，与基于 IP 的数据转发机制的不同之处如下：</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a） 5G 核心网为 G 节点分配公网 IP 地址，一个 PDU 会话关联 G 节点的一个公网 IP 地址；</p>
</li>
<li><p>b） 基于 6.5.2.2 中的 PDU 会话修改请求消息（不限定采用其他的 NAS 消息），G 节点可把 T 节点标识与 G 节点端口的对应关系发送给 5G 核心网；</p>
</li>
<li><p>c） 5G 核心网基于 G 节点端口区分 PDU 会话中不同 T 节点的数据。</p>
</li></ol>

:::
