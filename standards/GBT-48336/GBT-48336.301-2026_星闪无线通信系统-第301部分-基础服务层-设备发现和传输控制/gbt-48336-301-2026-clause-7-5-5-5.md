# 7.5.5.5 读取操作

(gbt-48336-301-2026-clause-7-5-5-5-1)=
## 7.5.5.5.1 SSAP\_READ\_REQ消息

:::{div}
:class: standard-paragraph

<p>SSAP_READ_REQ 消息为有响应的读取请求消息,用于客户端向服务端发送读取的请求,可使用句柄和数据类别读取单个或多个条目的数据信息,支持读取散列值,支持分包发送。</p>

:::

:class: standard-paragraph

:::

:::{div}
:class: standard-paragraph

<p>消息码参数值设置为0x08。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息控制码参数值使用bit1~bit0设置为本条消息的分包信息,其他比特位预留。</p>

:::

:::{div}
:class: standard-paragraph

<p>请求句柄列表参数值可设置为单个或多个不同的值。本消息中数据类型可用于指示属性、方法或事件条目中数据字段的成员(见表72)。</p>

(gbt-48336-301-2026-clause-7-5-5-5-2)=
## 7.5.5.5.2 SSAP\_READ\_RSP消息

:::{div}
:class: standard-paragraph

<p>SSAP_READ_RSP消息为读取响应消息,用于服务端在收到SSAP_READ_REQ 消息后,向客户端发送读取响应,可支持一个响应中包含多个条目数据,支持分包发送。</p>

:::

::::{div}
:class: table-scroll

(gbt-48336-301-2026-table-74)=
:::{div}
:class: standard-table-caption

<p>表 74　SSAP_READ_RSP消息格式</p>

:::

<table class="standard-table ">
<tr>
<th>消息参数</th>
<th>长度/字节</th>
<th>消息参数描述</th>
</tr>
<tr>
<td>消息码(0x09)</td>
<td>1</td>
<td>消息码</td>
</tr>
<tr>
<td>消息控制码</td>
<td>1</td>
<td>bit1~bit0:起 始 数 据 包 (0b00)/中 间 数 据 包<br/>(0b01)/结束数据包(0b10)/单个完整数据包<br/>(0b11)<br/>bit2:$0=$单个值$;1=$多个值<br/>bit3:错误标识$:0=$没有错误$;1=$存在错误<br/>bit7~bit4:预留</td>
</tr>
<tr>
<td>数据列表</td>
<td>可变</td>
<td>读取单个值时,读取成功时,返回数据列表结<br/>构为:{数据值}<br/>读取单个值时,读取失败时,返回数据列表结<br/>构为:{数据信息指示}读取多个值时,返回数据列表 结 构 为:{{数 据 信 息 指 示 1,数 据 值<br/>1},{数据信息指示2,数据值2}…..}<br/>返回的数据值结果与请求中的顺序对应数据信息指示长度2字节,使用 bit15表示数据值是否读取正常,数据列表中bit15为0时,指示失败,bit14~bit0表示的是错误码;如果bit15<br/>为1时,指示成功,bit14~bit0表示的是对应数据值的长度。读取多个值时,当数据信息指示字段指示读取失败时,数据值不存在</td>
</tr>
</table>

::::

:::{div}
:class: standard-paragraph

<p>SSAP_READ_RSP消息由消息码、消息控制码、数据列表等参数组成,SSAP_READ_RSP消息见表74。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息码参数值设置为0x09。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息控制码参数值以位图方式表示,其中bit7~bit4为预留值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端请求读取的句柄在服务端不存在,服务端应发送包含“无效句柄”错误码的SSAP_READ_RSP 消息。</p>

:::

:::{div}
:class: standard-paragraph

<p>如SSAP_READ_REQ 消息未能成功读取到符合要求的单个或多个数据值,服务端应发送带“数据类型错误”错误码的SSAP_READ_RSP消息。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端没有足够的授权,服务端应发送包含“客户端未授权”错误码的SSAP_READ_RSP消息。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端没有足够的安全认证,服务端应发送包含“客户端未认证”错误码的SSAP_READ_RSP消息。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端没有调整加密配置,但欲读取的属性条目需加密,服务端应发送包含“承载未加密”错误码的SSAP_READ_RSP消息。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端所请求的属性条目由于访问控制原因不能被读取,服务端应发送包含“禁止读取”错误码的SSAP_READ_RSP消息。</p>

:::

:::{div}
:class: standard-paragraph

<p>如服务端的读取响应超过 MTU,需分包发送而服务端不支持分包发送时,服务端应发送包含“服务端不支持分包”错误码的SSAP_READ_RSP消息。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端所请求的属性条目由于应用错误原因不能被读取,服务端应发送包含由上层应用定义的应用错误码的SSAP_READ_RSP消息。</p>

:::

(gbt-48336-301-2026-clause-7-5-5-5-3)=
## 7.5.5.5.3 SSAP\_READ\_BY\_UUID\_REQ消息

:::{div}
:class: standard-paragraph

<p>SSAP_READ_BY_UUID_REQ 消息为基于 UUID 读取请求消息,用于客户端已获知属性、方法或事件 UUID 但未知其句柄信息时,向服务端发送基于 UUID 读取条目数据的请求。</p>

:::

::::{div}
:class: table-scroll

(gbt-48336-301-2026-table-75)=
:::{div}
:class: standard-table-caption

<p>表 75　SSAP_READ_BY_UUID_REQ消息格式</p>

:::

<table class="standard-table ">
<tr>
<th>消息参数</th>
<th>长度/字节</th>
<th>消息参数描述</th>
</tr>
<tr>
<td>消息码(0x0A)</td>
<td>1</td>
<td>消息码</td>
</tr>
<tr>
<td>消息控制码</td>
<td>1</td>
<td>bit0:$0=$标准 UUID,$1=$自定义<br/>UUIDbit7~bit1:预留</td>
</tr>
<tr>
<td>起始句柄</td>
<td>2</td>
<td>查找的起始句柄</td>
</tr>
<tr>
<td>结束句柄</td>
<td>2</td>
<td>查找的结束句柄</td>
</tr>
<tr>
<td>数据类型</td>
<td>1</td>
<td>指示读取的数据类型</td>
</tr>
<tr>
<td>UUID</td>
<td>2/16</td>
<td>指定属性、方法或事件的 UUID</td>
</tr>
</table>

::::

:::{div}
:class: standard-paragraph

<p>SSAP_READ_BY_UUID_REQ 消息由消息码、消息控制码、起始句柄、结束句柄、数据类型和UUID 等参数组成SSAP_READ_BY_UUID_REQ 消息见表75。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息码参数值设置为0x0A。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息控制码参数值使用bit0指示 UUID 类型,其余比特位为预留值。</p>

:::

:::{div}
:class: standard-paragraph

<p>起始句柄参数值设置为查找的起始句柄。</p>

:::

:::{div}
:class: standard-paragraph

<p>结束句柄参数值设置为查找的结束句柄。</p>

:::

:::{div}
:class: standard-paragraph

<p>起始句柄值应小于或等于结束句柄值。客户端希望获取的服务信息句柄值应设置在起始句柄值与结束句柄值之间。</p>

:::

:::{div}
:class: standard-paragraph

<p>数据类型参数值设置为指示读取的数据类型,其定义可参考表72和表73。</p>

:::

:::{div}
:class: standard-paragraph

<p>UUID 参数值设置为待读取的属性、方法或事件的 UUID,支持标准 UUID 和自定义 UUID。</p>

:::

:::{div}
:class: standard-paragraph

<p>本消息支持一次请求包含一个或多个条目。如读取结果中出现单个或多个错误,应由服务端返回SSAP_READ_BY_UUID_RSP消息(不应为SSAP_ERROR_RSP消息)。具体错误码可见表53。</p>

:::

(gbt-48336-301-2026-clause-7-5-5-5-4)=
## 7.5.5.5.4 SSAP\_READ\_BY\_UUID\_RSP消息

:::{div}
:class: standard-paragraph

<p>SSAP_READ_BY_UUID_RSP消息为基于 UUID 读取响应消息,用于服务端收到SSAP_READ_BY_UUID_REQ 消息后,向客户端发送读取响应,可支持多一个消息中包含多条属性,支持分包发送。</p>

:::

::::{div}
:class: table-scroll

(gbt-48336-301-2026-table-76)=
:::{div}
:class: standard-table-caption

<p>表 76　SSAP_READ_BY_UUID_RSP消息格式</p>

:::

<table class="standard-table ">
<tr>
<th>消息参数</th>
<th>长度/字节</th>
<th>消息参数描述</th>
</tr>
<tr>
<td>消息码(0x0B)</td>
<td>1</td>
<td>消息码</td>
</tr>
<tr>
<td>消息控制码</td>
<td>1</td>
<td>bit1~bit0:起 始 数 据 包 (0b00)/中 间 数 据 包<br/>(0b01)/结束数据包(0b10)/单个完整数据包<br/>(0b11))<br/>bit2:$0=$单个实例$;1=$多个实例<br/>bit3:错误标识$:0=$ 没 有 错 误$;1=$ 存 在 错 误<br/>bit7~bit4:预留</td>
</tr>
<tr>
<td>数据列表</td>
<td>可变</td>
<td>返回单个实例时,读取成功时,数据列表结构为:{句柄,数据值}<br/>返回单个实例时,读取失败时,数据列表结构为:{句柄,数据信息指示}返回多个实例时,数<br/>据列表结构为:{{句柄1,数据信息指示1,数据值1},{句柄2,数据信息指示2,数据值2}…}<br/>数据信息指示长度2字节,使用 bit15表示数据值是否读取正常,数据列表中 bit15是0失败时,bit14~bit0表示的是错误码;如果bit15<br/>是1成功时,bit14~bit0表示的是对应数据值的长度</td>
</tr>
</table>

::::

:::{div}
:class: standard-paragraph

<p>SSAP_READ_BY_UUID_RSP消息由消息码、消息控制码和数据列表等参数组成(见表76)。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息码参数值设置为0x0B。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息控制码参数值以位图方式表示,其中bit7~bit4为预留值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如SSAP_READ_BY_UUID_REQ 消息中起始句柄值大于结束句柄值或为0x0000,服务端应发送包含“无效句柄”错误码的SSAP_READ_BY_UUID_RSP消息,并将错误句柄值设置为该起始句柄值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如SSAP_READ_BY_UUID_REQ 消息未能成功读取到符合 UUID 和数据类别要求的单个或多个属性条目,服务端应发送包含“未找到条目”错误码的SSAP_READ_BY_UUID_RSP消息,并将错误句柄值设置为对应的请求句柄值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端没有提供足够的授权,服务端应发送包含“客户端未授权”错误码的SSAP_READ_BY_UUID_RSP消息,并将错误句柄值设置为对应的请求句柄值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端没有提供足够的安全认证,服务端应发送包含“客户端未认证”错误码的 SSAP_READ_BY_UUID_RSP消息,并将错误句柄值设置为对应的请求句柄值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端没有调整加密配置,但读取的属性条目需加密,服务端应发送包含“承载未加密”错误码的SSAP_READ_BY_UUID_RSP消息,并将错误句柄值设置为对应的请求句柄值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端所请求的属性条目由于访问控制原因不能被读取,服务端应发送包含“禁止读取”错误码的SSAP_READ_BY_UUID_RSP消息,并将错误句柄值设置为对应的请求句柄值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如服务端的读取响应超过 MTU,需分包发送而服务端不支持分包发送时,服务端应发送包含“服务端不支持分包”错误码的SSAP_READ_RSP消息。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端所请求的属性条目由于应用错误原因不能被读取,则服务端应发送由上层应用定义的应用错误码的SSAP_READ_BY_UUID_RSP消息,并将错误句柄值设置为对应的请求句柄值。</p>

:::
