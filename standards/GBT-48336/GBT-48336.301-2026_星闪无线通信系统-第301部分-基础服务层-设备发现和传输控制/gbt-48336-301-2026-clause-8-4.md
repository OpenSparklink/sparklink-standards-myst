# 8.4 传输通道的传输模式

(gbt-48336-301-2026-clause-8-4-1)=
## 8.4.1 通则

:::{div}
:class: standard-paragraph

<p>本文件支持基础模式、流模式、可靠模式和透传模式等四种传输通道的传输模式。每个传输通道应采用其中一种传输模式。</p>

:::

:::{div}
:class: standard-paragraph

<p>所有设备应支持基础模式,基础模式是传输通道的缺省模式。使用基础模式建立传输通道时无需进行传输模式能力查询。</p>

:::

:::{div}
:class: standard-paragraph

<p>流模式、可靠模式与透传模式是可选传输模式,应先进行传输模式能力查询,仅在双方均支持某类传输模式时才可建立该模式的传输通道。应在传输通道建立信令中指定传输模式。</p>

:::

:::{div}
:class: standard-paragraph

<p>传输模式能力查询信令见9.3.1.2和9.3.1.3。能力查询结果如下:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— $\mathrm{result}=0x00:$表示只支持基础模式;</p>
</li>
<li><p>——— $\mathrm{result}=0\mathrm{xFF}:$表示支持其他传输模式,应通过capInfo中transModeCapInfo字段进一步指示所支持的一个或多个可选传输模式(见表88)。</p>
</li></ul>

:::

:class: table-scroll

(gbt-48336-301-2026-clause-8-4-2)=
## 8.4.2 基础模式

(gbt-48336-301-2026-clause-8-4-2-1)=
### 8.4.2.1 概述

:::{div}
:class: standard-paragraph

<p>基础模式应采用基础帧对数据进行封装和传输。在基础模式下发送数据,在基础服务层内无需对端确认,PDU 不重传且无超时丢弃机制。</p>

:::

:::{div}
:class: standard-paragraph

<p>所有使用固定 TCID 的传输通道默认使用基础模式。</p>

:::

(gbt-48336-301-2026-clause-8-4-2-2)=
### 8.4.2.2 发送端

:::{div}
:class: standard-paragraph

<p>在基础模式下应将SDU 按8.5.2规定的基础帧格式添加 TCID 与长度指示等信息以生成 PDU,并进行PDU 发送操作。发送端应直接丢弃超过 MTU 大小的SDU。</p>

:::

(gbt-48336-301-2026-clause-8-4-2-3)=
### 8.4.2.3 接收端

:::{div}
:class: standard-paragraph

<p>在基础模式下应支持接收PDU、校验PDU 长度、PDU 解封装等操作。</p>

:::

(gbt-48336-301-2026-clause-8-4-2-4)=
### 8.4.2.4 缓存控制

:::{div}
:class: standard-paragraph

<p>基础模式下没有流控机制,是否进行缓存控制留给具体实现。</p>

:::

(gbt-48336-301-2026-clause-8-4-3)=
## 8.4.3 流模式

(gbt-48336-301-2026-clause-8-4-3-1)=
### 8.4.3.1 通则

:::{div}
:class: standard-paragraph

<p>流模式可用于传输对实时性有一定要求的数据。应采用增强帧(见8.5.3)进行传输,且仅支持采用增强帧中的单向聚合帧及单向分片帧。传输过程中每一个 PDU 在进入发送队列之后应有一个关联的丢弃定时器,超时的PDU 应被丢弃,可向应用层上报该丢弃异常事件。</p>

:::

(gbt-48336-301-2026-clause-8-4-3-2)=
### 8.4.3.2 发送端

(gbt-48336-301-2026-clause-8-4-3-2-1)=
#### 8.4.3.2.1 分片与聚合

:::{div}
:class: standard-paragraph

<p>应支持根据当前 MPS将SDU 分片或聚合成PDU、PDU 发送、超时丢弃等操作。</p>

:::

:::{div}
:class: standard-paragraph

<p>发送端应直接丢弃超过 MTU 大小的SDU。</p>

:::

(gbt-48336-301-2026-clause-8-4-3-2-2)=
#### 8.4.3.2.2 发送 PDU

:::{div}
:class: standard-paragraph

<p>应按顺序生成PDUSN,并将其置于增强帧 TxSeq字段。</p>

:::

:::{div}
:class: standard-paragraph

<p>经过分片与聚合形成的PDU 进入发送队列,宜为每一个进入队列的 PDU 关联并启动一个丢弃定时器。</p>

:::

:::{div}
:class: standard-paragraph

<p>应从发送队列开头依次取出PDU 进行发送,应丢弃超时的PDU,可将丢弃 PDU 的 TxSeq字段值上报给上层。</p>

:::

(gbt-48336-301-2026-clause-8-4-3-3)=
### 8.4.3.3 接收端

(gbt-48336-301-2026-clause-8-4-3-3-1)=
#### 8.4.3.3.1 接收 PDU

:::{div}
:class: standard-paragraph

<p>接收PDU、校验PDU、PDU 重排序、PDU 合片或分拆成SDU、SDU 递交至上层是接收端应完成的操作。</p>

:::

:::{div}
:class: standard-paragraph

<p>所有操作应维护一个接收队列,接收队列缓存所有校验合法且还没有合片或分拆的 PDU,接收队列的缓存大小由设备自行确定。接收队列相关变量见表89。</p>

:::

:::{div}
:class: standard-paragraph

<p>不应对收到的PDU 进行确认。</p>

:::

::::{div}
:class: table-scroll

:::{div}
:class: standard-paragraph

<p>流模式下的接收队列示意图见图13。接收端滑窗由以下事件触发:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 插入队列的PDU 会根据 TxSeq字段进行滑窗;</p>
<ul class="standard-list">
<li><p>• 如果$\mathrm{TxSeq}==ExpectedTxSeq$,则将$ExpectedTxSeq$变量置为下一个未成功接收的数据包的 TxSeq字段值;</p>
</li>
<li><p>• 如果$ExpectedTxSeq\lt \mathrm{TxSeq}\lt MaxExpectedTxSeq$,则不进行任何滑窗;</p>
</li>
<li><p>• 如果$\mathrm{TxSeq}\gt =MaxExpectedTxSeq$,则设置$MaxExpectedTxSeq=\mathrm{TxSeq}+1$。</p>
</li></ul>
</li>
<li><p>——— 数据包被递交至上层之后需要滑窗:</p>
<ul class="standard-list">
<li><p>• 当$\mathrm{TxSeq}==BufferSeq$的数据包被递交至上层之后,该数据包会被移出队列,$BufferSeq$变量递增1。</p>
</li></ul>
</li></ul>

<p>接收端应维护一个重排序定时器,用于处理 PDU 乱序到达。重排序定时器有一个参数重排序变量$Seq$,用于记录重排序定时器等待的PDU。如果在定时器超时仍然没有收到该 PDU,则认为该数据包已经丢失,丢失PDU 的 TxSeq字段值应上报,后续处理会将该PDU 按已成功接收处理。</p>

:::

:::{div}
:class: standard-paragraph

<p>接收端在接收到PDU 之后按照如下操作进行数据处理:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 将校验通过且队列中没有的PDU 插入队列,并且进行接收端滑窗;</p>
</li>
<li><p>——— PDU 插入队列后:</p>
<ul class="standard-list">
<li><p>• 如果重排序定时器在运行中,且参数重排序变量$Seq$等于该PDU 的 TxSeq字段值,则停止重排序定时器;如果$ExpectedTxSeq\lt MaxExpectedTxSeq$,则启动重排序定时器;</p>
</li>
<li><p>• 如果重排序定时器没有运行,且$ExpectedTxSeq\lt MaxExpectedTxSeq$,则启动重排序定时器。</p>
</li></ul>
</li></ul>

:::

(gbt-48336-301-2026-clause-8-4-3-3-2)=
#### 8.4.3.3.2 校验 PDU

:::{div}
:class: standard-paragraph

<p>校验包含对PDU 的 CRC校验与 TxSeq校验。CRC校验失败的PDU 会被丢弃,CRC校验成功的PDU 会进一步进行 TxSeq校验。</p>

:::

:::{div}
:class: standard-paragraph

<p>TxSeq校验后的处理操作见表90。</p>

:::

::::{div}
:class: table-scroll

(gbt-48336-301-2026-table-90)=
:::{div}
:class: standard-table-caption

<p>表 90　流模式下TxSeq校验及处理操作</p>

:::

<table class="standard-table ">
<tr>
<th>TxSeq条件</th>
<th>处理操作</th>
</tr>
<tr>
<td>$TxSeq\lt ExpectedTxSeq$</td>
<td>丢弃PDU</td>
</tr>
<tr>
<td>$TxSeq==ExpectedTxSeq$</td>

<td>$TxSeq\gt =BufferSeq+txWindow$</td>
<td>丢弃PDU</td>

(gbt-48336-301-2026-clause-8-4-3-3-3)=
#### 8.4.3.3.3 合片与分拆

:::{div}
:class: standard-paragraph

<p>对于接收队列中的PDU,接收端应从 TxSeq字段值等于$BufferSeq$ 变量值的PDU 开始按顺序取出,然后传入数据传输与适配功能单元的数据合片与分拆单元。合片与分拆单元处理详见8.7.3.2和8.7.4.2。</p>

:::

:::{div}
:class: standard-paragraph

<p>如果 TxSeq字段值等于$BufferSeq$ 变量值的 PDU 还没有被接收,则不会进行取出动作,如果TxSeq字段值等于$BufferSeq$变量值的PDU 已被确认丢失(即对应的重排序定时器超时),则可上报TxSeq字段值,然后认为该PDU 被取出。PDU 从队列取出之后会进行滑窗。</p>

:::

(gbt-48336-301-2026-clause-8-4-3-3-4)=
#### 8.4.3.3.4 SDU 递交

:::{div}
:class: standard-paragraph

<p>PDU 经过合片与分拆成SDU 之后会递交至上层。</p>

:::

(gbt-48336-301-2026-clause-8-4-3-3-5)=
#### 8.4.3.3.5 缓存控制

:::{div}
:class: standard-paragraph

<p>流模式下由于没有应答,接收方与发送方没有流控机制。可选的,接收方可自行实现缓存控制。</p>

:::

:::{div}
:class: standard-paragraph

<p>一种参考实现是:接收方可实现固定有限缓存,当接收队列满时$(MaxExpectedTxSeq-BufferSeq==$最大缓存队列长度),如果继续接收到PDU,可丢弃新接收到的PDU 或最早接收的PDU。</p>

:::

:::{div}
:class: standard-paragraph

<p>另一种参考实现是:接收方可实现动态缓存,当接收队列满时申请更大缓存空间,直到无法申请更大空间再进行PDU 丢弃。</p>

:::

:::{div}
:class: standard-paragraph

<p>丢弃的PDU 可上报其 TxSeq字段值。</p>

:::

(gbt-48336-301-2026-clause-8-4-4)=
## 8.4.4 可靠模式

(gbt-48336-301-2026-clause-8-4-4-1)=
### 8.4.4.1 概述

:::{div}
:class: standard-paragraph

<p>可靠模式应采用增强帧进行传输,在传输过程中使用对应类型的增强帧进行传输。可靠模式用于传输可靠数据,传输过程中每一个PDU 有 ACK/NACK 响应,异常PDU 会重传,重传超过最大次数之后会触发传输达到最大次数异常(见8.7.5.2)。</p>

:::

(gbt-48336-301-2026-clause-8-4-4-2)=
### 8.4.4.2 发送端

(gbt-48336-301-2026-clause-8-4-4-2-1)=
#### 8.4.4.2.1 通则

:::{div}
:class: standard-paragraph

<p>对于使用可靠模式的传输通道,发送端应支持将 SDU 分片或聚合成 PDU、发送 PDU、重传 PDU等操作。应维护一个发送队列,发送队列缓存所有已发送但还未收到应答的PDU。</p>

:::

:::{div}
:class: standard-paragraph

<p>发送端会按顺序生成每个新传PDU 的SN,并将其置于增强帧中的 TxSeq字段中。重传 PDU 的TxSeq字段值应与原始新传PDU 保持一致。</p>

:::

:::{div}
:class: standard-paragraph

<p>发送队列相关变量描述见表91。</p>

:::

::::{div}
:class: table-scroll

(gbt-48336-301-2026-table-91)=

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 每发送一个新传PDU,该PDU 的 TxSeq字段应设置为$NextTxSeq$ 变量值,并将$NextTxSeq$变量递增1;</p>
</li>
<li><p>——— 每接收到一个应答,如果应答期待的 PDU 序号 ReqSeq 字段值满足不等式:$ExpectedAckSeq\lt \mathrm{ReqSeq}\lt =NextTxSeq$,则将$ExpectedAckSeq$变量置为 ReqSeq 字段值,并重启重传定时器;如果$ExpectedAckSeq==NextTxSeq$,则停止重传定时器。</p>
</li></ul>

<p>发送方应维护一个重传定时器,用于对PDU 的应答进行定时。当重传定时器超时,发送方将该数据包视为没有被成功接收。</p>

:::

:::{div}
:class: standard-paragraph

<p>发送方会维护一个重传序列号$ReTxSeq$ 变量,标识当前需要重传的PDU 的 TxSeq字段值。初始状态$ReTxSeq$ 变量设置为$NextTxSeq$ 变量值;当收到异常应答时$,ReTxSeq$ 变量会被置为异常应答包含的 ReqSeq字段值;当重传定时器超时时$,ReTxSeq$ 变量会被置为$ExpectedAckSeq$ 变量值。</p>

:::

(gbt-48336-301-2026-clause-8-4-4-2-2)=
#### 8.4.4.2.2 分片与聚合

:::{div}
:class: standard-paragraph

<p>发送方支持将SDU 通过分片或聚合操作形成PDU,详见8.7.3.1和8.7.4.1。</p>

:::

(gbt-48336-301-2026-clause-8-4-4-2-3)=
#### 8.4.4.2.3 发送 PDU

:::{div}
:class: standard-paragraph

<p>发送端在发送时会判断当前$ReTxSeq$ 变量和$NextTxSeq$ 变量是否相等,用以判断当前是否有需要重传的PDU。</p>

:::

:::{div}
:class: standard-paragraph

<p>当$ReTxSeq==NextTxSeq$ 时:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 如果$ExpectedAckSeq\lt =NextTxSeq\lt ExpectedAckSeq+\mathrm{txWindow},$则发送新传 PDU,并将$NextTxSeq$ 变量和$ReTxSeq$ 变量递增1;</p>
</li>
<li><p>——— 如果$NextTxSeq==ExpectedAckSeq+\mathrm{txWindow},$则不发送新传PDU。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>当$ReTxSeq\lt NextTxSeq$ 时:判断$\mathrm{TxSeq}==ReTxSeq$ 的重传 PDU 次数是否达到最大发送次数,如果达到最大发送次数则进入传输达到最大次数异常处理,如果没有达到最大发送次数,则发送该重传PDU,将该重传PDU 发送计数器递增1,将$ReTxSeq$ 变量递增1。</p>

:::

:::{div}
:class: standard-paragraph

<p>当PDU 发送之后,如果重传定时器没有在运行则会启动重传定时器;如果重传定时器在运行中,则不会对该重传定时器进行任何操作。每个传输通道上只会存在一个重传定时器。</p>

:::

(gbt-48336-301-2026-clause-8-4-4-2-4)=
#### 8.4.4.2.4 发送轮询

:::{div}
:class: standard-paragraph

<p>发送轮询操作为可选操作,用于长时间没有收到应答时主动发起请求应答。当发送端启动发送轮询时,应将下一个待发送PDU 对应的增强帧中的P字段设置为1。</p>

:::

:::{div}
:class: standard-paragraph

<p>在本文件中,发送端确定启动发送轮询的条件留给实现。</p>

:::

:::{div}
:class: standard-paragraph

<p>发送方可生成并维护发送轮询定时器及超时时间,用于记录没有收到应答的时间。每收到一个应答,发送方将发送轮询定时器重置。当发送轮询定时器超时确定启动发送轮询,然后重置定时器。</p>

:::

:::{div}
:class: standard-paragraph

<p>发送方也可生成并维护发送轮询计数器和最大次数,用于记录没有收到应答时发送的数据包个数。</p>

:::

:::{div}
:class: standard-paragraph

<p>每收到一个应答,发送方将计数器清0,每发送一个PDU 将计数器递增1。当发送轮询计数器达到最大次数时确定启动发送轮询,然后重置计数器。</p>

:::

(gbt-48336-301-2026-clause-8-4-4-3)=
### 8.4.4.3 接收端

(gbt-48336-301-2026-clause-8-4-4-3-1)=
#### 8.4.4.3.1 通则

:::{div}
:class: standard-paragraph

<p>对于使用可靠模式的传输通道,接收端应支持接收 PDU、校验 PDU、PDU 重排序、PDU 合片或分拆成SDU、应答和SDU 递交至上层等操作。所有操作应维护一个接收队列,接收队列缓存所有校验合法且还没有合片或分拆的PDU,接收队列的大小rxWindow 与发送队列的大小txWindow 相等。</p>

:::

:class: standard-paragraph

<p>接收队列相关的变量描述见表92。</p>

<p>接收端滑窗由以下事件触发,滑窗操作原则如下。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 插入队列的PDU 会根据 TxSeq字段值进行滑窗:</p>
<ul class="standard-list">
<li><p>• 如果$\mathrm{TxSeq}==ExpectedTxSeq$,则将$ExpectedTxSeq$变量置为下一个未成功接收的PDU 的 TxSeq字段值;</p>
</li>
<li><p>• 如果$ExpectedTxSeq\lt \mathrm{TxSeq}\lt MaxExpectedTxSeq$,则不进行任何滑窗;</p>
</li>
<li><p>• 如果$\mathrm{TxSeq}\gt =MaxExpectedTxSeq$,则设置$MaxExpectedTxSeq=\mathrm{TxSeq}+1$。</p>
</li></ul>
</li>
<li><p>——— 数据包被递交至上层之后需要滑窗:当$\mathrm{TxSeq}==BufferSeq$的数据包被递交至上层之后,该数据包会被移出队列$,BufferSeq$ 变量递增1。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>接收端应维护一个应答定时器,用于在长时间没有发送应答时触发$S=0$的正常应答。应答定时器超时会发送$S=0$应答帧;每发送一次应答(正常应答或异常应答),应答定时器清0。</p>

:::

:::{div}
:class: standard-paragraph

<p>接收端应维护一个重排序定时器,用于处理 PDU 乱序到达。重排序定时器用一个参数记录重排序定时器等待的PDU 的序号。如果在定时器超时仍然没有收到该PDU,则认为该数据包已经丢失,会触发$S==1$异常应答。</p>

:::

:::{div}
:class: standard-paragraph

<p>接收端应维护异常应答发送次数。异常应答发送次数初始为1,每发送一次包含与前一次相同ReqSeq字段值的异常应答会将异常应答发送次数递增1,每发送一次包含与前一次不同 ReqSeq字段值的异常应答会将异常应答发送次数重置为1。当异常应答发送次数达到传输通道设置的最大发送次数时仍需异常应答时,会触发传输达到最大次数异常处理。</p>

:::

(gbt-48336-301-2026-clause-8-4-4-3-2)=
#### 8.4.4.3.2 接收 PDU

:::{div}
:class: standard-paragraph

<p>接收端在接收到PDU 之后会进行数据处理与/或应答处理。其中数据处理是对 PDU 的数据部分进行处理,应答处理是对PDU 的应答部分进行处理。应答处理详见8.4.4.4.3。数据处理包括:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 将校验通过且队列中没有的PDU 插入队列,并且进行滑窗,详见接收队列滑窗;</p>
</li>
<li><p>——— PDU 插入队列后:</p>
<ul class="standard-list">
<li><p>• 如果重排序定时器在运行中,且参数重排序Seq参数等于该PDU 的 TxSeq字段值,则停止重排序定时器;</p>
</li>
<li><p>• 如果$ExpectedTxSeq\lt MaxExpectedTxSeq$,则启动重排序定时器;</p>
</li>
<li><p>• 如果重排序定时器没有运行,且$ExpectedTxSeq\lt MaxExpectedTxSeq$,则启动重排序定时器。</p>
</li></ul>
</li></ul>

:::

#### 8.4.4.3.4 合片与分拆

:::{div}
:class: standard-paragraph

<p>对于接收队列中的PDU,接收端应从$\mathrm{TxSeq}==BufferSeq$ 的PDU 开始按顺序取出,然后传入数据传输与适配功能单元的数据合片与分拆单元。</p>

:::

:::{div}
:class: standard-paragraph

<p>如果$\mathrm{TxSeq}==BufferSeq$ 的PDU 还没有被接收,则不会进行取出动作。PDU 从队列取出之后会进行滑窗。</p>

:::

#### 8.4.4.3.5 SDU 递交

:::{div}
:class: standard-paragraph

<p>PDU 经过合片与分拆成SDU 之后会递交至上层。</p>

:::

(gbt-48336-301-2026-clause-8-4-4-4)=
### 8.4.4.4 应答

(gbt-48336-301-2026-clause-8-4-4-4-1)=
#### 8.4.4.4.1 概述

:::{div}
:class: standard-paragraph

<p>应答分为正常应答与异常应答,正常应答可包含在双向帧中,也可单独采用应答帧并包含$S==0;$</p>

:::

:::{div}
:class: standard-paragraph

<p>异常应答只能采用应答帧并包含$S==1\text{。}$</p>

:::

:::{div}
:class: standard-paragraph

<p>正常应答表示 TxSeq&lt;ReqSeq的PDU 均成功接收并且$\mathrm{TxSeq}\gt =\mathrm{ReqSeq}$的PDU 状态未知或仍在处理中。正常应答仅用于发送方滑窗。</p>

:::

:::{div}
:class: standard-paragraph

<p>异常应答表示 TxSeq&lt;ReqSeq的PDU 均成功接收并且$\mathrm{TxSeq}\gt =\mathrm{ReqSeq}$的 PDU 状态异常,需要重传。异常应答除了触发发送方滑窗外,还会请求发送方对PDU 进行重传。</p>

:::

(gbt-48336-301-2026-clause-8-4-4-4-2)=
#### 8.4.4.4.2 应答发送

:::{div}
:class: standard-paragraph

<p>接收端会在如下条件进行应答。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 自身需要发送数据时,采用双向帧包含应答信息进行正常应答。其中,双向帧中的 F 字段设置为0。</p>
</li>
<li><p>——— 应答定时器超时之后会采用应答帧进行正常应答。其中,应答帧中的F字段设置为0。</p>
</li>
<li><p>——— 对于发送轮询流程(可选),当收到$P==1$的 PDU 时进行正常应答。其中,双向帧或应答帧中的F字段设置为1。</p>
</li>
<li><p>——— 当重排序定时器超时之后进行异常应答。其中,应答帧中的F字段设置为0。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>正常应答发送时,接收端的增强帧中的 ReqSeq字段应设置为$BufferSeq$ 变量值,异常应答发送时,接收端的增强帧中的 ReqSeq字段应设置为$ExpectedTxSeq$ 变量值。</p>

:::

(gbt-48336-301-2026-clause-8-4-4-4-3)=
#### 8.4.4.4.3 应答接收

:::{div}
:class: standard-paragraph

<p>接收到应答之后需要进行发送端滑窗操作。</p>

:::

:::{div}
:class: standard-paragraph

<p>发送方接收到正常应答之后,如果$ReTxSeq\lt \mathrm{ReqSeq}($说明当前正在重传更早的 PDU)则置$ReTxSeq$变量为 ReqSeq字段值。</p>

:::

:::{div}
:class: standard-paragraph

<p>发送方接收到异常应答之后,会置$ReTxSeq$ 变量为 ReqSeq字段值。</p>

:::

(gbt-48336-301-2026-clause-8-4-5)=
## 8.4.5 透传模式

:::{div}
:class: standard-paragraph

<p>透传模式应采用透传帧(见8.5.4)进行传输。透传模式传输通道在传输过程中不对SDU 进行任何缓存、封包、流控等处理,直接将SDU 传入接入层。透传模式传输通道应与接入层的逻辑信道建立一对一映射关系。</p>

:::
