# 7.5.5.4 服务发现

(gbt-48336-301-2026-clause-7-5-5-4-1)=
## 7.5.5.4.1 SSAP\_FIND\_STRUCTURE\_REQ消息

:::{div}
:class: standard-paragraph

<p>服务发现交互消息支持服务结构发现和分层发现:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 服务结构发现可通过一个请求发现服务端的整个服务结构;</p>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 分层发现可根据服务结构层次依次通过多个请求逐步发现首要服务、引用服务、属性、方法或事件等服务结构成员。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>SSAP_FIND_STRUCTURE_REQ 消息为服务结构发现请求消息,用于客户端向服务端发送发现服务结构的请求。客户端可通过本消息使用各种查找类型,例如整个服务结构、首要服务、引用服务等。</p>

:::

## 7.5.5.4.2 SSAP\_FIND\_STRUCTURE\_RSP消息

:::{div}
:class: standard-paragraph

<p>SSAP_FIND_STRUCTURE_RSP消息为服务结构发现响应消息,用于服务端收到SSAP_FIND_STRUCTURE_REQ 消息后,向客户端发送对应的响应,支持分包发送。</p>

:::

:::{div}
:class: standard-paragraph

<p>服务端根据客户端请求消息中的条目类型进行过滤,服务端可根据自身实现选择条目格式打包,并在SSAP_FIND_STRUCTURE_RSP消息的消息控制码中使用bit3~bit2指示条目类型,客户端根据SSAP_FIND_STRUCTURE_RSP消息中的条目类型进行解包。</p>

:::

:::
:::{div}
:class: standard-paragraph

:::

:::{div}
:class: standard-paragraph

<p>SSAP_FIND_STRUCTURE_RSP消息中所有返回的服务条目句柄应遵循从小到大的顺序。</p>

<p>SSAP_FIND_BY_UUID_REQ 消息由消息码、消息控制码、起始句柄、结束句柄和 UUID 等参数组成。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息码参数值设置为0x06。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息控制码参数值以位图方式表示,其中bit7~bit6为预留值,其他比特位定义见表64。</p>

:::

:::{div}
:class: standard-paragraph

<p>起始句柄参数值设置为待查找的起始句柄。</p>

:::

:::{div}
:class: standard-paragraph

<p>结束句柄参数值设置为待查找的结束句柄。起始句柄值应小于或等于结束句柄值。客户端希望获取的服务信息句柄值应设置在起始句柄值与结束句柄值之间。</p>

:::

:::{div}
:class: standard-paragraph

<p>UUID 参数值可设置为待查找的服务、属性、方法或事件的 UUID。</p>

:::

:::{div}
:class: standard-paragraph

<p>如 UUID 参数值设置为服务的 UUID,则查找返回的结果,需根据消息控制码的指示查找类型进行过滤:如指示查找类型为单个服务结构,则查询该服务的所有服务结构;如指示查找类型为首要服务,则查询该服务的首要服务信息;如指示查找类型为属性,则查询该服务的所有属性信息;其他类似。</p>

:::

:::{div}
:class: standard-paragraph

<p>如 UUID 参数值设置为属性、方法或事件的 UUID,则返回指定的属性、方法或事件的信息。</p>

:::

:::{div}
:class: standard-paragraph

<p>UUID 参数值和消息控制码中所指示的查找类型应匹配,如 UUID 参数值设置为某属性的UUID,则消息控制码中所指示的查找类型应设置为属性。</p>

:::
