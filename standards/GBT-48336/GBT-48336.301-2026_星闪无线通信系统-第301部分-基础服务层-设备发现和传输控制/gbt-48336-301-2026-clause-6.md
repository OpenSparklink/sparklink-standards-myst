(gbt-48336-301-2026-clause-6)=
# 6 设备发现

(gbt-48336-301-2026-clause-6-1)=
## 6.1 功能描述

:::{div}
:class: standard-paragraph

<p>设备发现功能单元定义了设备之间实现相互发现的方法、流程、信息格式等规范。</p>

:::

:::{div}
:class: standard-paragraph

<p>基础应用层或基础服务层其他功能单元是使用设备发现功能的需求主体,在设备发现过程中,应指定角色,并根据相应角色,发送被发现方公开信息或配置扫描过滤策略并执行信道扫描。</p>

:::

(gbt-48336-301-2026-clause-6-2)=
## 6.2 角色

:::{div}
:class: standard-paragraph

<p>基础服务层在设备发现过程中的角色要求如下。</p>

:::

:::{div}
:class: standard-paragraph

<p>被发现方:应根据基础应用层和基础服务层功能单元的被发现需求发布被发现方公开信息。</p>

:::

:::{div}
:class: standard-paragraph

<p>发现方:应根据基础应用层和基础服务层功能单元的发现需求设置过滤策略,结合接收到的被发现方公开信息,筛选出符合条件的被发现方并上报。</p>

:::

:::{div}
:class: standard-paragraph

<p>设备可同时运行被发现方和发现方角色。</p>

:::

(gbt-48336-301-2026-clause-6-3)=
## 6.3 被发现方公开信息

(gbt-48336-301-2026-clause-6-3-1)=
### 6.3.1 概述

:::{div}
:class: standard-paragraph

<p>设备公开信息按作用可分为两类:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 发现等级:是被发现方公开的可发现性信息,也是对发现方的要求,要求和期望发现方在接收到发现等级信息后应如何处理;</p>
</li>
<li><p>——— 设备信息:是被发现方自身属性信息和设备运行的应用公开信息等。</p>
</li></ul>

:::

(gbt-48336-301-2026-clause-6-3-2)=
### 6.3.2 发现等级

:::{div}
:class: standard-paragraph

<p>被发现方可发布的五个发现等级要求如下:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 不可见发现:一种最小范围的设备发现要求,不希望被一般设备发现并呈现给用户,仅特定应用能感知被发现设备才可发现;</p>
</li>
<li><p>——— 一般可发现:无特殊发现要求;</p>
</li>
<li><p>——— 优先可发现:要求被优先发现。优先可发现在时间维度上表现为更快地被发现;在空间维度上,与同类型设备相比,被发现的要求更强烈;</p>
</li>
<li><p>——— 被曾配对过的设备发现:要求只有被曾经配对过的设备才能发现;</p>
</li>
<li><p>——— 被指定设备发现:要求只有被指定 L2ID 的设备才能发现。</p>
</li></ul>

:::

(gbt-48336-301-2026-clause-6-3-3)=
### 6.3.3 设备信息

:::{div}
:class: standard-paragraph

<p>设备信息包括设备名称、设备支持的服务信息和通信域域名(应符合 GB/T48336.201—2026的规定)等,详细定义见6.5。</p>

:::

(gbt-48336-301-2026-clause-6-4)=
## 6.4 发现方过滤策略

(gbt-48336-301-2026-clause-6-4-1)=
### 6.4.1 概述

:::{div}
:class: standard-paragraph

<p>过滤策略是设备发现功能单元为基础应用层和基础服务层功能单元提供的服务之一,用于筛选其感兴趣的设备。发现方也可不设置任何过滤规则。</p>

:::

(gbt-48336-301-2026-clause-6-4-2)=
### 6.4.2 被发现方发现等级在发现方的处理

:::{div}
:class: standard-paragraph

<p>本文件定义了发现方处理不同发现等级的规则。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 不可见发现:不应直接将设备及其信息展示在用户 UI界面上。</p>
</li>
<li><p>——— 一般可发现:不做特殊处理,即在用户 UI界面上展示该设备及其信息。</p>
</li>
<li><p>——— 优先可发现:当发现方应用或基础服务层功能单元收到包含优先可发现的设备信息时,应优先处理或展示该设备及其信息。</p>
</li>
<li><p>——— 被曾配对过的设备发现:发现方设备发现功能单元应检查双方设备是否已配对。如果是,则发现该设备,并将设备信息上报;如果不是,则丢弃该设备信息,不对该设备进行发现。</p>
</li>
<li><p>——— 被指定设备发现:发现方接入层应检查被发现方配置的 L2ID,如果与本设备 L2ID 匹配,则接入层发现该设备并上报给设备发现功能单元;如果不匹配,接入层将丢弃该设备信息。设备发现功能单元按基础应用层或基础服务层其他功能单元的需求处理该设备信息即可。</p>
</li></ul>

:::

(gbt-48336-301-2026-clause-6-4-3)=
### 6.4.3 过滤条件

:::{div}
:class: standard-paragraph

<p>可作为过滤条件的选项包括 L2ID、设备名称,以及被发现方公开的其他设备信息。被发现方公开信息类型如表2所示,每一项可作为一个过滤条件。所有过滤条件可按需求向接入层配置,由接入层完成设备发现结果过滤。或由设备发现功能单元本身完成设备发现结果过滤。</p>

:::

(gbt-48336-301-2026-clause-6-4-4)=
### 6.4.4 过滤规则

:::{div}
:class: standard-paragraph

<p>对于多项过滤条件,提供逻辑与、逻辑或、逻辑非的配置:逻辑与是指被发现设备须同时符合各项过滤条件才能被发现;逻辑或是指被发现设备只需符合一项过滤条件就能被发现;逻辑非是指被发现设备符合一项过滤条件就被丢弃。</p>

:::

:::{div}
:class: standard-paragraph

<p>当满足过滤条件后,还需满足被发现方的需求之后,才能将设备信息上报。</p>

:::

#### 6.5.2.7 设备本地名称

:::{div}

## 6.6 配置管理

(gbt-48336-301-2026-clause-6-6-1)=
### 6.6.1 概述

:::{div}
:class: standard-paragraph

<p>设备可支持仅SLB工作、仅SLE工作以及SLB和SLE同时工作等多种接入层工作方式。在设备上电初始化后,基础服务层可向接入层查询其支持的特性与能力,或接入层向基础服务层上报其支持的特性与能力。</p>

:::

:::{div}
:class: standard-paragraph

<p>设备发现需求主体在执行设备发现过程时,应确定自身角色并向设备发现功能单元发送相关请求,并指示接入层类型、发现等级或过滤策略等参数。</p>

:::

:::{div}
:class: standard-paragraph

<p>设备发现功能单元按设备发现需求主体的要求,向接入层配置广播消息或系统消息内容、扫描参数、过滤策略等,并按照配置参数执行广播或扫描过程并反馈执行结果。</p>

:::
