# 5 概述

(gbt-48336-301-2026-clause-5-1)=
## 5.1 功能概述

:::{div}
:class: standard-paragraph

<p>星闪无线通信系统分为基础应用层、基础服务层和接入层。</p>

:::

:::{div}
:class: standard-paragraph

<p>基础服务层设备发现与传输控制包括控制面和数据面,涉及五大功能,包括设备发现、服务管理、数据传输与适配、连接管理、测量管理等,分别由设备发现功能单元、服务管理功能单元、数据传输与适配功能单元、连接管理功能单元和测量管理功能单元所承载。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 设备发现功能单元:定义了基础服务层的设备发现流程,向基础应用层或其他功能单元提供设备发现功能,定义了统一的设备公开信息格式,以及相关过滤条件,用以更好地披露信息或找到期望的信息,见第6章。</p>
</li>
<li><p>——— 服务管理功能单元:主要负责星闪无线通信设备(以下简称“星闪设备”或“设备”)的服务注册、维护、删除、发现和访问等服务管理功能,同时为基础应用层各类型服务提供统一的服务架构、服务结构和服务交互协议SSAP,见第7章。</p>
</li>
<li><p>——— 数据传输与适配功能单元:主要基于应用业务 QoS参数特征匹配合适的传输模式与传输通道,以及负责PDU 分片与合片、PDU 聚合与拆分、缓存与重传等数据面处理,见第8章。</p>
</li>
<li><p>——— 连接管理功能单元:主要负责设备间的传输通道建立、重配置、释放等操作,维护与逻辑信道映射关系等功能,见第9章。</p>
</li>
<li><p>——— 测量管理功能单元:主要负责面向传输通道的性能测量,向其他功能单元提供测量服务等,见第10章。</p>
</li></ul>

:::

:::{admonition} 注
:class: note

<p>本文件未定义 QoS管理功能单元及其功能,见 GB/T48336.302—2026。</p>

:::

:::{div}
:class: standard-paragraph

<p>数值表示方法和空口传输规则,遵循如下规定。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 如果无明确指示,下标为0的比特(如b<sub>0</sub>)表示为比特序列最低位。描述一组比特序列时默认最低位在前,最高位在后,例如二进制比特序列110,分别表示$b_{0}\text{、}b_{1}$和b<sub>2</sub>。</p>
</li>
<li><p>b) 如果无明确指示,数值表示方法默认采用十进制,并支持其他进制。例如数值15,默认表示为十进制数值15,采用二进制表示为0b00001111,采用八进制表示为0o017,采用十进制表示为0d15,采用十六进制表示为0x0F。</p>
</li>
<li><p>c) 一组比特序列按照比特位置从小到大的顺序在空口中传输,即最低比特位最先在空口中传输。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>同时,8个比特组成一个字节,对于多个字节组成的字节序列,按字节位置从小到大的顺序在空口中传输,即最低位置字节最先在空口中传输(小端序传输)。</p>

:::

(gbt-48336-301-2026-clause-5-2)=
## 5.2 通用控制信令概述

:::{div}
:class: standard-paragraph

<p>基础服务层通用控制信令包括传输控制信令、中继控制信令、测量管理信令和 QoS管理信令,用于设备间相同功能单元之间进行通用控制信息交互。各类信令的功能定义如下。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 传输控制信令用于传输通道的建立、重配、删除和连接管理能力协商,详见9.3.1。传输控制信令由连接管理功能单元负责生成、解析和交互。</p>
</li>
<li><p>——— 中继控制信令用于中继传输通道的建立、重配置和删除,详见9.3.2。中继控制信令由连接管理功能单元负责生成、解析和交互。</p>
</li>
<li><p>——— 测量管理信令用于测量实例建立、释放和测量结果上报,详见10.4。测量管理信令由连接管理功能单元负责生成、解析和交互。</p>
</li>
<li><p>——— QoS管理信令用于协商 QoS参数,QoS管理信令由 QoS管理功能单元负责生成、解析和交互。见 GB/T48336.302—2026的规定。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>通用控制信令在SLE通用管理传输通道或SLB通用管理传输通道内进行传输。</p>

:::

:::{div}
:class: standard-paragraph

<p>通用控制信令格式如图1所示,采用基础帧格式(见8.5.2),数据信息包含一个或多个code相同的信令内容,信令长度不能超过 MTU。</p>

:::

:::{div}
:class: standard-paragraph

<p>通用控制信令包括code、identifier、length和data四个部分,各部分描述如下。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— code:通用控制信令类型,整型,取值0~255,具体类型定义见表1。当接收到一个无法识别的code时,应回复异常响应消息(code为0x00)。</p>
</li>
<li><p>——— identifier:通用控制信令标识,标识一条具体的信令。整型,取值0~255。通用控制信令的一条具体请求信令和对应响应信令的identifier应相同。对于请求信令中设置identifier的方法留给实现,应确保两个连续请求信令identifier不同。例如:identifier可随着新的请求信令依次递增1,到达255后重新设置为0,并循环使用。当一条请求信令已经发送且没有收到回复时,不使用该identifier发送新的请求信令。</p>
</li>
<li><p>——— length:长度字段,用于指示信令中数据载荷部分的长度,整型,取值0~65535。</p>
</li>
<li><p>——— data:信令的数据载荷,包含某信令的具体信息。</p>
</li></ul>

:::
