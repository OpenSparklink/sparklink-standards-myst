# 7.5.5.2 错误处理

:::{div}
:class: standard-paragraph

<p>SSAP_ERROR_RSP消息用于一个请求无法完成时由服务端返回错误响应。</p>

:::

:::{div}
:class: standard-paragraph

<p>在访问请求消息中如涉及访问多个条目的错误响应,则由服务端通过对应的响应消息(不应为SSAP_ERROR_RSP消息)直接返回至发起请求的客户端。</p>

:::

:::{div}
:class: standard-paragraph

<p>SSAP_ERROR_RSP消息由消息码、消息控制码、请求消息码、错误句柄和错误码等参数组成(见表52)。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息码参数值设置为0x01。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息控制码参数值为预留。</p>

:::

:::{div}
:class: standard-paragraph

<p>请求消息码参数值设置为产生此错误的对应请求消息码。</p>

:::

:::{div}
:class: standard-paragraph

<p>错误句柄参数值设置为产生此错误的对应请求句柄值。</p>

:::

:::{div}
:class: standard-paragraph

<p>错误码的参数应为表53所示的值之一。</p>

:::

:::{div}
:class: standard-paragraph

<p>如服务端收到的请求消息无法正确解析,服务端应在其响应消息中包括“无效消息”的错误码并将相应属性句柄设置为0x0000。</p>

:::

:::{div}
:class: standard-paragraph

<p>如服务端收到一个不支持的请求消息,服务端应在其响应消息中包括“消息不支持”错误码并将相应属性句柄设置为0x0000。不支持的请求消息可包括不支持该消息码的处理,或不支持请求中消息控制码的处理。</p>

:::

:::{div}
:class: standard-paragraph

<p>如服务端收到一个无效或不支持的命令消息,服务端应忽略该命令。</p>

:::

:::{div}
:class: standard-paragraph

<p>如服务端没有足够资源处理一个请求消息,服务端应在其响应消息中包括“资源不足”错误码并将相应属性句柄设置为0x0000。</p>

:::

:::{div}
:class: standard-paragraph

<p>如服务端在处理一个请求消息时出现错误,则服务端应在其响应消息中包括“未知错误”错误码并将相应属性句柄设置为0x0000。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端请求消息中涉及多个条目,而服务端仅支持访问单个条目,服务端应发送包含“条目数量超限”错误码的SSAP_ERROR_RSP消息。</p>

:::

:::{div}
:class: standard-paragraph

<p>如服务端需发送“无效消息”“消息不支持”“资源不足”或“条目数量超限”等错误码,应使用SSAP_ERROR_RSP消息。</p>

:::

:::{div}
:class: standard-paragraph

<p>产生“服务端未接收所有分包”错误码的情况见7.5.2.2.2。</p>

:::

:::{div}
:class: standard-paragraph

<p>产生“服务端不支持分包序号”错误码的情况见7.5.2.2.2。</p>

:::

:::{div}
:class: standard-paragraph

<p>产生“服务端不支持消息事务号”错误码的情况见7.5.2.2.3。</p>

:::

:::{div}
:class: standard-paragraph

<p>如SSAP_ERROR_RSP 消息中包含客户端不能解释的错误码,SSAP_ERROR_RSP 消息仍说明给定的请求由于未知原因不能执行。</p>

:::

:::{div}
:class: standard-paragraph

<p>另外,服务端发送SSAP_ERROR_RSP消息后不应中断与客户端的连接。</p>

:::
