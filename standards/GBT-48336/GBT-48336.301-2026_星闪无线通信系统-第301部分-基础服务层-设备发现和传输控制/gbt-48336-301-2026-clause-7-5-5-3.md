# 7.5.5.3 信息交互

(gbt-48336-301-2026-clause-7-5-5-3-1)=
## 7.5.5.3.1 SSAP\_EXCHANGE\_INFO\_REQ消息

:::{div}
:class: standard-paragraph

<p>SSAP_EXCHANGE_INFO_REQ 消息为初始信息交互请求消息,用于客户端向服务端发送信息交互的请求。本消息应作为客户端与服务端启动服务交互流程的第一个消息。</p>

:::

::::

:::{div}
:class: standard-paragraph

<p>SSAP_EXCHANGE_INFO_REQ 消息由消息码、消息控制码、客户端 MTU、版本和扩展消息控制码等参数组成(见表54)。消息码参数值设置为0x02。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息控制码参数值以位图方式表示:bit0表示 MTU,bit1表示SSAP协议版本号,bit2表示扩展消息控制码,bit3表示SSAP支持可靠模式,bit4表示 SSAP 分包能力,bit5表示 SSAP 协议多值处理能力,bit6~bit7为预留。如果对应比特置1,消息载荷才可能包含相应的参数。当消息控制码bit3置1时,表示客户端支持SSAP可靠模式。</p>

:::

:::{div}
:class: standard-paragraph

<p>客户端 MTU 参数值设置为客户端能接受的 MTU 值。该参数值应大于或等于该SSAP传输通道的缺省 MTU 值;未进行 MTU 协商时,SSAP传输通道的 MTU 应为该传输通道的缺省 MTU。MTU协商后,SSAP传输通道的 MTU 应为协商后的值。</p>

:::

:::{div}
:class: standard-paragraph

<p>版本参数值设置为SSAP协议版本号,第一字节为大版本号,第二字节为小版本号。本文件规定当前SSAP协议版本号为1.3,即大版本号为1,小版本号为3。当SSAP协议版本号不低于1.3时,消息控制码bit4和bit5有效。</p>

:::

:::{div}
:class: standard-paragraph

<p>当消息控制码bit4置1时,表示客户端支持SSAP分包能力,即SSAP消息可进行分包和重组。该比特位置0时表示不支持该能力,此时SSAP分包序号功能不应支持。</p>

:::

:::{div}
:class: standard-paragraph

<p>当消息控制码bit5置1时,表示客户端支持SSAP多值处理能力,即支持对一个SSAP消息(读取、写入、通知或指示等)包含的多个数据值或数据类型进行正确处理和解析。该比特位置0时表示不支持该能力。</p>

:::

:::{div}
:class: standard-paragraph

<p>扩展消息控制码参数为4 字节。当消息参数“消息控制码”字段中 bit2 扩展消息控制码置为1时,且消息参数扩展消息控制码字段中字节0的bit2置为1时,支持SSAP分包序号功能。当消息参数“消息控制码”字段中bit2扩展消息控制码置为1时,且消息参数扩展消息控制码字段中字节0的bit3置1时,支持SSAP消息事务号功能,字节1继续指示客户端支持的最大SSAP消息事务号数量;如果不支持该功能,字节1无意义。</p>

:::

(gbt-48336-301-2026-clause-7-5-5-3-2)=
## 7.5.5.3.2 SSAP\_EXCHANGE\_INFO\_RSP消息

:::{div}
:class: standard-paragraph

<p>SSAP_EXCHANGE_INFO_RSP消息为初始信息交互响应消息,用于服务端接收到客户端发送的SSAP_EXCHANGE_INFO_REQ 消息后,进行初始信息交互响应。</p>

::::

:::{div}
:class: standard-paragraph

<p>SSAP_EXCHANGE_INFO_RSP消息由消息码、消息控制码、服务端 MTU、版本和扩展消息控制码等参数组成(见表55)。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息码参数值设置为0x03。消息控制码参数值以位图方式表示:bit0表示 MTU,bit1表示SSAP版本号,bit2表示扩展消息控制码,bit3 表示 SSAP 支持可靠模式传输通道,bit4 表示 SSAP 分包能力,bit5表示SSAP协议多值处理能力,bit6~bit7为预留。只有在对应位图值为1时,消息载荷才可能包含相应的参数。当消息控制码bit3为1时,表示服务端支持SSAP可靠模式,即SSAP消息可基于可靠模式传输通道进行交互。</p>

:::

:::{div}
:class: standard-paragraph

<p>服务端 MTU 参数值设置为服务端能接受的 MTU 值;服务端 MTU 值应大于或等于SSAP传输通道缺省 MTU 值,SSAP传输通道缺省 MTU 由数据传输与适配功能单元决定。未进行 MTU 协商时,SSAP传输通道 MTU 应为SSAP传输通道的缺省 MTU。通过SSAP_EXCHANGE_INFO_REQ消息和SSAP_EXCHANGE_INFO_RSP 消息进行协商后,SSAP 传输通道 MTU 应设置为客户端MTU 与服务端 MTU 两者的较小值。</p>

:::

:::{div}
:class: standard-paragraph

<p>客户端和服务端发出的所有消息数据长度应小于或等于该 SSAP 传输通道的 MTU。如果协商MTU 过程发生错误,如客户端 MTU 或服务端 MTU 参数设置不合法,则该SSAP传输通道 MTU 不发生变化。</p>

:::

:::{div}
:class: standard-paragraph

<p>如某设备同时是一个客户端和服务端,下列规则应适用于其交互流程:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 该设备的SSAP_EXCHANGE_INFO_REQ 消息和SSAP_EXCHANGE_INFO_RSP消息中设置的 MTU 值应相同;</p>
</li>
<li><p>——— MTU 值可进行单向或双向交互,而且 MTU 值应在每个方向的交互中均为相同的值;</p>
</li>
<li><p>——— 如该设备在SSAP_EXCHANGE_INFO_REQ 消息发出后但在SSAP_EXCHANGE_INFO_RSP消息收到之前收到某个SSAP请求消息,那么相关SSAP响应消息应使用缺省 MTU 值;</p>
</li>
<li><p>——— 当SSAP_ EXCHANGE_INFO _ REQ 消息发出后,该发起设备只能在收到 SSAP_EXCHANGE_INFO_RSP消息后再发出SSAP通知或指示消息,以避免出现 MTU 值未知的情况。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>版本参数值设置为SSAP协议版本号,第一字节为大版本号,第二字节为小版本号。本文件规定当前SSAP协议版本号为1.3,即大版本号为1,小版本号为3。</p>

:::

:::{div}
:class: standard-paragraph

<p>当SSAP协议版本号不低于1.3时,消息控制码bit4和bit5有效。</p>

:::

:::{div}
:class: standard-paragraph

<p>当消息控制码bit4置1时,表示服务端支持SSAP分包能力,即SSAP消息可进行分包和重组。该比特位置0时表示不支持该能力,此时SSAP分包序号功能不应支持。</p>

:::

:::{div}
:class: standard-paragraph

<p>当消息控制码bit5置1时,表示服务端支持SSAP多值处理能力,即支持对一个SSAP消息(读取、写入、通知或指示等)包含的多个数据值或数据类型进行正确处理和解析。该比特位置0时表示不支持该能力。</p>

:::

:::{div}
:class: standard-paragraph

<p>扩展消息控制码参数为4字节。当消息参数“消息控制码”字段中 bit2扩展消息控制码设置为1,并且消息参数扩展消息控制码字段中字节0的bit2设置为1时,支持SSAP分包序号功能。当消息参数“消息控制码”字段中bit2扩展消息控制码设置为1,并且消息参数扩展消息控制码字段中字节0的bit3设置为1时,支持SSAP消息事务号功能,字节1继续指示服务端支持的最大SSAP消息事务号数量;如果不支持该功能,字节1无意义。</p>

:::
