# 7.4 服务结构

(gbt-48336-301-2026-clause-7-4-1)=
## 7.4.1 概述

:::{div}
:class: standard-paragraph

<p>服务结构定义了服务之间的引用与逻辑关系。由服务声明、服务引用、属性、方法和事件等服务结构成员组成,客户端使用服务发现流程获取服务端的服务结构,解析服务结构以理解所提供的服务功能,并根据自身需求进行服务访问。</p>

:::

(gbt-48336-301-2026-clause-7-4-2)=
## 7.4.2 服务组成

(gbt-48336-301-2026-clause-7-4-2-1)=
### 7.4.2.1 服务

:::{div}
:class: standard-paragraph

<p>一个应用服务框架可由一个或多个服务组成,共同提供完整的应用功能。例如一个家庭室内监测功能可同时包括湿度检测服务和温度检测服务。</p>

:::

:::{div}
:class: standard-paragraph

<p>服务按是否能独立公开,分为首要服务和次要服务,相互关系见图8。</p>

:::

:::{div}
:class: standard-paragraph

<p>服务按定义方式,分为标准服务和自定义服务两类。</p>

:::

:::{div}
:class: standard-paragraph

<p>服务由若干个服务结构成员构成,包括服务声明、服务引用、属性、方法和事件。一个服务结构应包含服务声明,可包含服务引用,用于引用其他服务;是否包含属性、方法或事件,由基础服务层或基础应用层相关标准规定。</p>

:::

:::{div}
:class: standard-paragraph

<p>同一服务可支持多个实例。</p>

:::

(gbt-48336-301-2026-clause-7-4-2-2)=
### 7.4.2.2 服务声明

:::{div}
:class: standard-paragraph

<p>服务声明的句柄也是服务的起始句柄。服务声明指示了服务类型和服务标识。</p>

:::

(gbt-48336-301-2026-clause-7-4-2-3)=
### 7.4.2.3 服务引用

:::{div}
:class: standard-paragraph

<p>服务引用规定了服务引用一个或几个其他服务以及服务的类型和句柄范围。被引用的服务可为首要服务或次要服务,首要服务和次要服务均可引用其他服务。被引用的服务可继续引用其他服务,但不可引用原始服务。一个服务引用其他服务的数量没有限制。同一个服务可同时被其他多个服务引用。</p>

:::

(gbt-48336-301-2026-clause-7-4-2-4)=
### 7.4.2.4 属性

:::{div}
:class: standard-paragraph

<p>属性用于描述服务功能、状态以及相关的配置信息。使用 UUID 标识属性,并通过操作指示字段指示数据值的访问方式。</p>

:::

:::{div}
:class: standard-paragraph

<p>属性可有描述符,应为可选字段,对所关联的数据值进行解释说明、格式解析或操作方式控制。</p>

:::

:::{div}
:class: standard-paragraph

<p>属性值和描述符值均有相应的访问权限,例如认证、加密、授权等,由服务端定义,客户端应满足对应访问权限条件后才可访问属性值或描述符。服务端对客户端访问权限的验证由实现决定,例如服务端可通过基础服务层的安全管理功能单元或向接入层查询客户端的认证、加密、授权的结果。</p>

:::

(gbt-48336-301-2026-clause-7-4-2-5)=
### 7.4.2.5 方法

:::{div}
:class: standard-paragraph

<p>方法是服务端提供给客户端的访问接口,使用 UUID 标识方法。客户端通过访问服务端的方法完成特定功能。</p>

:::

:::{div}
:class: standard-paragraph

<p>每种方规定自己的输入参数、返回结果含义和格式,可包含可选的输入参数。客户端请求方法时应包含必要的输入参数。方法执行完成后服务端应返回执行结果。</p>

:::

:::{div}
:class: standard-paragraph

<p>方法通常可用于简化多步骤属性访问流程。</p>

:::

:::{div}
:class: standard-paragraph

<p>方法执行可改变服务中的某些属性值。</p>

:::

(gbt-48336-301-2026-clause-7-4-2-6)=
### 7.4.2.6 事件

:::{div}
:class: standard-paragraph

<p>事件是服务端在特定情况下触发的、并主动向客户端发送的信息,例如与属性值无关的公共事件信息(告警、故障等)。应用使用 UUID 指示事件,客户端通过获取事件 UUID 以识别对应事件所关联的数据含义和数据格式。</p>

:::

:::{div}
:class: standard-paragraph

<p>事件信息包含事件类型和关联数据,由上层协议固定:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 事件类型可包括设备异常、故障和告警等;</p>
</li>
<li><p>——— 关联数据具有与对应事件相关的具体格式。</p>
</li></ul>

:::

(gbt-48336-301-2026-clause-7-4-3-2)=
### 7.4.3.2 句柄

:::{div}
:class: standard-paragraph

<p>句柄由服务端生成,指示某条目在服务端的位置。句柄长度应为2字节,其中0x0000为预留句柄,0x0001~0x000F为服务管理功能单元内部可使用的句柄范围,0x0010~0xFFFF 为服务、属性、方法或事件等可使用的句柄范围。句柄的分配可不连续,但应为升序。客户端可通过句柄对条目内容进行访问。</p>

:::

(gbt-48336-301-2026-clause-7-4-3-4)=
### 7.4.3.4 标识

:::{div}
:class: standard-paragraph

<p>标识表示该条目描述的具体内容,由 UUID 表示。标准服务或标准服务成员使用由相关机构统一分配的16比特 UUID,具有全局唯一性,其具体形式见附录 A。自定义服务或自定义服务成员使用128比特 UUID。通过标识,客户端可识别条目所承载的是某一个服务、属性、方法、事件或服务引用。</p>

:::

### 7.4.3.5 数据

(gbt-48336-301-2026-clause-7-4-3-5-1)=
#### 7.4.3.5.1 概述

:::{div}
:class: standard-paragraph

<p>数据字段是标识字段所关联的数据信息,包含操作指示、数据值和描述符等字段。其中操作指示字段规定了数据值和描述符值的访问方式。数据值字段可包含0个或若干个描述符,由数据值访问方式和上层协议确定。</p>

:::

(gbt-48336-301-2026-clause-7-4-3-5-2)=
#### 7.4.3.5.2 操作指示

:::{div}
:class: standard-paragraph

<p>操作指示长度为4字节,其中低8比特指示数据值访问方式,高24比特指示描述符值访问方式(见表34)。</p>

:::

:::{div}
:class: standard-paragraph

<p>描述符默认可读,其写入权限由协议和实现定义。写入权限可固定或可变,当包含访问方式可变的描述符时,应在高24比特的描述符值访问方式中的对应比特设置相应的值。</p>

(gbt-48336-301-2026-clause-7-4-3-5-3)=
#### 7.4.3.5.3 数据值

:::{div}
:class: standard-paragraph

<p>数据值的具体含义由标识定义。数据值是一个字节组,长度可为0,可表示为常规的整型数值、布尔值或字符串等,也可借助描述符描述浮点数、科学计数法所表示的数值或自定义数据结构。</p>

:::

:::{div}
:class: standard-paragraph

<p>当客户端使用SSAP对数据值进行访问时,数据值的长度可由包含该数据值的报文隐式指示。如同时对多个数据值进行读取,则每个数据值的长度需在读取响应消息中显式指示。</p>

:::

(gbt-48336-301-2026-clause-7-4-3-5-4)=
#### 7.4.3.5.4 描述符

:::{div}
:class: standard-paragraph

<p>描述符用于表示数据值的关联信息,例如数据值的补充描述、数据值的格式说明、数据值的访问控制、或由上层协议定义的特定功能。</p>

:::

:::{div}
:class: standard-paragraph

<p>描述符字段可由若干个描述符组成。一个描述符由描述符类型和描述符值组成。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 描述符类型表示该描述符的功能,为1字节,取值范围为0x00~0xFF。属性、方法、事件的描述符类型定义空间相互独立。</p>
</li>
<li><p>——— 描述符值的含义和格式由描述符类型定义。具体表达格式在各个描述符定义中给出。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>服务管理功能单元定义了一系列标准描述符供上层协议使用,同时允许上层协议定义额外的特定描述符。</p>

:::

:::{div}
:class: standard-paragraph

<p>当数据字段包含多个描述符时,描述符的顺序是不固定的,客户端不应对多个描述符的顺序进行任何假定。</p>

:::

:::{div}
:class: standard-paragraph

<p>当客户端不能识别描述符类型时,可忽略,且不应去访问相应描述符值。描述符值默认是可读的;</p>

:::

:::{div}
:class: standard-paragraph

<p>描述符值的写入权限,由访问控制字段控制。</p>

:::

:::{div}
:class: standard-paragraph

<p>属性的描述符也称为属性描述符,属性描述符类型见表35。</p>

(gbt-48336-301-2026-clause-7-4-3-5-5)=
#### 7.4.3.5.5 权限

:::{div}
:class: standard-paragraph

<p>权限是服务端对客户端访问服务结构成员时所提出的安全要求,只有满足安全要求的客户端才能对服务结构成员进行访问。权限由服务端设置,对客户端不可见。</p>

:::

:::{div}
:class: standard-paragraph

<p>权限的种类可为以下几种。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 认证要求:需认证或无需认证。当服务端要求认证时,客户端如未与服务端进行认证,则客户端发起的SSAP请求会执行失败,在对应的响应中返回“客户端未认证”错误码。</p>
</li>
<li><p>——— 加密要求:需加密或无需加密。当服务端要求加密时,客户端与服务端的逻辑信道未经加密时,则客户端发起的SSAP请求会执行失败,在对应的响应中返回“承载未加密”错误码。</p>
</li>
<li><p>——— 授权要求:需授权或无需授权。当服务端要求授权时,客户端在访问数据值或描述符值之前,需先获得服务端的授权;否则客户端发起的SSAP请求会执行失败,在对应的响应中返回“客户端未授权”错误码。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>权限可与访问控制中的读取和写入控制一起使用,读取权限和写入权限要求可不同,例如写入时要求认证、读取时要求加密等。</p>

:::

:::{div}
:class: standard-paragraph

<p>服务端可独立设置数据值权限和描述符值权限。</p>

:::

:::{div}
:class: standard-paragraph

<p>服务端可通过基础服务层的安全管理功能单元或接入层获取客户端是否认证或加密,具体由实现决定。</p>

:::

## 7.4.6 服务结构缓存

(gbt-48336-301-2026-clause-7-4-6-1)=
### 7.4.6.1 概述

:::{div}
:class: standard-paragraph

<p>服务结构缓存将服务端的服务结构信息以服务结构副本形式保存在客户端,是一种可选方案,可用于避免或减少客户端对同一服务端的同一服务进行多次服务访问,也可用于避免或减少当客户端连接多个提供相同服务的不同服务端时进行多次服务访问。</p>

:::

:::{div}
:class: standard-paragraph

<p>服务结构缓存对应一种服务结构,而不绑定一个服务端。多个服务端拥有相同的服务结构时,同一服务结构缓存对这些服务端都有效。</p>

:::

:::{div}
:class: standard-paragraph

<p>当服务端的服务结构发生变更时,不应继续使用其服务结构缓存。当服务结构成员对应条目中的句柄、类别、标识、操作指示或描述符类型等信息发生变更时,即认为服务结构发生变更。</p>

:::

:::{div}
:class: standard-paragraph

<p>客户端在使用服务结构缓存时,需保证使用的服务结构缓存对服务端是有效的。服务结构缓存的有效性可通过比对服务结构散列值和接收服务结构变更事件验证。当服务结构缓存失效或不能保证有效性时,客户端应对服务端进行服务发现过程,获取最新的服务结构信息。</p>

:::

:class: standard-paragraph

#### 7.4.6.2.3 计算

:::{div}
:class: standard-paragraph

<p>服务结构散列值根据以下方式计算。</p>

:::

:::{div}
:class: standard-paragraph

<p>服务结构散列值为$\mathrm{SHA}-256(M)$计算结果截取低128比特。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— SHA-256为安全散列函数。</p>
</li>
<li><p>——— $M$为可变长度的数据$,M$的组成范围包括一个服务结构的所有条目的句柄、类别、标识、操作指示和描述符类型列表。这些成员均可表示为字节组。其中描述符类型列表是条目中所有描述符的类型值按照升序排列的字节组。$M$是按照条目句柄升序将所有字节组拼接后的结果。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>所有字节组都是小端字节序。</p>

:::

### 7.4.6.3 服务变更事件

(gbt-48336-301-2026-clause-7-4-6-3-1)=
#### 7.4.6.3.1 定义

:::{div}
:class: standard-paragraph

<p>服务变更事件用于在服务结构发生变化时通知与服务端连接的所有客户端,其句柄固定为0x000E。</p>

:::

:::{div}
:class: standard-paragraph

<p>服务结构变化的原因可为服务的添加、更新或删除等。</p>

:::

:::{div}
:class: standard-paragraph

<p>客户端收到服务变更事件后,如果本地保存了与该服务关联的服务结构缓存,应将其标记为失效,并重新发起服务发现过程。</p>

:::

:::{div}
:class: standard-paragraph

<p>7.4.6.3.2 <strong>表示</strong></p>

:::

:::{div}
:class: standard-paragraph

<p>服务变更事件的表示见表48。</p>

:::

:::{div}
:class: standard-paragraph

<p>服务变更事件使用SSAP的通知消息,包含变更服务对应条目的句柄范围。</p>

:::

(gbt-48336-301-2026-clause-7-4-6-4)=
### 7.4.6.4 服务结构缓存验证

:::{div}
:class: standard-paragraph

<p>客户端可支持两种方式以获取服务结构散列值,可根据实际情况使用任意一种:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 通过接收服务端广播以获取服务结构散列值;</p>
</li>
<li><p>——— 通过SSAP读取服务端的服务结构散列值。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>客户端获取服务结构散列值后,应与对应服务结构缓存中的服务结构散列值进行对比,验证服务结构缓存的有效性。</p>

:::
