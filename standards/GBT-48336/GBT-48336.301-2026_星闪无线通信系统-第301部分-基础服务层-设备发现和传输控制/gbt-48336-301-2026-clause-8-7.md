(gbt-48336-301-2026-clause-8-7-2)=
## 8.7.2 传输定时器

(gbt-48336-301-2026-clause-8-7-2-1)=
### 8.7.2.1 重传定时器

:::{div}
:class: standard-paragraph

<p>重传定时器用于发送方在传输过程中对长时间未收到应答的 PDU 进行重传,用于防止应答帧丢失导致的异常:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 开启条件:PDU 发送之后,如果重传定时器不在运行则启动重传定时器;</p>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 停止条件:收到应答之后,如果$ExpectedAckSeq==NextTxSeq$,则停止重传定时器;</p>
</li>
<li><p>——— 重启条件:收到应答之后,如果$ExpectedAckSeq\lt \mathrm{ReqSeq}\lt NextTxSeq$,则重启重传定时器;</p>
</li>
<li><p>——— 超时操作:将$ReTxSeq$ 变量置为$ExpectedAckSeq$ 变量值。</p>
</li></ul>

:::

(gbt-48336-301-2026-clause-8-7-2-2)=
### 8.7.2.2 重排序定时器

:::{div}
:class: standard-paragraph

<p>重排序定时器用于接收方对于乱序到达的数据进行重排序。当定时器超时时,可认为对应的 PDU已丢失。重排序定时器仅用于可靠模式或流模式传输通道。每个传输通道在每一端仅维护一个重排序定时器:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 开启条件:PDU 插入接收队列后,如果重排序定时器没有运行,且$ExpectedTxSeq\lt MaxEx-$$pectedTxSeq$,则启动重排序定时器,并将重排序Seq变量置为$ExpectedTxSeq$变量值;</p>
</li>
<li><p>——— 停止条件:PDU 插入接收队列后,该PDU 的 TxSeq字段值等于重排序Seq变量值,则停止重排序定时器;</p>
</li>
<li><p>——— 重启条件:PDU 插入接收队列后,该 PDU 的 TxSeq 字段值等于重排序 Seq 变量值,且$ExpectedTxSeq\lt MaxExpectedTxSeq$,则重启重排序定时器,将重排序 Seq变量置为$Ex-$$pectedTxSeq$变量值;或重排序定时器超时,则会进行超时操作并重启重排序定时器;</p>
</li>
<li><p>——— 超时操作:发送异常应答,包含 ReqSeq字段,设置为重排序 Seq变量值,并重启重排序定时器。</p>
</li></ul>

:::

(gbt-48336-301-2026-clause-8-7-2-3)=
### 8.7.2.3 应答定时器

:::{div}
:class: standard-paragraph

<p>应答定时器用于接收方在没有数据发送时触发应答帧的发送,用于防止设备长时间没有数据发送时无法对对方发送的PDU 进行应答。应答定时器仅用于可靠模式传输通道:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 开启条件:通道建立时开启;</p>
</li>
<li><p>——— 停止条件:无;</p>
</li>
<li><p>——— 重启条件:发送一次双向帧或应答帧;</p>
</li>
<li><p>——— 超时操作:发送应答帧。</p>
</li></ul>

:::

(gbt-48336-301-2026-clause-8-7-2-4)=
### 8.7.2.4 丢弃定时器

:::{div}
:class: standard-paragraph

<p>丢弃定时器用于发送方对超时数据进行丢弃,用于防止超时数据的发送占用空口资源。丢弃定时器仅用于流模式传输通道:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 开启条件:每个PDU 进入发送队列之后,会针对该PDU 启动一个丢弃定时器;</p>
</li>
<li><p>——— 停止条件:无;</p>
</li>
<li><p>——— 超时操作:从发送队列中丢弃该定时器对应的PDU。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>每个PDU 都会有一个丢弃定时器,因此一个传输通道上可能存在多个定时器。</p>

:::

## 8.7.3 数据分片与合片

(gbt-48336-301-2026-clause-8-7-3-1)=
### 8.7.3.1 数据分片

:::{div}
:class: standard-paragraph

<p>数据分片是指将一个 SDU 切分成多个 PDU 的操作,示意图见图27。数据分片属于发送端功能,且仅可用于流模式和可靠模式传输通道。当发送端对SDU 进行数据分片操作时,发送端将SDU 切分成多个PDU,并将每个PDU 按照8.5.3定义的单向分片帧或双向分片帧的格式进行封装并发送。其中,单向分片帧或双向分片帧的选择需要根据传输通道的传输模式确定。</p>

:::

(gbt-48336-301-2026-clause-8-7-3-2)=
### 8.7.3.2 数据合片

:::{div}
:class: standard-paragraph

<p>数据合片是指将接收到的多个SDU 分片重组成一个SDU 的操作。数据合片属于接收端功能,仅可用于流模式和可靠模式传输通道。</p>

:::

:::{div}
:class: standard-paragraph

<p>接收端应根据接收到的PDU 的帧类型指示字段判断是否属于单向分片帧或双向分片帧。接收端仅支持对单向分片帧或双向分片帧执行数据合片。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于使用单向分片帧或双向分片帧的PDU,接收端根据PDU 的SAR 字段判断PDU 的分片状态。</p>

:::

:::{div}
:class: standard-paragraph

<p>如果PDU 包含SDU 的某一个分片,接收端应执行合片流程。</p>

:::

:::{div}
:class: standard-paragraph

<p>接收端从多个 TxSeq连续的PDU 中解析出的第一个分片、中间分片(如果存在)以及最后一个分片并进行组合,组成SDU 的大小应符合首个 PDU(该 PDU 的SAR 字段为0b10)中SDU 长度指示的长度。如果不符合,则认为此SDU 和组成此SDU 的所有分片PDU 不可靠。</p>

:::

## 8.7.4 数据聚合和分拆

### 8.7.4.1 数据聚合

(gbt-48336-301-2026-clause-8-7-4-2)=
### 8.7.4.2 数据分拆

:::{div}
:class: standard-paragraph

<p>数据分拆是指从接收到的一个 PDU 中提取出多个SDU 的操作。数据分拆属于接收端功能,仅可用于流模式和可靠模式传输通道。</p>

:::

:::{div}
:class: standard-paragraph

<p>接收端应根据接收到的PDU 的帧类型指示字段判断是否属于单向聚合帧或双向聚合帧。接收端仅支持对单向聚合帧或双向聚合帧执行数据分拆。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于使用单向聚合帧或双向聚合帧的 PDU,接收端按照8.5.3 定义的帧格式从第一个 SDU 开始,按照每个SDU 长度指示依次分拆出所有SDU。如果从 PDU 的长度指示字段推演出的SDU 总长度与拆分出的多个SDU 总长度不符,则认为此PDU 和所有拆分出的SDU 不可靠。</p>

:::

(gbt-48336-301-2026-clause-8-7-5)=
## 8.7.5 异常处理

(gbt-48336-301-2026-clause-8-7-5-1)=
### 8.7.5.1 逻辑信道异常释放

:::{div}
:class: standard-paragraph

<p>当逻辑信道异常释放时,数据传输与适配功能单元应触发本异常处理。</p>

:::

:::{div}
:class: standard-paragraph

<p>应依次处理映射到该逻辑信道上的所有传输通道。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 如果一个传输通道除了该异常释放的逻辑信道外没有映射到其他的逻辑信道,数据传输与适配功能单元应将该传输通道释放。</p>
</li>
<li><p>——— 如果一个传输通道除了异常释放的逻辑信道外还映射到其他的逻辑信道,数据传输与适配功能单元应将该传输通道中的数据映射至其他逻辑信道进行传输,并重配置传输通道以删除与该异常释放的逻辑信道的映射关系。</p>
</li></ul>

:::

(gbt-48336-301-2026-clause-8-7-5-2)=
### 8.7.5.2 传输达到最大次数

:::{div}
:class: standard-paragraph

<p>该异常处理仅适用于可靠模式传输通道。当传输通道内的 PDU 重传次数达到最大次数时,数据传输与适配功能单元应触发本异常处理。</p>

:::

:::{div}
:class: standard-paragraph

<p>本异常处理有两种处理方式,即释放传输通道或上报数据丢失。处理方式的选择应根据该传输通道创建时配置的最大次数异常处理变量进行确定,默认为释放传输通道。</p>

:::

:::{div}
:class: standard-paragraph

<p>当配置为释放传输通道时,数据传输与适配功能单元应触发释放传输通道流程。</p>

:::

:::{div}
:class: standard-paragraph

<p>当配置为上报数据丢失时,数据传输与适配功能单元应上报丢失的数据 TxSeq。本异常处理完成后,发送端将该PDU 视为收到正确应答,并进行后续处理流程。本异常处理完成后,接收端将该 PDU视为已正确接收,并进行后续处理流程。尽管该 PDU 被视为已正确接收,但是该 PDU 实际未被接收,无法被递交至上层。</p>

:::
