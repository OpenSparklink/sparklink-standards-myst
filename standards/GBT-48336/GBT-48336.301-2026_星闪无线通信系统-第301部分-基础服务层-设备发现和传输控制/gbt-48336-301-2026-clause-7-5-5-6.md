# 7.5.5.6 写入操作

(gbt-48336-301-2026-clause-7-5-5-6-1)=
## 7.5.5.6.1 SSAP\_WRITE\_CMD消息

:::{div}
:class: standard-paragraph

<p>SSAP_WRITE_CMD 消息是无响应写入消息,用于客户端向服务端发送无需响应的写入消息。支持一次性写入单个值或多个值,支持分包发送。</p>

:::

::::{div}
:class: table-scroll

(gbt-48336-301-2026-table-77)=
:::{div}
:class: standard-table-caption

<p>表 77　SSAP_WRITE_CMD消息格式</p>

:::

<tr>
<th>消息参数</th>
<th>长度/字节</th>
<th>消息参数描述</th>
</tr>
<tr>
<td>消息码(0x0C)</td>
<td>1</td>
<td>消息码</td>
</tr>
<tr>
<td>消息控制码</td>
<td>1</td>
<td>bit1~ bit0:指 示 写 入 值 的 状 态,起 始 包<br/>(0b00)/接续包(0b01)/结束包(0b10)/单个完<br/>整数据包(0b11)bit2:$0=$单个值$;1=$多个值<br/>bit4~bit3:写入操作指示,立即写入(0b00);值<br/>未完整传输,需继续传输后续值(0b01);取消<br/>写入(0b10);预留(Others)<br/>bit7~bit5:预留</td>

::::

:::{div}
:class: standard-paragraph

<p>SSAP_WRITE_CMD 消息由消息码、消息控制码和写入参数列表等参数组成(见表77)。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息码参数值设置为0x0C。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息控制码参数值以位图方式表示,bit7~bit5为预留值;其中,对于消息控制码bit4~bit3的说明如下。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 立即写入(0b00):用于单个完整数据包或分包时的结束包中。</p>
</li>
<li><p>——— 值未完整传输,需继续传输后续值(0b01):用于分包时的起始包(0b00)和接续包(0b01)中,服务端应缓存接收到的分包报文。</p>
</li>
<li><p>——— 取消写入(0b10):用于在分包情况时,客户端在发送结束包之前,可发送包含“取消写入”操作指示的分包报文。服务端收到后应清空缓存的所有相关分包。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>写入参数列表的结构根据客户端写入值的设置而变化。</p>

:::

:::{div}
:class: standard-paragraph

<p>本消息中数据类型定义可参考表72和表73。</p>

:::

:::{div}
:class: standard-paragraph

<p>写入参数列表中的句柄应为有效句柄。其数据值在成功写入后应成为该属性的新值。</p>

:::

:::{div}
:class: standard-paragraph

<p>元组数为1个字节,指示针对当前句柄待写入的三元组个数。</p>

:::

:::{div}
:class: standard-paragraph

<p>如属性值为固定长度,且写入属性值的长度值小于或等于属性值的长度,则属性值中包括写入属性值长度的部分应被写入新的属性值,而剩下的部分应不被改动。</p>

:::

:::{div}
:class: standard-paragraph

<p>如属性值为固定长度,且写入属性值的长度值大于属性值的固定长度,则服务端应忽略该写入请求。</p>

:::

:::{div}
:class: standard-paragraph

<p>如属性值为可变长度,则该写入属性值应根据实际情况缩短或增加以匹配属性值的长度要求。</p>

:::

:::{div}
:class: standard-paragraph

<p>如属性值为可变长度,且写入属性值的长度值大于属性值可能的最大的长度,则服务端应忽略该写入请求。</p>

:::

:::{div}
:class: standard-paragraph

<p>当SSAP_WRITE_CMD 消息收到后,服务端不应产生任何响应消息。</p>

:::

## 7.5.5.6.2 SSAP\_WRITE\_REQ消息

## 7.5.5.6.3 SSAP\_WRITE\_RSP消息

:::{div}
:class: standard-paragraph

<p>SSAP_WRITE_RSP消息为写入响应消息,用于服务端收到SSAP_WRITE_REQ 消息后,向客户端发送写入响应。支持一次性响应写入单个值或多个值,支持分包发送。</p>

:::

::::{div}
:class: table-scroll

(gbt-48336-301-2026-table-79)=
:::{div}
:class: standard-table-caption

<p>表 79　SSAP_WRITE_RSP消息格式</p>

:::

<table class="standard-table ">
<tr>
<th>消息参数</th>
<th>长度/字节</th>
<th>消息参数描述</th>
</tr>
<tr>
<td>消息码(0x0E)</td>
<td>1</td>
<td>消息码</td>
</tr>
<tr>
<td>消息控制码</td>
<td>1</td>
<td>bit1~bit0:起始包(0b00)/接续包(0b01)/结束<br/>包(0b10)/单个数据包(0b11)<br/>bit3~bit2:指示服务端写入结果;写入成功<br/>(0b00)/写入失败(0b01)/取消写入(0b10)<br/>bit7~bit4:预留</td>
</tr>
<tr>
<td>错误数量</td>
<td>1</td>
<td>错误数量(有错误的情况下出现)</td>
</tr>
<tr>
<td>错误数据列表</td>
<td>可变</td>
<td>返回的错误信息,数据列表格式:{{句柄1,错<br/>误码1},{句柄2,错误码2}...};其中,句柄长度<br/>2字节;错误码长度1字节(错误数据列表在有<br/>错误的情况下出现)</td>
</tr>
<tr>
<td>值列表</td>
<td>可变</td>
<td>按照表78写入参数列表中的每个写入成功的<br/>值进行原值返回</td>
</tr>
</table>

::::

:::{div}
:class: standard-paragraph

<p>SSAP_WRITE_RSP消息由消息码、消息控制码、错误数量、错误数据列表和值列表等参数组成(见表79)。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息码参数值设置为0x0E。</p>

:::

:::{div}
:class: standard-paragraph

<p>消息控制码参数值以位图方式表示,其中bit7~bit4为预留值;其中,消息控制码bit3~bit2关于服务端写入结果指示信息的描述如下:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 写入成功(0b00):包含单值写入成功、多值全部写入成功等情况;</p>
</li>
<li><p>——— 写入失败(0b01):包含单值写入失败、多值部分写入失败、多值全部写入失败等情况;</p>
</li>
<li><p>——— 取消写入(0b10):指示服务端已将包含“取消写入”指示的 SSAP_WRITE_REQ 消息相关的所有分包清空。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>错误数量参数值应设置为读取错误的总数量,且仅在至少有一个错误的情况下出现。</p>

:::

:::{div}
:class: standard-paragraph

<p>错误数据列表参数值设置为返回的读取错误信息,包括错误所对应的句柄和错误码,具体格式为{{句柄1,错误码1},{句柄2,错误码2}...},且仅在至少有一个错误的情况下出现。具体错误码见表53。</p>

:::

:::{div}
:class: standard-paragraph

<p>值列表包含在表78写入参数列表内容中所有写入成功的值的原值返回信息,即只有成功写入的值才应原值返回并放入值列表;未成功写入的值,应通过错误数据列表按相应要求返回。</p>

:::

:::{div}
:class: standard-paragraph

<p>写入参数列表中的句柄应为有效句柄,其数据值在成功写入后应成为该属性的新属性值,且服务端应发送相应的SSAP_WRITE_RSP消息。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端请求写入消息中含需原值返回校验的要求,服务端在成功写入属性值后应发送包含该属性值的SSAP_WRITE_RSP消息并由客户端校验。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端请求写入的句柄在服务端不存在,服务端应发送包含 “无效句柄”错误码的 SSAP_WRITE_RSP 消息,并将错误句柄值设置为对应的请求句柄值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如SSAP_WRITE_REQ 消息未能成功写入因不符合类别要求的单个或多个数据值,服务端应发送包含“数据类型错误”错误码的SSAP_WRITE_RSP消息,并将错误句柄值设置为对应的请求句柄值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如属性值为固定长度,且写入属性值的长度值小于或等于属性值的长度,则属性值中从最低位开始,包括写入属性值长度的部分应被写入新的属性值,而剩下的部分应不被改动。</p>

:::

:::{div}
:class: standard-paragraph

<p>如属性值为固定长度,且写入属性值的长度值大于属性值的长度,则服务端应忽略该写入请求,并发送带“数据值长度错误”错误码的 SSAP_WRITE_RSP 消息,并将错误句柄值设置为对应的请求句柄值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如属性值为可变长度,则该写入属性值应根据实际情况缩短或增加以匹配属性值的长度要求。</p>

:::

:::{div}
:class: standard-paragraph

<p>如属性值为可变长度,且写入属性值的长度值大于属性值可能的最大长度,则服务端应忽略该写入请求,并发送带“数据值长度错误”错误码的SSAP_WRITE_RSP消息,并将错误句柄值设置为对应的请求句柄值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如写入的属性值超出了该属性值所允许的取值范围,服务端应忽略该写入请求,并发送包含“值超出范围”错误码的SSAP_WRITE_RSP消息,并将错误句柄值设置为对应的请求句柄值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端没有提供足够的授权去写入所请求的属性值,服务端应发送包含“客户端未授权”错误码的SSAP_WRITE_RSP消息响应,并将错误句柄值设置为对应的请求句柄值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端没有提供足够的安全认证去写入所请求的属性值,服务端应发送包含“客户端未认证”错误码的SSAP_WRITE_RSP消息,并将错误句柄值设置为对应的请求句柄值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端没有调整加密配置,但写入的属性值需加密,服务端应发送包含“承载未加密”错误码的SSAP_WRITE_RSP消息,并将错误句柄值设置为对应的请求句柄值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端所请求的数据值由于访问控制原因不能被写入,服务端应发送包含“禁止写入”错误码的SSAP_WRITE_RSP消息,并将错误句柄值设置为对应的请求句柄值。</p>

:::

:::{div}
:class: standard-paragraph

<p>如服务端的有响应写入的响应超过 MTU,需分包发送而服务端不支持分包发送时,服务端应发送包含“服务端不支持分包”错误码的SSAP_WRITE_RSP消息。</p>

:::

:::{div}
:class: standard-paragraph

<p>如客户端所请求的属性值由于应用错误原因不能被写入,服务端应发送由上层应用定义的应用错误码的SSAP_WRITE_RSP消息,并将错误句柄值设置为对应的请求句柄值。</p>

:::
