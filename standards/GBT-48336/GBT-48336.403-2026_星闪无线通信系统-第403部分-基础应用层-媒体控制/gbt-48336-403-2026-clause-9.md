# 9 面向合作设备集合的音量同步

:::{div}
:class: standard-paragraph

<p>合作设备集合成员应保持音量同步。</p>

:::

:::{div}
:class: standard-paragraph

<p>集合使用者为音量控制端，集合成员为音量输出端时，集合使用者应通过音量控制请求控制合作设备集合内所有其他成员的音量或静音状态进行同步的变更。</p>

:::

:::{div}
:class: standard-paragraph

<p>集合使用者触发的音量或静音状态同步变更行为源自：</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a） 集合使用者主动调整集合成员的音量或静音状态；</p>
</li>
<li><p>b） 任一集合成员音量或静音状态发生变化，应向集合使用者发送音量同步事件。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>对于上述两种情形，集合使用者应向所有其他集合成员发送音量控制请求并设置相同的生效时间。</p>

:::

:::{div}
:class: standard-paragraph

<p>其中，对于情形 b）：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 若集合成员发送音量变化的音量同步事件，集合使用者应向所有其他集合成员发送主音量设置的音量控制请求；</p>
</li>
<li><p>—— 若集合成员发送静音状态变化的音量同步事件，集合使用者应向其他所有集合成员发送静音或取消静音的音量控制请求。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>生效时间的设置宜考虑保留适当余量，余量宜大于等于信令的空口传输时间和处理时间。</p>

:::

:::{div}
:class: standard-paragraph

<p>合作设备集合、集合成员及集合使用者应符合 GB/T 48336.402—2026 中第 3 章。</p>

:::
