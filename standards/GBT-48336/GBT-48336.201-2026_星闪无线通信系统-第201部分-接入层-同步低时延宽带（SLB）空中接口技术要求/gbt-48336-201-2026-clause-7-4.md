# 7.4 管理功能和流程

(gbt-48336-201-2026-clause-7-4-1)=
## 7.4.1 服务与功能

(gbt-48336-201-2026-clause-7-4-1-1)=
### 7.4.1.1 一般描述

:::{div}
:class: standard-paragraph

<p>管理实体是一个逻辑功能实体,应至少提供如下服务和功能:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 通信域系统消息发送与接收;</p>
</li>
<li><p>——— 连接建立、重配置、拒绝和释放;</p>
</li>
<li><p>——— 认证与安全机制更新;</p>
</li>
<li><p>——— 逻辑信道管理(添加、修改和删除);</p>
</li>
<li><p>——— ARQ、HARQ 和 DRX等配置;</p>
</li>
<li><p>——— 资源调度配置(半静态调度和动态调度);</p>
</li>
<li><p>——— 测量与上报;</p>
</li>
<li><p>——— T节点辅助信息上报;</p>
</li>
<li><p>——— T节点能力上报。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>G节点管理实体和 T节点管理实体通过 XRC 消息交互实现上述功能和服务。管理实体产生的XRC消息通过数据链路层和物理层传输。</p>

:::

(gbt-48336-201-2026-clause-7-4-1-2)=
### 7.4.1.2 状态管理

:::{div}
:class: standard-paragraph

<p>T节点包含两种状态,分别为连接态和非连接态。T 节点成功建立 XRC连接后,进入连接态;当XRC连接被释放后,T节点进入非连接态。</p>

:::

:::{div}
:class: standard-paragraph

<p>当 T节点处在非连接态时,T节点可执行以下操作:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 获取通信域的广播信息和系统消息。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>当 T节点处在连接态时,T节点可执行以下操作:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 获取通信域的广播信息和系统消息;</p>
</li>
<li><p>——— 监听物理 G链路控制信息;</p>
</li>
<li><p>——— 进行非连续接收;</p>
</li>
<li><p>——— 进行单播通信;</p>
</li>
<li><p>——— 进行信道测量。</p>
</li></ul>

:::

(gbt-48336-201-2026-clause-7-4-2)=
## 7.4.2 流程

(gbt-48336-201-2026-clause-7-4-2-1)=
### 7.4.2.1 通信域系统消息获取

:::{div}
:class: standard-paragraph

<p>通信域广播信息的发送周期为固定值,通信域广播信息携带指示通信域第一组系统消息的位置和发送周期信息。通信域第一组系统消息携带通信域其他系统消息的位置和发送周期信息。</p>

:::

:::{div}
:class: standard-paragraph

<p>通信域广播信息携带通信域广播信息或系统消息变更指示信息,指示广播信息或系统消息是否发生更改。当发生变更时,G节点在相应的更新周期上更新广播信息或系统消息。</p>

:::

:::{div}
:class: standard-paragraph

<p>当 T节点在上电、连接选择或获知通信域广播信息或系统消息发生变更时,需执行通信域系统消息获取流程,通用流程如下所示。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 获取通信域的广播信息。</p>
</li>
<li><p>b) 基于通信域的广播信息,获取通信域第一组系统消息。</p>
</li>
<li><p>c) 基于第一组系统消息,获取其他系统消息。</p>
</li>
<li><p>d) 当 T节点为 Type2类型,且获得足够信息用于确定随机接入的目标 G节点时:</p>
</li></ol>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 如果通信域系统消息中接入控制信元accessControl指示不允许 Type2类型的终端接入,则不进行随机接入流程;</p>
</li>
<li><p>——— 否则,发起随机接入流程。</p>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="5">
<li><p>e) 当 T节点为 Type1类型,且获得足够信息用于确定随机接入的目标 G节点时:</p>
</li></ol>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 如果通信域系统消息中接入控制信元accessControl指示不允许 Type1类型的终端接入,则不进行随机接入流程;</p>
</li>
<li><p>——— 否则,如果 T节点配置的物理层标识有效,则发起随机接入流程。</p>
</li></ul>

:::

:::{admonition} 注1
:class: note

<p>Type1类型为封闭式设备,Type2类型为开放式设备。</p>

:::

:::{admonition} 注2
:class: note

<p>Type1类型设备,其物理层标识配置后默认始终有效;当且仅当 G节点为期望的目标通信节点时,T节点才发起随机接入流程。</p>

:::

(gbt-48336-201-2026-clause-7-4-2-2)=
### 7.4.2.2 连接管理

(gbt-48336-201-2026-clause-7-4-2-2-1)=
#### 7.4.2.2.1 概述

:::{div}
:class: standard-paragraph

<p>连接管理包括 XRC连接建立、XRC连接参数重配置和 XRC连接释放等流程。</p>

:::

(gbt-48336-201-2026-clause-7-4-2-2-2)=
#### 7.4.2.2.2 连接建立

:::{div}
:class: standard-paragraph

<p>T节点可发起随机接入流程,与目标 G节点建立 XRC连接,为业务数据提供安全传输保障。</p>

:::

:::{div}
:class: standard-paragraph

<p>在随机接入流程中,T节点至少使用两类物理层标识。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 用于随机接入的物理层标识:可由 T 节点随机生成或由 G 节点配置。当首次接入目标 G 节点时,T节点随机生成物理层标识;当 T节点保存上次接入时由该 G 节点分配的newphy-ID-</p>
</li></ul>

:::

:::{div}
:class: algorithm-line

<p>for NextAccess时,则应使用该物理层标识。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 用于数据调度的物理层标识:由 G节点在关联建立时配置newphy-IDforUnicast。</p>
</li></ul>

:::

:::{admonition} 注
:class: note

<p>在连续传输模式下,若通信域系统消息包含[contentionPhysID-starting,contentionPhysID-ending]指示,可使用其配置范围内的一个物理层标识用于随机接入。</p>

:::

:::{div}
:class: standard-paragraph

<p>随机接入时采用的调制方式由 mcsforAccess确定。</p>

:::

:::{div}
:class: standard-paragraph

<p>根据是否进行安全协商,随机接入流程分为无安全上下文的随机接入流程和有安全上下文的随机接入流程。无安全上下文的随机接入流程应进行安全协商。</p>

:::

:::{div}
:class: standard-paragraph

<p>完整的无安全上下文随机接入流程描述如下(见附录 G)。T 节点首次接入目标 G 节点应使用该流程。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 步骤1:T节点监听SAB,识别并同步目标 G节点。</p>
</li>
<li><p>b) 步骤2:T节点监听广播信息,获得目标 G节点通信域广播信息,包含通信域实时参数信息。</p>
</li>
<li><p>c) 步骤3:T节点可监听目标 G节点第一组系统消息,获取更多接入相关信息。</p>
</li>
<li><p>d) 步骤4:T 节点使用24比特物理层标识,按照6.2.4.5的规定使用接入资源进行随机接入。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>T节点在该接入资源上向目标 G节点发送接入信息块,包括接入目的(取值为0)、T 节点物理层标识和 G节点物理层标识等信息,指示该 T 节点对目标 G 节点发送随机接入请求。同时,T节点开启计时器timer-connection。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="5">
<li><p>e) 步骤5:G节点接收接入请求,通过 G链路控制信息向 T节点发送xrcSetup消息,用于指示允</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>许该 T节点进行接入。该消息包含 TA 指示、功率控制、必要的物理层配置(T 节点可用的ACK/NACK 资源等)、SR资源配置等。同时,G节点开启计时器timer-connection。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="6">
<li><p>f) 步骤6:当 T节点接收到xrcSetup消息时,T节点根据配置信息,建立可承载后续XRC消息交互的逻辑信道$(\mathrm{LCID}=1)\text{。}$该逻辑信道使用默认参数配置,满足双方 XRC消息基本交互要求。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>同时,T节点向 G节点发送xrcSetupComplete消息。该消息包含关联请求信息,用于开启关联建立流程。由于 T节点本地没有 G节点安全上下文,则携带associationRequestNonSec信元,期望 G节点执行安全协商流程。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="7">
<li><p>g) 步骤7:在成功收到包含associationRequestNonSec信元的xrcSetupComplete消息后,G 节点与 T节点需进行安全协商流程和关联建立流程。</p>
<ol class="decimal-list" start="1">
<li><p>1) 安全协商流程:双方通过securityContextRequest和securityContextResponse消息交互建立安全连接,获得彼此安全上下文信息。</p>
</li>
<li><p>2) 关联建立流程:双方通过associationSetupNonSec和associationComplete消息交互,完成关联建立流程。G节点为 T节点配置通信域内用于调度的唯一物理层标识newphy-ID-</p>
</li></ol>
</li></ol>

:::

:::{div}
:class: algorithm-line

<p>for Unicast、用于下次接入的唯一物理层标识newphy-IDforNextAccess和安全上下文标</p>

:::

:::{div}
:class: standard-paragraph

<p>识newSecurityContextID。此后,T 节点应使用 newphy-IDforUnicast物理层标识与G节点进行数据通信。associationComplete消息可同时携带 T 节点辅助信息,指示业务特征信息。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="8">
<li><p>h) 步骤8:若 G节点未获得 T 节点能力信息,可通过tNodeCapabilityRequest消息发起 T 节点能力查询请求,T节点通过tNodeCapabilityFeedback消息反馈自己的能力信息集合。</p>
</li>
<li><p>i) 步骤9:G节点根据 T 节点能力和 T 节点辅助信息等信息,通过 xrcReconfiguration消息对T节点添加可承载高层业务数据的逻辑信道(默认承载),该逻辑信道参数应满足高层业务数据 QoS要求。T节点发送xrcReconfigurationComplete进行确认。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>至此,无安全上下文的 XRC连接建立流程完成,T节点进入连接态。</p>

:::

:::{div}
:class: standard-paragraph

<p>在整个流程中,当 G节点或 T节点侧的计时器timer-connection超时,本次随机接入流程失败。</p>

:::

:::{div}
:class: standard-paragraph

<p>在步骤5中,G节点可发送xrcReject消息拒绝 T 节点的连接建立请求。T 节点接收到该消息时应执行以下操作:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 停止计时器timer-connection;</p>
</li>
<li><p>——— 接收连接失败原因,并报告给上层;</p>
</li>
<li><p>——— 如果配置 waitTime,应在 waitTime时间内保持静默,waitTime超时后可再次向该 G 节点发起随机接入流程。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>当 T节点再次接入已知 G节点且保留该 G 节点的安全上下文时,可执行有安全上下文的随机接入流程,该流程不包含安全协商交互,具体描述如下。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 步骤1:T节点监听SAB,识别并同步目标 G节点。</p>
</li>
<li><p>b) 步骤2:T节点监听广播信息,获得目标 G节点通信域广播信息,包含通信域实时参数信息。</p>
</li>
<li><p>c) 步骤3:T节点可监听目标 G节点第一组系统消息,获取更多接入相关信息。</p>
</li>
<li><p>d) 步骤4:T 节点使用24比特物理层标识,按照6.2.4.5的规定使用接入资源进行随机接入。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>T节点在该接入资源上向目标 G节点发送接入信息块,包括接入目的(取值为0)、T 节点物理层标识和 G节点物理层标识等信息,指示该 T 节点对目标 G 节点发送随机接入请求。同时,T节点开启计时器timer-connection。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="5">
<li><p>e) 步骤5:G节点接收到接入请求后,通过 G链路控制信息向 T节点发送xrcSetup消息,用于指示允许进行 接入。该消 息包 含 TA 指示、功率控制、必 要的物理层配置 (T 节点可用的ACK/NACK 资源等)、SR资源配置等。同时,G节点开启计时器timer-connection。</p>
</li>
<li><p>f) 步骤6:当 T节点接收到xrcSetup消息时,T节点根据配置信息,建立可承载后续XRC消息交</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>互的逻辑信道$(\mathrm{LCID}=1)\text{。}$该逻辑信道使用默认参数配置,满足双方 XRC 消息基本交互要求。同时,T节点向 G 节点发送 XRCSetupComplete消息。该消息包含关联请求信息,用于开启关联建立流程。由于 T 节点本地已保存 G 节点的安全上下文,则携带associationRe-questWithSec信元,包含关联的安全上下文标识newSecurityContextID。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="7">
<li><p>g) 步骤7:在成功收到包含associationRequestWithSec信元的 xrcSetupComplete消息后,G 节点应进行安全上下文验证和关联建立流程。</p>
<ol class="decimal-list" start="1">
<li><p>1) 安全上下文验证:G节点通过newSecurityContextID查询并验证本地保存的 T 节点安全上下文的有效性。</p>
</li>
<li><p>2) 关联建立流程:双方通过associationSetupWithSec和associationComplete消息交互,完成关联建立流程。G 节点为 T 节点配置通信域内用于调度的唯一物理层标识newphy-IDforUnicast、用于下次接入的唯一物理层标识newphy-IDforNextAccess和安全上下文标识newSecurityContextID。associationComplete消息同时可携带 T 节点辅助信息,指示业务特征信息。</p>
</li></ol>
</li>
<li><p>h) 步骤8:若 G节点未获得 T 节点能力信息,可通过tNodeCapabilityRequest消息发起 T 节点能力查询请求,T节点通过tNodeCapabilityFeedback消息反馈自己的能力信息集合。</p>
</li>
<li><p>i) 步骤9:G节点根据 T 节点能力和 T 节点辅助信息等信息,通过 xrcReconfiguration消息对T节点添加可承载高层业务数据的逻辑信道,该逻辑信道参数应满足高层业务数据 QoS要求。T节点发送xrcReconfigurationComplete进行确认。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>至此,有安全上下文的 XRC连接建立流程完成,T节点进入连接态。</p>

:::

(gbt-48336-201-2026-clause-7-4-2-2-3)=
#### 7.4.2.2.3 连接重配置

:::{div}
:class: standard-paragraph

<p>G节点可通过xrcReconfiguration消息对连接态 T 节点进行更多配置,例如,逻辑信道添加、安全密钥更新,测量任务配置、调度资源配置和多载波配置等。</p>

:::

:::{div}
:class: standard-paragraph

<p>当 T节点接收到xrcReconfiguration消息时,根据所包含的不同信元,进行相应的处理。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 若包含securityConfig,执行单播密钥或组播密钥配置流程。</p>
</li>
<li><p>——— 若包含logicalchannelConfig,执行逻辑信道配置流程。</p>
</li>
<li><p>——— 若包含 meas-reportConfig,获取测量任务,执行测量与上报流程。</p>
</li>
<li><p>——— 若包含sps-Config,执行半静态资源配置流程。</p>
</li>
<li><p>——— 若包含physicalConfigDedicated,获取并执行物理层配置流程。</p>
</li>
<li><p>——— 若包含carrierSwitch-TSpecific,获取载波切换配置信息,并在目标载波发起接入。</p>
</li>
<li><p>——— 若包含 multiBandConfig,获取多载波配置信息。</p>
</li>
<li><p>——— 若包含groupcastConfig,获取组播组的配置信息。</p>
</li>
<li><p>——— 若包含otherConfig,可分别获取drx-Config、lcsr-Config或rlf-Config等配置信息。</p>
</li></ul>

:::

(gbt-48336-201-2026-clause-7-4-2-2-4)=
#### 7.4.2.2.4 连接释放

:::{div}
:class: standard-paragraph

<p>当连接态 T节点接收到 G节点发送的xrcRelease消息时,释放所有逻辑信道,清除所有缓存区数据。XRC连接释放后,T节点进入非连接态。</p>

:::

:::{div}
:class: standard-paragraph

<p>T节点可向 G节点发送 xrcReleaseRequest消息,主动请求释放 XRC 连接,随后 G 节点可反馈xrcRelease消息。</p>

:::

(gbt-48336-201-2026-clause-7-4-2-3)=
### 7.4.2.3 逻辑信道配置

(gbt-48336-201-2026-clause-7-4-2-3-1)=

### 7.4.2.13 上层地址配置与唯一性检测

:::{div}
:class: standard-paragraph

<p>XRC连接可承载若干种上层地址的数据报文。本文件规定上层地址类型包括 MAC地址。</p>

:::

:::{div}
:class: standard-paragraph

<p>G节点对 T节点的上层地址进行唯一性检测并按需使能该地址类型的数据传输功能。以 T 节点申请 MAC地址数据传输功能为例,步骤如下。</p>

:::

:::{div}
:class: standard-paragraph

<p>初始接入步骤如下。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) T 节点在 XRC 随机接入过程中发送associationComplete消息,携带tNode-AssistantInfor-mationReport信元,包含上层地址类型信息addressTypeRequest;或在 XRC连接建立后的任意时 刻 发 送 携 带包 含 addressTypeRequest 的 tNode-AssistantInformationReport 信元。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>其中:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 在addressTypeBitmap中,比特位0为1,指示T节点期望使能 MAC地址数据传输功能;</p>
<ul class="standard-list">
<li><p>——— 若 T节点已配置 MAC地址,可通过 macAddress上报;否则不包含 macAddress信元。</p>
</li></ul>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="2">
<li><p>b) 当addressTypeBitmap中比特位0为1且 macAddress不为空时,G节点应执行 MAC地址唯一性检测,检测结果包括:</p>
<ul class="standard-list">
<li><p>——— MAC地址唯一:允许 T节点使用该 MAC地址;</p>
</li>
<li><p>——— MAC地址不唯一:禁止 T节点使用该 MAC地址。</p>
</li></ul>
</li>
<li><p>c) 当addressTypeBitmap中比特位0为1且 macAddress为空时,G 节点为 T 节点分配一个唯一的 MAC地址,并通过addressTypeConfig中的 macAddress进行指示。</p>
</li>
<li><p>d) G节点根据检测结果执行相应操作,通过xrcReconfiguration消息中addressTypeConfig指示</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>是否使能 T节点的 MAC地址数据传输功能。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 当比特位0置1时,指示 G 节点使能 MAC地址数据传输功能。若 macAddress为空,指示 T节点应使用上报的 MAC地址;否则 T 节点应使用 macAddress指示的 MAC地址。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>配置完成后,G节点将 T节点的 MAC地址与 T节点的 L2ID建立映射关系。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 当比特位0置0时:指示G节点不使能 MAC地址数据传输功能,此时 macAddress无效。</p>
</li></ul>

:::

<p>G节点也可直接通过 xrcReconfiguration消息配置并使能指定 T 节点的 MAC 地址数据传输功能。</p>

<p>T节点在 XRC随机接入过程中发送associationComplete消息,携带tNode-AssistantInformation-Report信元,包含上层地址类型信息addressTypeRequest;或在 XRC连接建立后的任意时刻发送携带包含addressTypeRequest的tNode-AssistantInformationReport信元。如果addressTypeBitmap中比特位0为1,指示 T节点期望使能 MAC地址数据传输功能,G节点应基于 T节点的 L2ID以及 T 节点的 MAC地址与T节点的L2ID映射关系,确定T节点的 MAC地址。G节点使能该T节点 MAC地址的数据传输功能,并通过xrcReconfiguration消息中addressTypeConfig指示(比特位0置1)。</p>
