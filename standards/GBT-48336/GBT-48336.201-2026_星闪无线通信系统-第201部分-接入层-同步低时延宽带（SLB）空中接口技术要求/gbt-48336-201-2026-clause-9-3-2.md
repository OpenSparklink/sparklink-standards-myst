:::{div}
:class: standard-paragraph

<p>当 T节点无安全上下文时,应进行认证和安全上下文协商流程。认证和安全上下文协商流程在关联流程中执行。流程见图43,流程描述如下。</p>

:::

:::{div}
:class: standard-paragraph

<p>G节点在通信域系统消息中携带其支持的密钥协商算法。密钥协商算法按照优先级顺序排列,优先级高的算法排在前面。通信域系统消息 DomainSysInfo-Group0、DomainSysInfo-Group1、Domain-SysInfo-Group2、DomainSysInfo-Group3和 DomainSysInfo-Group4均应使用算法 Dalgorithm 进行完整性保护。DomainSysInfo-Group0、DomainSysInfo-Group1、DomainSysInfo-Group2、DomainSysInfo-Group3或 DomainSysInfo-Group4可使用算法 Dalgorithm 进行加密和完整性保护。如果只进行完整性保护,则使用密钥SIGK;如果进行加密和完整性保护,则使用密钥SGK。</p>

:::

:::{div}
:class: standard-paragraph

<p>T节点根据 G节点的密钥协商算法能力,选择密钥协商算法。该算法应是 T节点支持的密钥协商算法,且在 G节点支持的密钥协商算法中优先级最高。T 节点产生私钥,并根据选择的密钥协商算法生成 相 应的 公 钥,其 中 公 钥作 为 密 钥协 商 参数 KEt(包 括 KEtx 和 KEty)。T 节点 生 成 随 机数NONCEt。T节点应每次生成对应于密钥协商算法的新密钥对,且密钥对不应为弱密钥对。生成NONCEt的随机数生成器应使用安全的的随机数生成器,确保 NONCEt的随机性。</p>

:::

:::{div}
:class: standard-paragraph

<p>T节点向 G节点发送关联请求信息,携带认证凭证配置指示indication [00表示 PSK、01表示口令]、[PSKID]、T节点选择的密钥协商算法(KEalg)、密钥协商参数 KEt、[Rt]、T 节点的安全能力(SecCapabilities)和随机数 NONCEt。安全能力包括T节点支持的密钥派生函数、认证加密算法、加密算法和完整性保护算法,见9.3.7。[PSKID]为可选,当 T 节点使用配置密钥方式接入 G 节点时携带,当 T节点使用配置口令方式接入 G节点时不携带。[Rt](包括rtx和rty)为可选,当 T节点选择的密钥协商算法为SM2时携带,T节点根据SM2算法计算 Rt,当 T 节点选择的密钥协商算法为 ECDH时不携带。</p>

:::

:::{div}
:class: standard-paragraph

<p>G节点判断 G节点的关联数量是否小于或等于 G节点可关联数量阈值。当 G 节点关联数量超过关联数量阈值时,G节点不再接收或处理关联请求。</p>

:::

:::{div}
:class: standard-paragraph

<p>G节点验证接收到的密钥协商参数 KEt(包括 KEtx和 KEty)是否在选择的密钥协商算法的椭圆曲线上,且 KEt的阶是否等于所选椭圆曲线上g生成的子群的阶。如果验证不通过,则 G 节点丢弃该消息。G节点判断 T 节点选择的密钥协商算法是否在广播消息中携带的密钥协商算法里。如果不在,则G节点丢弃该消息。如果在,则G节点根据T节点的安全能力、G节点预配置的算法优选策略和业务类型选择优先级最高的算法,包括优先级最高的密钥派生函数以及优先级最高的信令面的认证加密算法,或信令面的加密算法和完整性保护算法,以及优先级最高的用户面的认证加密算法,或用户面的加密算法和完整性保护算法。算法优选策略可通过按照优先级排序的算法列表实现,如 G 节点预配置的密钥派生函数优先级列表、信令面认证加密算法优先级列表、信令面加密算法优先级列表、信令面完整性保护算法优先级列表、用户面认证加密算法优先级列表、用户面加密算法优先级列表、用户面完整性保护算法优先级列表等。信令面和用户面选择的算法可不同。</p>

:::

:::{div}
:class: standard-paragraph

<p>当选择的认证加密算法或完整性保护算法支持多个 MIC长度时,G节点根据选择的信令面认证加密算法或完整性保护算法支持的 MIC长度、预配置的信令面完整性保护的 MIC长度优选策略,选择信令面完整性保护的 MIC长度。信令面 MIC长度优选策略可通过按照优先级排列的 MIC长度列表实现。用户面的 MIC长度根据用户面认证加密算法或完整性保护算法支持的 MIC长度、以及 T 节点的业务特征(比如,业务类型和业务数据包大小)确定,G节点将用户面的 MIC长度发给 T节点。典型应用场景下的用户面完整性保护的 MIC长度策略见附录B。</p>

:::

:::{admonition} 注1
:class: note

<p>G节点可配置优先级,以决定当用户面加密和完整性保护开启时,是优先选择认证加密算法还是独立的完整性保护和加密算法。</p>

:::

:::{admonition} 注2
:class: note

<p>信令面和用户面加密算法和完整性保护算法的优先级可不同。</p>

:::

:::{admonition} 注3
:class: note

<p>控制面使用和信令面相同的算法。</p>

:::

:::{div}
:class: standard-paragraph

<p>G节点产生私钥,并根据选择的密钥协商算法,生成相应的公钥,其中公钥作为密钥协商参数 KEg(包括 KEgx和 KEgy)。G节点生成随机数 NONCEg。G节点根据 KEt和密钥协商算法,计算出共享密钥 K<sub>KE</sub>,其中$,K_{\mathrm{KE}}=\mathrm{KE}(\mathrm{KEt},G$ 节点私钥)。G 节点根据 K<sub>KE</sub>、NONCEt和 NONCEg,使用选择的密钥派生函数计算出 Kgt,计算方式为$:Kgt=\mathrm{KDF}(K_{\mathrm{KE}},\mathrm{NONCEt},\mathrm{NONCE}g)\text{。}G$ 节点应每次生成对应于密钥协商算法的新密钥对,且密钥对不应为弱密钥对。生成 NONCEg的随机数生成器应使用安全的随机数生成器,确保 NONCEg的随机性。</p>

:::

:::{div}
:class: standard-paragraph

<p>G节点根据选择的密钥派生函数进一步从 Kgt推演出信令面的安全密钥(即信令面的认证加密密钥,或信令面的加密密钥和完整性保护密钥)、用户面的安全密钥(即用户面的认证加密密钥,或用户面的加密密钥和完整性保护密钥)。详细密钥推演方式见9.3.3.1。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于使用口令方式接入的 T节点,G节点根据口令生成PSK,PSK 计算方式如公式(53)所示。</p>

:::

(gbt-48336-201-2026-equation-53)=
```{math}
\mathrm{PSK}=\operatorname{KDF}(\mathrm{Kgt},\text{口令},\text{T 节点 phy-ID},\text{G 节点 phy-ID},\mathrm{NONCEt},\mathrm{NONCEg})\tag{53}
```

:::{admonition} 注4
:class: note

<p>在生成 PSK 之前,G 节点可给用户发送提示,提示有新的 T 节点需要和 G 节点进行关联。待用户确认之后,G节点再生成PSK。</p>

:::

:::{div}
:class: standard-paragraph

<p>G节点计算认证参数 AUTHg。AUTHg的计算方式如公式(54)所示。</p>

:::

(gbt-48336-201-2026-equation-54)=
```{math}
\mathrm{AUTHg}=\operatorname{AUF}(\mathrm{PSK},\mathrm{KKE},\mathrm{NONCEg},\text{没有安全上下文的关联请求信息内容})\text{。}\tag{54}
```

:::{admonition} 注5
:class: note

<p>AUF和 KDF使用相同的密码算法。</p>

:::

:::{admonition} 注6
:class: note

<p>没有安全上下文的关联请求信息内容=indication||预留 ||[PSKID]||[KEtx]||[KEty]||[Rtx]||[Rty]||SecCapabilities||NONCEt||KEalg。其中,预留长度为6bit,默认值为0。</p>

:::

:::{div}
:class: standard-paragraph

<p>G节点向 T节点发送安全上下文请求消息,携带 G节点的密钥协商参数 KEg[Rg]、随机数 NON-CEg、选择的算法(algorithm)、MIC长度(MIClength)和 AUTHg。选择的算法(algorithm)见9.3.7,包括密钥派生函数,信令面的认证加密算法,或者,信令面的加密算法和完整性保护算法,还包括用户面的认证加密算法,或者,用户面的加密算法和完整性保护算法。MIC长度(MIClength)包括选择的信令面完整性保护的 MIC长度和选择的用户面完整性保护的 MIC长度。[Rg](包括rgx和rgy)为可选,当T节点选择的密钥协商算法为SM2时携带,T节点根据SM2算法计算 Rg,当 T 节点选择的密钥协商算法为 ECDH 时不携带。</p>

:::

:::{admonition} 注7
:class: note

<p>当选择的算法(algorithm)中携带的用户面完整性保护算法标识符为全0时,则不启动用户面完整性保护。</p>

:::

:::{div}
:class: standard-paragraph

<p>G节点使用选择的信令面的认证加密算法和信令面的完整性保护密钥 Ks.int,或者使用选择的信令面的完整性保护算法和完整性保护密钥 Ks.int,对安全上下文请求消息做完整性保护,即计算 MIC(MessageIntegrityCode,消息完整性代码),并将 MIC包含在安全上下文请求消息中。</p>

:::

:::{div}
:class: standard-paragraph

<p>T节点验证接收到的密钥协商参数 KEg(包括 KEgx和 KEgy)是否在选择的密钥协商算法的椭圆曲线上,且 KEg的阶是否等于所选椭圆曲线上g生成的子群的阶。如果验证不通过,则 T 节点丢弃该消息。T节点根据 KEg和密钥协商算法,计算出共享密钥 K<sub>KE</sub>,其中$,K_{\mathrm{KE}}=\mathrm{KE}(\mathrm{KE}g,T$ 节点私钥)。</p>

:::

:::{div}
:class: standard-paragraph

<p>T节点根据 K<sub>KE</sub>、NONCEt和 NONCEg,使用选择的密钥派生函数计算出 Kgt,$Kgt=\mathrm{KDF}(K_{\mathrm{KE}},\mathrm{NON}-$CEt,NONCEg)。T节点根据 G节点选择的密钥派生函数,使用和 G 节点相同的方式计算出信令面的安全密钥,用户面的安全密钥。详细密钥推演方式见9.3.3.1。</p>

:::

:::{div}
:class: standard-paragraph

<p>T节点检查消息的完整性,即校验 MIC是否正确。如果完整性验证不通过,T节点丢弃该消息,可重新发送接入请求。</p>

:::

:::{div}
:class: standard-paragraph

<p>若 T节点使用口令方式接入,T 节点根据 G 节点ID 查询是否有对应于 G 节点ID 的 PSK 信息。</p>

:::

:::{div}
:class: standard-paragraph

<p>如果没有,则 T节点根据口令生成PSK,PSK 计算方式如公式(55)所示。</p>

:::

(gbt-48336-201-2026-equation-55)=
```{math}
\mathrm{PSK}=\operatorname{KDF}(\mathrm{Kgt},\text{口令},\text{T 节点 phy-ID},\text{G 节点 phy-ID},\mathrm{NONCEt},\mathrm{NONCEg})\tag{55}
```

:::{div}
:class: standard-paragraph

<p>T节点基于PSK 验证 AUTHg是否正确。如果 AUTHg验证不通过,T 节点丢弃该消息,可重新发送接入请求。</p>

:::

:::{admonition} 注8
:class: note

<p>当 AUTHg验证多次失败时,若使用口令方式接入的 T节点存在预共享密钥 PSK,T节点可提示用户确认是否删除 T节点上的预共享密钥PSK。若使用口令方式接入的 T节点不存在预共享密钥PSK,T节点可提示用户在 G节点处删除 G节点的预共享密钥PSK。</p>

:::

:::{div}
:class: standard-paragraph

<p>T节点向 G节点发送安全上下文响应消息。消息中携带 AUTHt和 T 节点 L2ID。AUTHt的计算方法如公式(56)所示。</p>

:::

(gbt-48336-201-2026-equation-56)=
```{math}
\mathrm{AUTHt}=\operatorname{AUF}(\mathrm{PSK},\mathrm{KKE},\text{安全上下文请求消息内容},\mathrm{NONCEt},\text{G 节点密钥协商算法能力})\tag{56}
```

:::{admonition} 注9
:class: note

<p>AUF和 KDF使用相同的密码算法。</p>

:::

:::{admonition} 注10
:class: note

<p>安全上下文请求消息内容=[KEgx]|| [KEgy]|| [Rgx]|| [Rgy]||NONCEg||algorithm|| MIC length||AUTHg。</p>

:::

:::{div}
:class: standard-paragraph

<p>T节点使用信令面的认证加密算法和认证加密密钥 Ks.ac对安全上下文响应消息做保护,或者T节点使用信令面的完整性保护算法和完整性保护密钥 Ks.int对安全上下文响应消息做完整性保护,使用信令面的加密算法和加密密钥 Ks.enc对安全上下文响应消息做加密保护,完整性保护生成的MIC携带在安全上下文响应消息中。</p>

:::

:::{div}
:class: standard-paragraph

<p>如果安全上下文响应消息进行了加密,则 G节点解密安全上下文响应消息。G 节点检查安全上下文响应消息的完整性,并验证 AUTHt是否正确。如果完整性或 AUTHt验证不通过,G 节点向 T 节点发送拒绝接入的关联建立消息,携带 causeReject,包含拒绝原因(取值为 2,即 G 节点校验消息失败)。</p>

:::

:::{div}
:class: standard-paragraph

<p>如果完整性和 AUTHt验证通过,则执行后续流程。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于使用配置密钥方式接入的 T节点,若 G 节点配置了白名单,G 节点应判断 T 节点 L2ID 是否在白名单中。如果不在,则 G节点应丢弃该消息。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于使用口令方式接入的 T节点,若 G节点配置了白名单,G 节点应判断 T 节点 L2ID 是否在白名单中。如果不在,G节点应提示用户确认是否允许新 T 节点接入。当用户选择不允许时,应丢弃该消息。</p>

:::

:::{div}
:class: standard-paragraph

<p>G节点为 T节点生成newSecurityContextID。</p>

:::

:::{div}
:class: standard-paragraph

<p>G节点根据 T节点 L2ID判断 G节点是否有预配置与 T 节点 L2ID 对应的组ID(IDforGroupcast中对应的 phy-ID)。如 果 存在组 ID,G 节点 判 断 T 节点 所 在组 是 否 有 组密 钥 GK 和 组 算法Galgorithm。当 T节点所在组不存在组密钥 GK 时,G节点产生随机数 RAND,并根据 RAND和组ID生成组密钥 GK。GK 的计算方法如公式(57)所示。</p>

:::

(gbt-48336-201-2026-equation-57)=
```{math}
\mathrm{GK}=\operatorname{KDF}(\mathrm{RAND},\text{组 ID})\tag{57}
```

:::{div}
:class: standard-paragraph

<p>式中:</p>

:::

:::{div}
:class: standard-definitions

KDF
: G节点支持的优先级最高的密钥派生函数。G节点生成 GK 的标识符(GKID)。

:::

:::{div}
:class: standard-paragraph

<p>G节点将 COUNTERg初始化为0。当单播信令面的加密保护未开启时,G 节点根据共享密钥Kgt和 COUNTERg,使用选择的密钥派生函数计算出保护组密钥 GK 机密性的密钥 Kg:$Kg=\mathrm{KDF}$(Kgt,COUNTERg,&quot;groupkey&quot;)。G节点把 GK 和 Kg进行异或得到$:\mathrm{GKc}=\mathrm{GK}\oplus Kg$。</p>

:::

:::{div}
:class: standard-paragraph

<p>当 T节点所在组未确定组算法时,G节点在组内所有 T 节点均支持的算法中,根据预配置的算法优选策略选择组算法,组算法包括优先级最高的密钥派生函数,信令面的认证加密算法或信令面的加密算法和完整性保护算法,用户面的认证加密算法或用户面的加密算法和完整性保护算法。</p>

:::

:::{div}
:class: standard-paragraph

<p>G节点根据选择的密钥派生函数进一步从 GK 推演出组播信令面的安全密钥(即信令面的认证加密密钥,或信令面的加密密钥和完整性保护密钥)、组播用户面的安全密钥(即用户面的认证加密密钥,或用户面的加密密钥和完整性保护密钥)。详细密钥推演方式见9.3.3.2。</p>

:::

:::{div}
:class: standard-paragraph

<p>G节点向 T节点发送关联建立消息,携带identityConfig(包括newphy-IDforUnicast、newphy-ID-</p>

:::

:class: algorithm-line

<p>for Groupcast、newphy-IDforNextAccess、newSecurityContextID)、G节点 L2ID、Kgt的有效期(Kgtex-</p>

:::
