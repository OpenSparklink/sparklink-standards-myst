# 9.3.3 密钥架构

(gbt-48336-201-2026-clause-9-3-3-1)=
## 9.3.3.1 单播密钥架构

:::{div}
:class: standard-paragraph

<p>单播场景下的密钥架构如图45所示。</p>

:::

```{image} ../../../assets/structured/GBT-48336.201-2026/diagrams/figure-45-structured.svg
:alt: 图 45　单播密钥架构。保留分支上的算法标识和密钥名称。
:class: standard-vector-figure
```

(gbt-48336-201-2026-figure-45)=
:::{div}
:class: standard-caption

<p>图 45　单播密钥架构</p>

:::

:::{div}
:class: standard-paragraph

<p>PSK 是预配置的共享密钥,或者是由输入的口令或应用服务器发送的口令生成的共享密钥。</p>

:::

:::{div}
:class: standard-paragraph

<p>K<sub>KE</sub>是 G节点和 T节点通过密钥协商算法和密钥协商参数 KEg和 KEt产生的共享密钥。KEg和KEt分别是 G节点和 T节点生成的密钥协商参数。</p>

:::

:::{div}
:class: standard-paragraph

<p>Kgt是 G节点和 T节点根据 K<sub>KE</sub>,NONCEg和 NONCEt推演出的同步低时延宽带通信系统的主密钥。NONCEg和 NONCEt分别是 G节点和 T节点生成的随机数。</p>

:::

:::{div}
:class: standard-paragraph

<p>Kmid是根据 Kgt和counter推演出的一个中间密钥,该中间密钥用于推演后续的信令面和用户面保护密钥。counter作为新鲜性参数,在Kgt生成时初始化为0,每使用counter推演一次Kmid,counter值加1。counter将作为安全上下文的一部分保存。</p>

:::

:::{div}
:class: standard-paragraph

<p>Ks.ac是 G节点和 T节点根据 Kmid、算法标识和字符串“signallingauthenc”推演得到的密钥,用于保护信令面的机密性和完整性。当选择使用认证加密算法对信令面提供保护时,G 节点和 T 节点需要推演 Ks.ac。</p>

:::

:::{div}
:class: standard-paragraph

<p>Ku.ac是 G节点和 T节点根据 Kmid、算法标识和字符串“userauthenc”推演得到的密钥,用于保护用户面的机密性和完整性。当选择使用认证加密算法对用户面提供保护时,G 节点和 T 节点需要推演 Ku.ac。</p>

:::

:::{div}
:class: standard-paragraph

<p>Kc.ac是 G节点和 T节点根据 Kmid、算法标识和字符串“controlauthenc”推演得到的密钥,用于保护控制面的机密性和完整性。当选择使用认证加密算法对控制面提供保护时,G 节点和 T 节点需要推演 Kc.ac。</p>

:::

:::{div}
:class: standard-paragraph

<p>Ks.enc是 G节点和 T节点根据 Kmid、算法标识和字符串“signallingenc”推演得到的密钥,用于保护信令面的机密性。</p>

:::

:::{div}
:class: standard-paragraph

<p>Ks.int是 G节点和 T节点根据 Kmid、算法标识和字符串“signallingint”推演得到的密钥,用于保护信令面的完整性。</p>

:::

:::{div}
:class: standard-paragraph

<p>Ku.enc是 G节点和 T节点根据 Kmid、算法标识和字符串“userenc”推演得到的密钥,用于保护用户面的机密性。当选择使用加密算法对用户面提供保护时,G节点和 T节点需要推演 Ku.enc。</p>

:::

:::{div}
:class: standard-paragraph

<p>Ku.int是 G节点和 T节点根据 Kmid、算法标识和字符串“userint”推演得到的密钥,用于保护用户面的完整性保护。当选择使用完整性保护算法对用户面提供保护时,G 节点和 T 节点需要推演Ku.int。</p>

:::

:::{div}
:class: standard-paragraph

<p>Kc.int是 G节点和 T节点根据 Kmid、算法标识和字符串“controlint”推演得到的密钥,用于保护控制面的完整性保护。当选择使用完整性保护算法对用户面提供保护时,G 节点和 T 节点需要推演Ku.int。</p>

:::

:::{div}
:class: standard-paragraph

<p>密钥架构中密钥的详细推演方式见9.3.4.1。</p>

:::

<p>GKs.ac是 G节点和 T节点根据 GK、算法标识和字符串“Groupsignallingauthenc”推演得到的组密钥,用于保护信令面的机密性和完整性。当选择使用认证加密算法对信令面提供保护时,G 节点和T节点需要推演 GKs.ac。</p>

:::

:::{div}
:class: standard-paragraph

<p>GKu.ac是 G节点和 T节点根据 GK、算法标识和字符串“Groupuserauthenc”推演得到的组密钥,用于保护用户面的机密性和完整性。当选择使用认证加密算法对用户面提供保护时,G 节点和T节点需要推演 GKu.ac。</p>

:::

:::{div}
:class: standard-paragraph

<p>GKs.enc是 G节点和 T节点根据 GK、算法标识和字符串“Groupsignallingenc”推演得到的组密钥,用于保护信令面的机密性。</p>

:::

:::{div}
:class: standard-paragraph

<p>GKs.int是 G节点和 T节点根据 GK、算法标识和字符串“Groupsignallingint”推演得到的组密钥,用于保护信令面的完整性。</p>

:::

:::{div}
:class: standard-paragraph

<p>GKu.enc是 G节点和 T节点根据 GK、算法标识和字符串“Groupuserenc”推演得到的组密钥,用于保护用户面的机密性。当选择使用加密算法对用户面提供保护 时,G 节点和 T 节点需要 推 演GKu.enc。</p>

:::

:::{div}
:class: standard-paragraph

<p>GKu.int是G节点和T节点根据GK、算法标识和字符串“Groupuserint”推演得到的组密钥,用于保护用户面的完整性保护。当选择使用完整性保护算法对用户面提供保护时,G 节点和 T 节点需要推演 GKu.int。</p>

:::

:class: standard-paragraph
