# 7.2 媒体接入层

(gbt-48336-201-2026-clause-7-2-1)=
## 7.2.1 媒体接入层功能

:::{div}
:class: standard-paragraph

<p>媒体接入层负责进行无线资源分配,并为链路控制层提供数据传输服务,应包含至少一个媒体接入实体。</p>

:::

:::{div}
:class: standard-paragraph

<p>媒体接入层要求物理层提供如下服务:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 数据传输服务;</p>
</li>
<li><p>——— HARQ 反馈信号;</p>
</li>
<li><p>——— 测量。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>媒体接入实体应至少提供如下功能:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 对不同逻辑信道的数据进行复用,生成传输块,并递交到物理层;</p>
</li>
<li><p>——— 对 LCPDU 数据进行级联;</p>
</li>
<li><p>——— 对物理层传递的传输块进行解复用,并递交到不同的逻辑链路实体;</p>
</li>
<li><p>——— 资源请求流程;</p>
</li>
<li><p>——— HARQ 机制;</p>
</li>
<li><p>——— 逻辑信道优先级机制;</p>
</li>
<li><p>——— 链路控制层数据量报告;</p>
</li>
<li><p>——— 非连续接收;</p>
</li>
<li><p>——— 数据透传。</p>
</li></ul>

:::

(gbt-48336-201-2026-clause-7-2-2)=
## 7.2.2 媒体接入层流程

(gbt-48336-201-2026-clause-7-2-2-1)=
### 7.2.2.1 随机接入

:::{div}
:class: standard-paragraph

<p>当确定目标 G节点后,T节点管理实体(见7.4.1.1)指示媒体接入实体使用合适的物理层标识开启随机接入流程。在非连续传输模式下,T节点媒体接入实体执行如下流程。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 按照6.2.4.5的规定使用接入资源发送接入信息。接入信息块中包括 T 节点物理层标识和目标 G节点物理层标识,指示该 T节点存在对目标 G 节点的随机接入请求。同时,启动timer-rachRsp计时器。</p>
</li>
<li><p>b) 在该目标 G节点的若干个后续 COT内监听发送给自己的 G链路控制信息。</p>
<ol class="decimal-list" start="1">
<li><p>1) 当成功通过该控制信息的 CRC校验时,则停止发送随机接入请求;接收该控制信息指示的 G链路数据,并递交给链路控制层,结束本次流程。</p>
</li>
<li><p>2) 当timer-rachRsp超时时,仍未接收到该控制信息或 CRC校验失败,则继续按6.2.4.5要求以概率$P$ 执行步骤a)。</p>
</li></ol>
</li>
<li><p>c) 当接收到停止发送接入信息的指示时,应停止发送接入信息,结束本次流程。</p>
</li></ol>

:::

:::{admonition} 注
:class: note

<p>timer-rachRsp计时器仅包括目标 G节点实际占用信道的时间。</p>

:::

(gbt-48336-201-2026-clause-7-2-2-2)=
### 7.2.2.2 资源请求

:::{div}
:class: standard-paragraph

<p>当上层新数据到达媒体接入层,且缺之 T 链路资源用于报告链路控制层数据量大小时,T 节点可发起资源请求流程,向 G节点申请用于发送 T链路数据的资源。</p>

:::

:::{div}
:class: standard-paragraph

<p>资源请求流程可分为以下两种方式:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 基于SR资源的资源请求流程;</p>
</li>
<li><p>——— 基于接入资源的资源请求流程。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>当 G节点已为 T节点配置SR资源时,资源请求流程如下:</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) T节点在SR资源中选择一个资源,在该资源上向 G 节点发送调度请求信息。T 节点可发起多次调度请求;</p>
</li>
<li><p>b) G节点向 T 节点发送用于调度 T 链路数据的动态调度数据控制信息,其中该控制信息被T节点的物理层标识加扰,从而对该 T节点的资源请求进行应答;</p>
</li>
<li><p>c) T节点尝试接收该动态调度数据控制信息。若成功接收并解析,则本次资源请求成功;若在发送最近一次调度请求信息的timer-srRsp时间内没有接收到该控制信息,本次资源请求失败。</p>
</li></ol>

:::

:::{div}
:class: standard-paragraph

<p>当 G节点未给 T节点配置SR资源时,资源请求流程如下:</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) T节点基于6.2.4.4规定在 COT尾部选择一个接入资源,或者在连续传输模式下从信元 Con-tentionAccessResource(若配置)指示的接入资源中随机选择一个接入资源,T 节点在该接入资源上向G节点发送接入信息块,包括接入目的(取值为1)、T节点物理层标识和G节点物理层标识,指示该 T节点向指定 G节点发送资源请求;</p>
</li>
<li><p>b) G节点向 T节点发送用于调度 T链路数据的动态调度数据控制信息;</p>
</li>
<li><p>c) T节点尝试接收该控制信息。若成功接收并解析,则本次资源请求成功;若在发送最近一次资源请求的timer-srRsp时间内没有接收到该控制信息,本次资源请求失败。</p>
</li></ol>

:::

:::{admonition} 注
:class: note

<p>资源请求失败可触发 XRC断链事件。</p>

:::

(gbt-48336-201-2026-clause-7-2-2-3)=
### 7.2.2.3 G 链路数据传输

(gbt-48336-201-2026-clause-7-2-2-3-1)=
#### 7.2.2.3.1 HARQ

:::{div}
:class: standard-paragraph

<p>G节点通过物理层 G链路控制信息,向 T节点指示是否在 G链路上存在发送给 T 节点的数据,以及相关 HARQ 信息。G节点通过物理层 G链路控制信息,向 T节点指示是否在 T链路上调度 T节点的待发送数据,以及相关 HARQ 信息。</p>

:::

:::{div}
:class: standard-paragraph

<p>媒体接入实体应包含一个 HARQ 实体,维护最多4个 HARQ 进程。每个 HARQ 进程具有唯一的 HARQ 进程标识。</p>

:::

:::{div}
:class: standard-paragraph

<p>支持数据的动态调度和半静态调度。</p>

:::

:::{div}
:class: standard-paragraph

<p>一个半静态调度可关联$L$ 个 HARQ 进程,其中$L$ 为sps-Config配置中harqProcessList信元所包含的 HARQ 进程个数。关联方式为:以每$L$ 个传输块为周期,在每个周期内$,L$ 个不同 HARQ 进程依次调度$L$ 个传输块。</p>

:::

:::{div}
:class: standard-paragraph

<p>当存在 T链路调度资源时,媒体接入实体应将 MACPDU 和其关联的 HARQ 信息一并传递到对应 HARQ 进程。</p>

:::

(gbt-48336-201-2026-clause-7-2-2-3-2)=
#### 7.2.2.3.2 解复用

:::{div}
:class: standard-paragraph

<p>媒体接入实体应根据7.2.3.1的 MACPDU 结构进行解复用,将子SDU 递交到逻辑信道标识对应的链路控制实体中。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于第一类业务,物理层向媒体接入层递交接收到的第一类业务数据,以及该数据对应的SPS资源指示。媒体接入实体根据SPS资源与承载第一类业务的逻辑信道的映射关系,将SPS资源上接收的透传数据直接递交到对应的链路控制实体中。</p>

:::

(gbt-48336-201-2026-clause-7-2-2-4)=
### 7.2.2.4 T链路数据传输

(gbt-48336-201-2026-clause-7-2-2-4-1)=
#### 7.2.2.4.1 逻辑信道优先级与数据封装

:::{div}
:class: standard-paragraph

<p>管理实体(见7.4.1.1)通过 XRC消息配置 T节点每个逻辑信道在媒体接入层的参数,具体包括:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 逻辑信道优先级priority;</p>
</li>
<li><p>——— 逻辑信道优先比特量prioritisedBitSize。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>当有新传数据时,媒体接入实体应按照如下步骤进行逻辑信道数据封装。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 对于有待发送数据的若干个逻辑信道,按照优先级递减顺序依次组包。</p>
</li>
<li><p>b) 对于逻辑信道j,当prioritisedBitSize配置为invalid时,只有当逻辑信道j的待发送数据全部组包后,才能对比其优先级低的逻辑信道的数据进行组包。</p>
</li>
<li><p>c) 否则,逻辑信道j首次封装数据量不得超过prioritisedBitSize配置的数据量。</p>
</li></ol>

:::

:::{admonition} 注
:class: note

<p>如果以上步骤执行完毕后仍有 T链路待发送数据,如何封装剩余 T链路数据,取决于 T节点实现。</p>

:::

:::{div}
:class: standard-paragraph

<p>此外,T节点应遵循以下原则:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 如果一个完整的SDU(或者部分发送的 SDU,或者重传的 LCPDU)能够填入剩余物理资源中,则不应对该SDU 进行分段;</p>
</li>
<li><p>——— 如果逻辑信道不支持分段,则不应对SDU 进行分段;</p>
</li>
<li><p>——— 如果逻辑信道支持分段,则应根据剩余物理资源大小,根据最大可填入数据量进行分段。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>对于第一类业务,配置逻辑信道标识和对应的 SPS资源,应将该逻辑信道的 T 链路数据映射到SPS对应的 T链路资源上。</p>

:::

(gbt-48336-201-2026-clause-7-2-2-4-2)=
#### 7.2.2.4.2 链路控制层数据量上报机制

:::{div}
:class: standard-paragraph

<p>T节点宜向 G节点上报其链路控制层待发送数据量。T 节点基于逻辑信道粒度进行数据量上报。</p>

:::

:::{div}
:class: standard-paragraph

<p>链路控制层数据量上报应按照有数据传输需求的逻辑信道的优先级顺序由高到低上报,具体数据量计算方法见7.3。</p>

:::

:::{admonition} 注
:class: note

<p>对于数据量为0的逻辑信道可不进行链路控制层数据量上报。</p>

:::

:::{div}
:class: standard-paragraph

<p>G节点管理实体通过 XRC消息配置参数periodic-LCSR-Timer指示 T 节点链路控制层数据量上报周期。</p>

:::

:::{div}
:class: standard-paragraph

<p>当满足以下条件之一时可触发链路控制层数据量上报机制:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— T链路新业务到达;</p>
</li>
<li><p>——— 高优先级的数据到达;</p>
</li>
<li><p>——— periodic-LCSR-Timer计时器超时。</p>
</li></ul>

:::

(gbt-48336-201-2026-clause-7-2-2-5)=
### 7.2.2.5 半静态调度与辅助信息上报

:::{div}
:class: standard-paragraph

<p>T节点支持数据的半静态调度,通过sps-Config进行配置。半静态调度预留周期物理资源,以满足对时延或速率有严格要求的业务。</p>

:::

:::{div}
:class: standard-paragraph

<p>T节点发起的周期业务,其周期信息可通过 XRC消息tNode-AssistantInformationReport向 G 节点上报,辅助 G节点配置匹配业务特征的资源并提供满足业务传输要求的调度。辅助信息包括的信息种类见7.4.2.4。</p>

:::

(gbt-48336-201-2026-clause-7-2-2-6)=
### 7.2.2.6 非连续接收 DRX

:::{div}
:class: standard-paragraph

<p>媒体接入实体宜支持非连续接收功能,以实现 T 节点对物理 G 链路控制信息的非连续监听,实现节能。</p>

:::

:::{div}
:class: standard-paragraph

<p>当 T节点处在非连接态时,可不监听 G 链路动态调度信令。在 T 节点处在连接态时,T 节点可基于 DRX配置对 G链路进行非连续监听。</p>

:::

:::{div}
:class: standard-paragraph

<p>针对 DRX配置,支持 G节点主动配置 T 节点;支持 T 节点主动提供参数并请求 G 节点进行配置,G节点可参考 T节点建议的参数,并根据通信域整体情况进行最终配置,其配置参数数值可与 T 节点建议的参数数值不同。</p>

:::

:::{div}
:class: standard-paragraph

<p>支持不同颗粒度 DRX配置项,可对 T节点的一个工作信道进行配置;可对 T节点的一个工作频段进行配置;若支持多频段,可对 T节点多个工作频段分别进行配置。</p>

:::

:::{div}
:class: standard-paragraph

<p>支持 T 节点在同一个工作频段上配置多个不同的 DRX 配置项,T 节点在该频段上的休眠与唤醒行为是多个 DRX配置项的并集结果。若 T节点支持多频段,则支持 T 节点在不同频段上配置不同的DRX配置项,此时 T节点根据不同频段上的不同 DRX配置独立执行各自的休眠与唤醒行为。</p>

:::

:::{div}
:class: standard-paragraph

<p>DRX配置包括添加、删除、使能和去使能等操作。其中使能和去使能操作不会添加或删除指定的DRX配置项,需确保对应的配置项存在。</p>

:::

(gbt-48336-201-2026-clause-7-2-3)=
## 7.2.3 媒体接入层帧结构

(gbt-48336-201-2026-clause-7-2-3-1)=
### 7.2.3.1 媒体接入层协议数据单元

(gbt-48336-201-2026-clause-7-2-3-1-1)=
#### 7.2.3.1.1 概述

:::{div}
:class: standard-paragraph

<p>媒体接入层协议数据单元的格式可包含第一类 MACPDU 结构和第二类 MACPDU 结构。</p>

:::

(gbt-48336-201-2026-clause-7-2-3-1-2)=
#### 7.2.3.1.2 第一类 MAC PDU 结构

:::{div}
:class: standard-paragraph

<p>第一类 MACPDU 可由若干个媒体接入层子PDU 组成。其中,一个媒体接入层子PDU 由媒体接入层子头和媒体接入层子SDU 组成。</p>

:::

:::{div}
:class: standard-paragraph

<p>媒体接入层子PDU 根据所承载的载荷内容不同,可分为三种类型。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 承载 LCPDU:其子头结构见图 21,共3字节,包含2字节长度字段,指示子SDU 长度,即所承载的LCPDU 长度;对组播LCID,字节1的比特2为密钥类型指示 Keytype:0表示使用组播密钥加密和解密;1表示使用单播密钥加密和解密。</p>
</li>
<li><p>——— 媒体接入层控制元素(MACCE):其子头结构见图 22,共2字节,包含1字节长度字段,指示子SDU 长度,即该类型 MACCE的具体内容长度,不包含填充 MACCE。</p>
</li>
<li><p>——— 填充 MACCE:是一种特殊的 MACCE,其子头结构见图 23,共1字节,没有长度指示或子SDU。一个第一类 MACPDU 可包含若干个填充 MACCE。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>以上三种类型的媒体接入层子PDU 在组成第一类 MACPDU 时应遵循以下规则:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— T链路传输时:所有 LCPDU 在前,所有 MACCE位于中间,若干填充 MACCE在尾部;</p>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— G链路传输时:所有 MACCE在前,所有 LCPDU 位于中间,若干填充 MACCE在尾部。</p>
</li></ul>

:::

(gbt-48336-201-2026-clause-7-2-3-2-6)=
#### 7.2.3.2.6 心跳包

:::{div}
:class: standard-paragraph

<p>心跳包用于维护 XRC连接的状态。心跳包 MACCE中,L字段数值为0,不包含后续内容。</p>

:::

:::{div}
:class: standard-paragraph

<p>T节点与 G 节点建立 XRC连接后,在配置周期timer-keepalive内可进行心跳包的发送,并进行XRC连接的 T链路和 G链路状态维护。在配置周期内:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— T节点:负责 G链路状态维护,并在该时间内至少发送一次心跳包和尝试接收 G节点的反馈。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>若收不到来自 G节点的任何反馈(包含来自 G 节点的任意 G 链路报文或信令),则触发 XRC断链事件;</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— G节点:负责 T链路状态维护,即在该时间内若收不到来自 T 节点的任意 T 链路报文或信令(含心跳包),则触发 XRC断链事件。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>由xrcReconfiguration消息中的rlf-config 信元 进行相 关参数配置,其 中,timer-keepalive默 认64ms,该时间需排除 DRX配置(若使能)的 T节点睡眠时间。</p>

:::

:::{div}
:class: standard-paragraph

<p>在第三类 MACPDU 结构中使用下图格式的心跳包。</p>

:::

:::{div}
:class: standard-paragraph

<p>其中,成员列表版本号指示信息指示是否携带成员列表版本号。该指示信息为0时版本号字段无效。</p>

:::

:::{div}
:class: standard-paragraph

<p>发送节点 DTRX 状态指示发送节点的 DTRX 状态,0表示处于业务态,1表示处于 DTRX 短周期,2表示处于 DTRX长周期。</p>
