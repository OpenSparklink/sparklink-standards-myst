# 9.3.1 认证凭证配置

:::{div}
:class: standard-paragraph

<p>本过程用于在 T节点和 G节点之间配置相同的256比特共享密钥PSK。</p>

:::

:::{admonition} 注1
:class: note

<p>PSK 是 T节点特定的。</p>

:::

:::{div}
:class: standard-paragraph

<p>配置方法可使用以下三种方法。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 配置密钥方法:通过预配置的方法,将256比特共享密钥PSK 预配置在 T节点和 G节点上。</p>
</li></ul>

:::

:::{admonition} 注2
:class: note

<p>预配置的详细方案不在本文件范围内。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 配置口令方法:用户在 G节点和 T节点上输入相同的口令。口令通过密码算法转换为256比</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>特共享密钥PSK。同步低时延宽带通信系统应满足9.3.8中的口令相关要求。</p>

:::

:::{admonition} 注3
:class: note

<p>不同 T节点可使用不同口令接入 G节点。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 第三方服务器认证凭证配置方法:第三方服务器认证凭证配置方法主要目的是识别 T 节点是</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>否和 G节点满足预设的绑定关系。T节点应可获取 G 节点标识信息,并利用 T 节点和 G 节点的标识信息生成校验信息发送给相关应用服务器,以获取认证信息。G 节点和 T 节点获取到应用服务器发送的认证口令后,基于认证口令获得256比特PSK。</p>

:::

:::{admonition} 注4
:class: note

<p>T节点和应用服务器之间的信息安全不在本文件范围内。</p>

:::

:::{admonition} 注5
:class: note

<p>本方案依赖于 G节点和 T节点分别与应用服务器之间有安全链接。</p>

:::

:::{div}
:class: standard-paragraph

<p>通过以上三种配置方法,T节点和 G节点之间可配置相同的256比特密钥PSK。</p>

:::

:::{admonition} 注6
:class: note

<p>T节点和 G节点也可通过其他方法完成 T节点和 G节点间的预共享密钥配置。</p>

:::
