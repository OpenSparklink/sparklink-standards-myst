# 7.3 链路控制层

(gbt-48336-201-2026-clause-7-3-1)=
## 7.3.1 链路控制层功能

:::{div}
:class: standard-paragraph

<p>链路控制层 为 上层 提 供 数据传输服务。来 自 上层的 PDU,作 为 链路控制层服务数据单元(SDU),采用匹配的传输模式进行传输。</p>

:::

:::{div}
:class: standard-paragraph

<p>链路控制层可包含若干个链路控制实体,其中每个链路控制实体与一个逻辑信道对应。链路控制功能主要包括:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— ARQ 状态报告;</p>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 对SDU 进行分段和重组;</p>
</li>
<li><p>——— 对SDU 进行重分段;</p>
</li>
<li><p>——— 数据透传;</p>
</li>
<li><p>——— 上层PDU 重复检测;</p>
</li>
<li><p>——— 上层PDU 重排序;</p>
</li>
<li><p>——— 链路管理功能;</p>
</li>
<li><p>——— 数据加密与解密;</p>
</li>
<li><p>——— 数据完整性保护。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>链路控制层支持以下传输模式类型,见表21。</p>

:::

:::{div}
:class: standard-paragraph

<p>链路控制层期望媒体接入层及时通知传输机会以及该机会可传输的数据量大小。</p>

(gbt-48336-201-2026-clause-7-3-2)=
## 7.3.2 链路控制层流程

(gbt-48336-201-2026-clause-7-3-2-1)=
### 7.3.2.1 链路管理流程

:::{div}
:class: standard-paragraph

<p>当上层请求建立链路控制实体时,链路控制层应建立链路控制实体,并设置参数初始值,清空缓存区,并根据指定传输模式进行数据发送和接收。</p>

:::

:::{div}
:class: standard-paragraph

<p>当上层请求释放链路控制实体时,链路控制层应清空缓存区,并释放相应的链路控制实体。</p>

:::

(gbt-48336-201-2026-clause-7-3-2-2)=
### 7.3.2.2 数据传输流程

(gbt-48336-201-2026-clause-7-3-2-2-1)=
#### 7.3.2.2.1 模式1和模式2的数据传输

(gbt-48336-201-2026-clause-7-3-2-2-1-1)=
##### 7.3.2.2.1.1 模式1和模式2的数据发送

:::{div}
:class: standard-paragraph

<p>在发送端,当接收到数据传输请求时,链路控制实体应进行以下操作:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 将上层PDU 视为链路控制层SDU;</p>
</li>
<li><p>——— 确定上层PDU 的协议报文类型,见附录 E;</p>
</li>
<li><p>——— 确定与上层PDU 关联的 XQI标识;</p>
</li>
<li><p>——— 确定与上层PDU 关联的逻辑信道标识;</p>
</li>
<li><p>——— 若层间原语传递应用标识 AID,则确定与上层PDU 关联的业务类型,见附录 D。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>针对每个SDU,链路控制实体应为其创建符合7.3.3.1规定的链路控制层PDU,并执行以下操作。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— SN 设置为(TX_NEXTmod2ˆ[lc-SN-Size])。</p>
</li>
<li><p>——— 确定 GFN,并将 GFN 值关联到该SDU。</p>
</li>
<li><p>——— 若配置 ROHC压缩,则对SDU 进行包头压缩。</p>
</li>
<li><p>——— TX_NEXT增加1。</p>
</li>
<li><p>——— 根据不同传输模式确定是否支持分段。若支持分段且需分段时,填充分段指示字段(即分段序号)和分段偏移值字段。包含同一个 SDU 各分段的多个 PDU,其 SN 字段应统一设置为该SDU 对应的SN。</p>
</li>
<li><p>——— 若配置完整性保护和加密功能,则使用 GFN 和分段序号进行完整性保护和加密操作。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>对于传输模式1,发送端链路控制实体还需根据 TX_NEXT_ACK 维护发送窗口[TX_NEXT_ACK,TX_NEXT_ACK+Window_Size],将在该窗口内若干个 LCPDU 发送给下层进行传输,并维护其状态。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 通过对端链路控制实体发送的状态报告获知SDU 是否被正确接收。</p>
</li>
<li><p>——— 当获知SN 为$x$ 的SDU 被正确接收时,链路控制实体应执行如下操作:</p>
</li>
<li><p>· $\cdot$通知上层该SDU 已经成功传输;</p>
</li>
<li><p>· $\cdot$将 TX_NEXT_ACK 设置为在[TX_NEXT_ACK,SN(TX_NEXT)]范围内的并且没有收到正确接收信息的SDU 中的最小SN。</p>
</li></ul>

:::

(gbt-48336-201-2026-clause-7-3-2-2-1-2)=
##### 7.3.2.2.1.2 模式1和模式2的数据接收

:::{div}
:class: standard-paragraph

<p>在接收端,链路控制实体维护接收窗口[RX_SUBMIT,RX_SUBMIT+Window_Size]。</p>

:::

:::{div}
:class: standard-paragraph

<p>当从下层接收到包含SN 为$x$ 且分段从$y$ 到$z$ 的SDU 的 LCPDU 时,链路控制实体应执行以下操作。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 如果$x$ 在接收窗口内且从$y$ 到$z$ 的分段之前未接收,将该PDU 保存在接收缓存中。</p>
</li>
<li><p>——— 如果SN 为$x$ 的SDU 的所有分段PDU 均成功接收,则将关联的若干分段PDU 进行重组以获取完整SDU。</p>
</li>
<li><p>——— 确定SDU 的 RCVD_HFN:</p>
</li>
<li><p>· $\cdot$若 RCVD_SN&lt;SN(RX_SUBMIT)-Window_Size,则设置$\mathrm{RCVD}\_\mathrm{HFN}=\mathrm{HFN}(\mathrm{RX}\_$SUBMIT)+1;</p>
</li>
<li><p>· $\cdot$若$\mathrm{RCVD}\_\mathrm{SN}\gt =\mathrm{SN}(\mathrm{RX}\_\mathrm{SUBMIT})+\mathrm{Window}\_\mathrm{Size}$,则设置$\mathrm{RCVD}\_\mathrm{HFN}=\mathrm{HFN}(\mathrm{RX}\_$SUBMIT)-1;</p>
</li>
<li><p>· $\cdot$ 若$\mathrm{RCVD}\_\mathrm{SN}\gt =\mathrm{SN}(\mathrm{RX}\_\mathrm{SUBMIT})-\mathrm{Window}\_\mathrm{Size}$,且 RCVD_SN&lt;SN(RX_SUBMIT)+Window_Size,则设置$\mathrm{RCVD}\_\mathrm{HFN}=\mathrm{HFN}(\mathrm{RX}\_\mathrm{SUBMIT})\text{。}$</p>
</li>
<li><p>——— 设置$\mathrm{RCVD}\_\mathrm{GFN}=[\mathrm{RCVD}\_\mathrm{HFN},\mathrm{RCVD}\_\mathrm{SN}]\text{。}$</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>若 LCPDU 的 GFN 值等于 RCVD_GFN,链路控制实体应执行以下操作。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 若配置加密和完整性校验,则使用$\mathrm{GFN}=\mathrm{RCVD}\_\mathrm{GFN}$ 对该PDU 执行解密和完整性校验。</p>
</li>
<li><p>——— 将完整性校验成功的PDU 存储在缓存中。</p>
</li></ul>

:::

:::{admonition} 注
:class: note

<p>如果已经成功接收过该 PDU 或 PDU 分段,或者该 PDU 或 PDU 分段的 SN 小于 SN(RX_SUBMIT),则丢弃该PDU。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 如果$\mathrm{RCVD}\_\mathrm{GFN}\gt =\mathrm{RX}\_\mathrm{NEXT}$,更新 RX_NEXT 为 RCVD_GFN+1。</p>
</li>
<li><p>——— 如果$\mathrm{RCVD}\_\mathrm{GFN}=\mathrm{RX}\_\mathrm{SUBMIT}$:</p>
</li>
<li><p>· $\cdot$若配置包头压缩,则执行包头解压缩;</p>
</li>
<li><p>· $\cdot$按照 GFN 值的正序,从$\mathrm{GFN}=\mathrm{RX}\_\mathrm{SUBMIT}$开始,将缓存中 GFN 值连续的若干个SDU一起递交到上层;</p>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>· $\cdot$将 RX_SUBMIT更新为没有递交到上层的第一个SDU 的 GFN 值,其中 GFN 值&gt;RX_SUBMIT。</p>
</li>
<li><p>——— 如果 T_RR在运行,且$\mathrm{RX}\_\mathrm{SUBMIT}\gt =\mathrm{RX}\_\mathrm{REORD}$,则重启 T_RR。</p>
</li>
<li><p>——— 如果 T_RR未运行,且 RX_SUBMIT&lt;RX_NEXT,则更新 RX_REORD 为 RX_NEXT,并重启 T_RR。</p>
</li></ul>

:::

(gbt-48336-201-2026-clause-7-3-2-2-2)=
#### 7.3.2.2.2 模式3数据传输

(gbt-48336-201-2026-clause-7-3-2-2-2-1)=
##### 7.3.2.2.2.1 模式3数据发送

:::{div}
:class: standard-paragraph

<p>在发送端,当接收到上层发送的数据传输请求时,链路控制实体应进行以下操作:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 若层间原语传递应用标识 AID,则确定上层业务数据包对应的业务类型;</p>
</li>
<li><p>——— 确定对应的 XQI标识;</p>
</li>
<li><p>——— 确定关联的逻辑信道标识。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>对于第一类业务:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 若配置加密功能,基于 GFN 对上层PDU 进行加密操作;</p>
</li>
<li><p>——— LCPDU 不包含完整性保护字段。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>链路控制实体遵循7.3.3.1的格式生成 LCPDU,并将其递交给下层。</p>

:::

(gbt-48336-201-2026-clause-7-3-2-2-2-2)=
##### 7.3.2.2.2.2 模式3数据接收

:::{div}
:class: standard-paragraph

<p>在接收端,当链路控制层接收到下层传递的传输模式3类型的数据时,链路控制实体应进行以下操作:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 若配置加密和完整性检查功能,则基于 GFN 进行解密和完整性检查操作;</p>
</li>
<li><p>——— 将该数据递交到上层。</p>
</li></ul>

:::

(gbt-48336-201-2026-clause-7-3-2-2-3)=
#### 7.3.2.2.3 重组和重排序时间

(gbt-48336-201-2026-clause-7-3-2-2-3-1)=
##### 7.3.2.2.3.1 t-RR超时执行流程

:::{div}
:class: standard-paragraph

<p>如果t-RR超时,接收端链路控制实体应向上层递交如下完整的SDU:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 所有 RCVD_GFN 值小于 RX_REORD的链路控制层完整SDU;</p>
</li>
<li><p>——— 从 RX_REORD开始的并且 RCVD_GFN 值连续的链路控制层完整SDU;</p>
</li>
<li><p>——— 更新 RX_SUBMIT为没有递交给上层的 RCVD_GFN 值大于或等于 RX_REORD 的第一个SDU 的 RCVD_GFN 值,其中 RCVD_GFN 值大于或等于 RX_REORD;</p>
</li>
<li><p>——— 如果 RX_SUBMIT&lt;RX_NEXT,更新 RX_REORD为 RX_NEXT并重启t-RR。</p>
</li></ul>

:::

(gbt-48336-201-2026-clause-7-3-2-2-3-2)=
##### 7.3.2.2.3.2 t-RR重配置过程

:::{div}
:class: standard-paragraph

<p>当t-RR正在运行时,如果高层重配置t-RR参数,接收端链路控制实体应更新 RX_REORD为RX_NEXT并重启t-RR。</p>

:::

(gbt-48336-201-2026-clause-7-3-2-3)=
### 7.3.2.3 ARQ功能

(gbt-48336-201-2026-clause-7-3-2-3-1)=
#### 7.3.2.3.1 重传

:::{div}
:class: standard-paragraph

<p>使用传输模式1的发送端链路控制实体可通过对端链路控制实体发送的状态报告获知对方是否成功接收SDU 或者SDU 分段的信息。当获知该信息时,发送端链路控制实体应执行以下操作。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 如果该SDU 的SN 大于或等于 TX_Next_Ack,并且小于或等于所有发送给下层的PDU 的最大的SN:</p>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>· $\cdot$确定该SDU 或者该SDU 的分段需要重传;</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>$\cdot \mathrm{RETX}\_\mathrm{GFN}+1$。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 如果$\mathrm{RETX}\_\mathrm{GFN}=\mathrm{maxRetxThreshold}$,通知高层已经到达最大重传次数。</p>
</li>
<li><p>——— 当重传一个SDU 或者SDU 分段时:</p>
</li>
<li><p>· $\cdot$根据需要,如果允许,对SDU 或者SDU 分段进行分段;</p>
</li>
<li><p>· $\cdot$产生可匹配当前传输机会的一个新的PDU;</p>
</li>
<li><p>· $\cdot$将这个新的PDU 发送给下层。</p>
</li>
<li><p>——— 当产生一个新的PDU 时:</p>
</li>
<li><p>· $\cdot$将初始的SDU 或者SDU 分段映射到该PDU 的数据字段中;</p>
</li>
<li><p>· $\cdot$根据7.3.3.1修改该PDU 的包头;</p>
</li>
<li><p>· $\cdot$根据7.3.3.1设置查询字段。</p>
</li></ul>

:::

(gbt-48336-201-2026-clause-7-3-2-3-2)=
#### 7.3.2.3.2 SDU 释放

:::{div}
:class: standard-paragraph

<p>当状态报告确认SDU 已正确接收,发送端链路控制实体需要释放该SDU 以及关联的 LCPDU。</p>

:::

(gbt-48336-201-2026-clause-7-3-2-4)=
### 7.3.2.4 状态报告查询和发送

(gbt-48336-201-2026-clause-7-3-2-4-1)=
#### 7.3.2.4.1 状态报告查询

:::{div}
:class: standard-paragraph

<p>状态报告查询只适用于使用传输模式1的链路控制实体。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 如果在PDU 内设置查询指示:</p>
</li>
<li><p>· $\cdot$将查询域设置为1;</p>
</li>
<li><p>· $\cdot$设置t-PollPeriod。</p>
</li>
<li><p>——— 当传输该PDU 时,将POLL_SN 设置为所有发送给下层的PDU 的最大SN 值。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>当接收 到 状态 报告 时,如 果状态 反馈 包 含 SN 为 POLL_SN 的 SDU 的接收 状态,且t-PollRetransmit在运行,则停止t-PollRetransmit。</p>

:::

:::{div}
:class: standard-paragraph

<p>当t-PollPeriod超时或t-PollRetransmit超时,发送端链路控制实体应触发状态报告查询。</p>

:::

(gbt-48336-201-2026-clause-7-3-2-4-2)=
#### 7.3.2.4.2 状态报告发送

:::{div}
:class: standard-paragraph

<p>状态报告只适用于传输模式1的链路控制实体。</p>

:::

:::{div}
:class: standard-paragraph

<p>一个链路控制实体向对端链路控制实体发送状态报告,提供SDU 是否成功接收的信息。</p>

:::

:::{div}
:class: standard-paragraph

<p>发起状态报告的触发条件包括:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 接收到对端链路控制实体发起的查询指示。</p>
</li></ul>

:::

:::{admonition} 注
:class: note

<p>允许在其他条件下向发送端主动发送状态报告。</p>

:::

:::{div}
:class: standard-paragraph

<p>当构造状态报告PDU 时,链路控制实体应进行以下操作。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 对于没有被完全接收的 SDU,从$\mathrm{SN}=\mathrm{SN}(\mathrm{RX}\_\mathrm{SUBMIT})$开始,按照 SN 的升序,并且按照SDU 内分段的升序,一直到生成的状态报告PDU 能够匹配下层指示的容量大小:</p>
</li>
<li><p>· $\cdot$对于没有任何分段被接收的SDU,在状态报告中添加 NACK_SN 字段,并将该字段设置为SN;</p>
</li>
<li><p>· $\cdot$对于有一部分分段被接收,但是有一段连续的字节分段没有被接收的SDU,在状态报告中添加一组 NACK_SN、SOstart和SOend字段。</p>
</li>
<li><p>——— 将 ACK_SN 设置为没有被 NACK_SN 指示为丢失且建议发送端不应清除缓存的首个 SDU的SN。</p>
</li></ul>

:::

(gbt-48336-201-2026-clause-7-3-2-5)=
### 7.3.2.5 链路控制层数据量计算

:::{div}
:class: standard-paragraph

<p>链路控制层数据量上报机制需要链路控制层进行缓存区数据量计算。T 节点应根据 G 节点的配置,周期或非周期发送该报告。当系统不配置周期值时,使用periodic-LCSR-Timer默认值。在计算缓存区数量时,考虑如下数据量:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— LCPDU;</p>
</li>
<li><p>——— 上层未提交给链路控制层的SDU;</p>
</li>
<li><p>——— 若为传输模式1,待重传的 LCPDU。</p>
</li></ul>

:::

(gbt-48336-201-2026-clause-7-3-2-6)=
### 7.3.2.6 完整性保护和校验

:::{div}
:class: standard-paragraph

<p>链路控制层执行完整性保护功能。完整性保护针对链路控制层数据类型 PDU 的全部内容,控制类型状态报告PDU 的全部内容,以及控制类型头压缩反馈 PDU 的全部内容。当安全上下文建立之后,应对信令面、控制面进行完整性保护,用户面的完整性保护可配置。</p>

:::

:::{div}
:class: standard-paragraph

<p>完整性保护和校验的方法以及相应的见9.3.5。</p>

:::

(gbt-48336-201-2026-clause-7-3-2-7)=
### 7.3.2.7 加密和解密

:::{div}
:class: standard-paragraph

<p>链路控制层执行加密和解密功能。加密和解密功能针对链路控制层数据类型 PDU 的数据部分,以及控制类型头压缩反馈PDU 的InterspersedROHCfeedback。当安全上下文建立之后,应对信令面、用户面和控制面头压缩反馈PDU 进行加密。</p>

:::

:::{div}
:class: standard-paragraph

<p>加密和解密功能以及相应的参数见9.3.5。其中,发送端和接收端基于 GFN 分别进行加密和解密。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于用户面和信令面数据,发送端维护独立的 GFN。对于 G 链路和 T 链路,发送端维护独立的 GFN。</p>

:::

:::{div}
:class: standard-paragraph

<p>每个逻辑信道维护各自的 GFN,当连接释放时,对于第一类业务的数据传输,发送端和接收端保存HFN+2;对于第二类业务的数据传输,发送端和接收端保存 GFN。</p>

:::

##### 7.3.3.1.3.7 PDU 序号字段

:::{div}
:class: standard-paragraph

<p>PDU 序号字段指示SDU 在分段时的序号,规则如下:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 首次分段的PDU 序号为1;</p>
</li>
<li><p>——— 当每一次对 SDU 进行新的分段而产生新的 PDU 时,该 PDU 序号为已有的最大 PDU 序号+1;</p>
</li>
<li><p>——— 当对已有的SDU 分段进行重传并对该SDU 分段再次分段而产生新的 PDU 时,该 PDU 序号为已有的 最大PDU 序号+1;</p>
</li>
<li><p>——— 当对已有的SDU 分段进行重传但不对该SDU 分段进行再次分段时,PDU 序号不变,直接重传已加密的PDU。</p>
</li></ul>

:::

<p>完整性保护字 段 为 可选 字 段,用 于对 数据 PDU 进行 完 整 性 保护,长 度 为 32bits、64bits或128bits。</p>

:::{div}
:class: standard-paragraph

<p>ACK_SN 字段指示在状态报告 PDU 中没有被报告为丢失且建议发送端不应清除缓存的首个SDU 的SN。当传输模式1的发送端链路控制实体接收到状态报告时,该接收端链路控制实体认为在状态报告中指示的除 NACK_SN 指示的SDU,NACK_SN 以及SOstart和SOend指示的SDU 的一部分,截止但不包括 ACK_SN 的SN 的SDU 都已经被对端传输模式1的实体成功接收。</p>

:::

(gbt-48336-201-2026-clause-7-3-3-1-3-10)=
##### 7.3.3.1.3.10 NACK\_SN 字段

:::{div}
:class: standard-paragraph

<p>NACK_SN 字段指示传输模式1的接收端链路控制实体已经检测到丢失的SDU(或者SDU 分段)的SN。</p>

:::

(gbt-48336-201-2026-clause-7-3-3-1-3-12)=
##### 7.3.3.1.3.12 SOstart字段

:::{div}
:class: standard-paragraph

<p>SOstart指示传输模式1的接收端链路控制实体中SN 是 NACK_SN 的SDU 中已经被检测为丢失的部分的第一个字节在初始SDU 中的位置。</p>

(gbt-48336-201-2026-clause-7-3-3-1-3-13)=
##### 7.3.3.1.3.13 SOend字段

:::{div}
:class: standard-paragraph

<p>当 E为010时SOend指示传输模式1的接收端链路控制实体中SN 是 NACK_SN 的SDU 中已经被检测为丢失的部分的最后一个字节在初始SDU 中的位置。</p>

:::

##### 7.3.3.1.3.14 预留字段

:::{div}
:class: standard-paragraph

<p>发送端链路控制实体需要将该字段设置为0,接收端链路控制实体应忽略该字段。</p>

:::

(gbt-48336-201-2026-clause-7-3-3-1-3-15)=
##### 7.3.3.1.3.15 ROHC反馈顺序号字段

:::{div}
:class: standard-paragraph

<p>ROHC反馈顺序号字段初始值为0。接收端链路控制实体在发送一个新的 ROHC 反馈数据包时,基于上次数值增加1并设置本次 ROHC反馈顺序号。当数值增加最大值15后翻转退回0。</p>

:::
