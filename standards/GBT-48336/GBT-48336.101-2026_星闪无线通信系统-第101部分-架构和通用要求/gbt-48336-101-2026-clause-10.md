(gbt-48336-101-2026-clause-10)=
# 10 系统安全通用要求

(gbt-48336-101-2026-clause-10-1)=
## 10.1 概述

:::{div}
:class: standard-paragraph

<p>为了保障端到端通信安全，星闪无线通信系统安全设计覆盖接入层，基础服务层和基础应用层。</p>

:::

:::{div}
:class: standard-paragraph

<p>其中在接入层，SLB 定义了星闪设备间 SLB 安全通信所需的信息安全特征，如认证凭证配置、双向认证、安全上下文协商和更新、传输数据信息安全保护、隐私保护等，提供了强认证鉴权和高信息安全的传输安全保护。同时，SLB 还定义了企业场景的安全认证流程，包括 EAP 认证、证书认证和自定义认证的方式。 SLE 定义了星闪设备间 SLE 安全通信所需的信息安全特征，如配对和鉴权、加密管理、隐私管理、加解密等，提供了数字比较、免输入、通行码输入、口令验证、带外方式和预配置密钥 PSK 等 6 种配对和鉴权方式。SLB 和 SLE 支持定位和感知能力。SLB 和 SLE 的定位技术支持物理层安全机制，基于随机参数产生测量波形，防止测量信号被伪造和非法用户接受测量信号。SLB 和 SLE 感知技术可在多天线场景下对感知信号进行加扰，防止非法用户窃听。接入层还定义了超宽带脉冲测量的安全机制，包括超宽带脉冲测量的密钥派生、测量子片段间隔随机生成、加扰序列生成等。</p>

:::

:::{div}
:class: standard-paragraph

<p>基础服务层的安全管理功能提供基础服务层的信息安全服务功能，包括安全连接管理、安全状态管理、授权管理、5G 融合安全管理等服务功能。</p>

:::

:::{div}
:class: standard-paragraph

<p>基础应用层也定义了相关的安全机制，以保障端到端的应用层传输安全。</p>

:::

(gbt-48336-101-2026-clause-10-2)=
## 10.2 接入层安全

:::{div}
:class: standard-paragraph

<p>SLB 接入层安全应符合 GB/T 48336.201—2026 中第 9 章的要求。</p>

:::

:::{div}
:class: standard-paragraph

<p>SLE 接入层安全应符合 GB/T 46803.2—2025 中第 7 章的要求。</p>

:::

(gbt-48336-101-2026-clause-10-3)=
## 10.3 基础服务层安全

(gbt-48336-101-2026-clause-10-3-1)=
### 10.3.1 概述

:::{div}
:class: standard-paragraph

<p>基础服务层的安全管理功能单元可提供基础服务层的网络安全服务功能，包括安全连接管理、安全状态管理、授权管理和 5G 融合安全管理等服务功能。</p>

:::

(gbt-48336-101-2026-clause-10-3-2)=
### 10.3.2 安全连接管理

:::{div}
:class: standard-paragraph

<p>安全连接过程在 SLB 中为认证和安全上下文协商流程，在 SLE 中为配对和鉴权流程。</p>

:::

:::{div}
:class: standard-paragraph

<p>安全连接服务为基础应用层应提供如下服务：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 建立安全连接；</p>
</li>
<li><p>—— 取消安全连接；</p>
</li>
<li><p>—— 安全连接状态查询；</p>
</li>
<li><p>—— 安全连接状态通知。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>其中建立安全连接服务用于向基础应用层提供和对端设备建立安全连接的功能，可根据对端设备地址和对端设备的能力建立安全连接。调用建立安全连接功能之后，设备启动和对端设备的安全连接和鉴权流程。安全管理功能单元负责传递接入层和用户界面之间的交互信息，如口令值、数字比较值、输入口令通知、用户确认通知、用户确认等。当安全连接失败或成功后，通过安全连接状态服务通知用户安全连接结果。</p>

:::

:::{div}
:class: standard-paragraph

<p>取消安全连接服务用于取消与对端设备的安全连接。调用取消安全连接服务后，获得的状态应包括：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 取消安全连接成功；</p>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 取消安全连接失败，地址不存在；</p>
</li>
<li><p>—— 取消安全连接失败，正在安全连接中。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>安全连接状态查询服务用于基础应用层查询和指定设备的安全连接的状态，状态应包括：安全连接中、安全连接失败和安全连接成功。</p>

:::

:::{div}
:class: standard-paragraph

<p>安全连接状态通知服务用于向基础应用层通知安全连接建立之后安全连接的状态。安全连接状态的通知方式应为注册⁃通知的方式。安全连接状态应包括：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 安全连接中；</p>
</li>
<li><p>—— 安全连接失败；</p>
</li>
<li><p>—— 安全连接成功。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>当安全连接失败时，可通知安全连接失败的原因，如：安全连接冲突、链路断开、鉴权失败等。</p>

:::

(gbt-48336-101-2026-clause-10-3-3)=
### 10.3.3 安全状态管理

:::{div}
:class: standard-paragraph

<p>安全状态管理应为基础应用层提供如下服务：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 安全状态查询；</p>
</li>
<li><p>—— 安全状态通知。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>其中安全状态查询服务用于基础应用层查询当前链路的安全状态信息，以确定当前链路的安全性是否满足要求，可包括如下内容：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 安全状态：包括加密和未加密状态、完整性保护和未完整性保护状态；</p>
</li>
<li><p>—— 安全算法：包括加密算法和完整性保护算法（如果安全开启的话）；</p>
</li>
<li><p>—— 链路状态：包括连接和断开；</p>
</li>
<li><p>—— 鉴权状态：包括未鉴权，鉴权中，已鉴权和鉴权方式。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>安全状态通知服务用于当链路的安全状态发生改变时，通知基础应用层来决策和处理。其中安全状态和状态参数定义见表 10。</p>

(gbt-48336-101-2026-clause-10-3-4)=
### 10.3.4 授权管理

:::{div}
:class: standard-paragraph

<p>当对端设备访问基础服务层的功能单元服务时，可能需要基础服务层的功能单元对该服务访问进行授权。基础服务层安全管理可将该授权请求发送给基础服务层的功能单元，基础服务层的功能单元可自行判断或者请求用户确定以得到授权结果。基础服务层的功能单元得到授权结果之后，可将该授权结果发送回基础服务层安全管理。基础服务层安全管理可保存该授权结果。基础服务层安全管理可为基础服务层的服务访问提供该授权结果。</p>

:::

:::{div}
:class: standard-paragraph

<p>当对端设备访问基础应用层的服务时，可能需要基础应用层对该服务访问进行授权。基础服务层安全管理可将该授权请求发送给基础应用层，基础应用层可自行判断或者请求用户确定以得到授权结果。</p>

:::

:::{div}
:class: standard-paragraph

<p>基础应用层得到授权结果之后，可将该授权结果发送回基础服务层安全管理。基础服务层安全管理可保存该授权结果。基础服务层安全管理可为基础应用层的服务访问提供该授权结果。</p>

:::

(gbt-48336-101-2026-clause-10-3-5)=
### 10.3.5 5G 融合安全管理

:::{div}
:class: standard-paragraph

<p>具有 5G 融合业务和非 5G 融合业务（普通业务）的 T 节点和 G 节点将存在三类 PSK，分别为非可信 5G⁃PSK、可信 5G⁃PSK 以及普通 PSK。</p>

:::

:::{div}
:class: standard-paragraph

<p>三类 PSK 使用原则如下：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 针对 5G 融合业务，使用 5G⁃PSK（非可信 5G⁃PSK 或可信 5G⁃PSK）；如果有可信 5G⁃PSK，则使用可信 5G⁃PSK；</p>
</li>
<li><p>—— 针对非 5G 融合业务，使用普通 PSK。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>G 节点和 T 节点进行业务时应根据 PSK 类型确定该连接的业务范围：基于非可信 5G⁃PSK 或可信5G⁃PSK 建立的连接（包括安全上下文）只能用于 5G 融合业务；基于普通 PSK 建立的连接（包括安全上下文）只能用于普通业务。</p>

:::

(gbt-48336-101-2026-clause-10-4)=
## 10.4 基础应用层安全

:::{div}
:class: standard-paragraph

<p>星闪无线通信系统设备可支持基础应用层传输安全机制。</p>

:::

:::{div}
:class: standard-paragraph

<p>基础应用层应具备会话安全保护机制（例如：使用随机生成会话 ID 等机制）。</p>

:::

:::{div}
:class: standard-paragraph

<p>基础应用层对外传输个人敏感信息时，应符合 GB/T 35273 的要求。</p>

:::

:::{div}
:class: standard-paragraph

<p>基础应用层发送个人敏感信息之前，应实现通信端之间的双向认证。</p>

:::
