(gbt-48336-101-2026-clause-11)=
# 11 设备安全通用要求

(gbt-48336-101-2026-clause-11-1)=
## 11.1 通则

:::{div}
:class: standard-paragraph

<p>星闪无线通信系统设备安全应满足硬件安全、软件安全、通信安全、数据安全和安全管理五类要求。</p>

:::

(gbt-48336-101-2026-clause-11-2)=
## 11.2 硬件安全

(gbt-48336-101-2026-clause-11-2-1)=
### 11.2.1 芯片安全

:::{div}
:class: standard-paragraph

<p>芯片安全满足如下要求：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 应具备芯片固件的物理写保护的功能，防止固件被篡改；</p>
</li>
<li><p>—— 芯片的硬件特征信息应与芯片固件绑定，如果芯片固件程序被篡改或更换，设备应能够停止加</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>载芯片固件程序并反馈异常信息；</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 宜具备安全芯片或硬件密码模块，物理保护设备密钥、证书等的安全；</p>
</li>
<li><p>—— 芯片宜具备固件读保护功能，防止固件被非法读取；</p>
</li>
<li><p>—— 宜支持安全启动，保障运行环境安全。</p>
</li></ul>

:::

(gbt-48336-101-2026-clause-11-2-2)=
### 11.2.2 接口安全

:::{div}
:class: standard-paragraph

<p>接口安全满足如下要求：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 调试接口应禁用或进行安全访问控制；</p>
</li>
<li><p>—— 如果具备摄像头、麦克风等隐私信息采集的传感器，默认处于关闭状态，并提供用户可控的开</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>关、直观便捷的状态指示；</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 对于具有控制台接口的设备，需配置用户名、口令等方式进行认证授权；</p>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 应禁用闲置的物理端口。</p>
</li></ul>

:::

(gbt-48336-101-2026-clause-11-2-3)=
### 11.2.3 防止物理攻击

:::{div}
:class: standard-paragraph

<p>防止物理攻击满足如下要求：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 设备密码模块应具备抵抗物理攻击能力；</p>
</li>
<li><p>—— 对于需要获取时间的设备，应支持与授权时间同步。</p>
</li></ul>

:::

(gbt-48336-101-2026-clause-11-2-4)=
### 11.2.4 密钥生成与保护

:::{div}
:class: standard-paragraph

<p>密钥生成与保护满足如下要求：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 使用到的随机数应符合随机数相关标准，保证由已验证、安全的随机数生成器产生；</p>
</li>
<li><p>—— 密钥应存储并运行于安全区域，无法被外部获取。</p>
</li></ul>

:::

(gbt-48336-101-2026-clause-11-2-5)=
### 11.2.5 加密运算安全

:::{div}
:class: standard-paragraph

<p>在整个加密周期中应保持加密运算的机密性，满足如下要求：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 本地加密密钥应被安全存储；</p>
</li>
<li><p>—— 非本地加密密钥在业务结束时应从本地销毁；</p>
</li>
<li><p>—— 加密运算过程中应防止密钥信息的泄露，确保密钥安全。</p>
</li></ul>

:::

(gbt-48336-101-2026-clause-11-3)=
## 11.3 软件安全

(gbt-48336-101-2026-clause-11-3-1)=
### 11.3.1 系统安全

:::{div}
:class: standard-paragraph

<p>系统安全满足如下要求：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 支持合法程序/固件版本更新机制，更新前应验证程序/固件包的合法性、完整性，高版本的才可</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>更新，发生更新失败时支持恢复到更新前的版本；</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 应默认关闭远程登录管理功能，即仅支持本地登录管理；</p>
</li>
<li><p>—— 应关闭不必要的服务及端口，避免被攻击和利用的风险；</p>
</li>
<li><p>—— 软件开发遵循安全编码流程，上线前应经过严格的漏洞扫描和渗透测试并对暴露的问题进行修</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>复处理；</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 应支持用户的身份验证、权限控制机制，保证正确的操作者身份和操作权限才可进行操作，并对</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>用户的操作进行日志审计；</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 应支持系统的备份和恢复机制，在本地系统损坏后可恢复原来备份的系统和数据、配置等；</p>
</li>
<li><p>—— 宜支持本地部署监测代理软件，监测本地软件执行过程并记录运行日志，如果出现异常则进行</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>上报并采取措施及时处理；</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 符合密码学要求，不应直接在代码中写入密钥。</p>
</li></ul>

:::

(gbt-48336-101-2026-clause-11-3-2)=
### 11.3.2 应用安全

:::{div}
:class: standard-paragraph

<p>应用安全满足如下要求。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 应在用户访问应用前，对其身份进行鉴别，并提供鉴别失败处理措施。</p>
</li>
<li><p>—— 应具备登录超时后的锁定或注销功能。</p>
</li>
<li><p>—— 当应用使用过程中涉及用户口令，应满足 11.6 中对口令的要求，还应满足如下要求：</p>
<ul class="standard-list">
<li><p>• 不应默认保存用户上次的账号及口令信息；</p>
</li>
<li><p>• 支持口令时效性检查机制，如提醒用户定期更换口令。</p>
</li></ul>
</li>
<li><p>—— 不应以明文形式存储用户敏感信息。</p>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 若具备数据删除功能，在删除数据前应明确提示用户，并由用户再次确认是否删除数据。</p>
</li>
<li><p>—— 不应存在已公开发布 6 个月以上的高危及以上等级漏洞。</p>
</li>
<li><p>—— 应用的运行不应长时间固定或无限制占用设备资源。</p>
</li>
<li><p>—— 不应存在非授权收集或泄露个人敏感信息、非授权数据外传等恶意行为。</p>
</li>
<li><p>—— 当应用软件支持升级时，应满足如下要求：</p>
<ul class="standard-list">
<li><p>• 应用软件应从安全合规的来源下载；</p>
</li>
<li><p>• 下载的应用软件应包含签名信息，且签名信息真实可信；</p>
</li>
<li><p>• 应用软件的升级应在用户授权的情况下进行，当升级行为不能保证设备系统、其他应用软件、软件本身的安全时，应在说明中明示用户可能带来的安全风险；</p>
</li>
<li><p>• 当应用软件升级失败时，应保证应用软件能保持在可用状态。</p>
</li></ul>
</li></ul>

:::

(gbt-48336-101-2026-clause-11-4)=
## 11.4 通信安全

:::{div}
:class: standard-paragraph

<p>通信安全满足如下要求：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 应支持对通信双方主体身份进行鉴别后建立通信连接；</p>
</li>
<li><p>—— 对于鉴权信息、隐私数据和重要业务数据等敏感信息，通信过程中应提供完整性保护和机密性保护等；</p>
</li>
<li><p>—— 应采用计数器、时间戳等机制防止重放攻击。</p>
</li></ul>

:::

(gbt-48336-101-2026-clause-11-5)=
## 11.5 数据安全

(gbt-48336-101-2026-clause-11-5-1)=
### 11.5.1 用户数据的收集

:::{div}
:class: standard-paragraph

<p>若设备出于业务需要收集用户个人信息，应在收集前明示收集的目的和范围，并且只有在用户同意的情况下方可继续，且应提供关闭数据收集功能。</p>

:::

(gbt-48336-101-2026-clause-11-5-2)=
### 11.5.2 用户数据的存储

:::{div}
:class: standard-paragraph

<p>用户数据的存储满足如下要求：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 宜支持数据按照类型选择不同的逻辑区域进行存储，可支持加密存储和逻辑隔离以及物理隔离（如安全芯片内），并设置不同的访问权限和身份验证；</p>
</li>
<li><p>—— 个人敏感信息应加密存储。</p>
</li></ul>

:::

(gbt-48336-101-2026-clause-11-5-3)=
### 11.5.3 用户数据的授权访问

:::{div}
:class: standard-paragraph

<p>设备应提供本地存储的用户数据的授权访问能力，防止未授权访问。</p>

:::

(gbt-48336-101-2026-clause-11-5-4)=
### 11.5.4 用户数据的转移

:::{div}
:class: standard-paragraph

<p>用户数据的转移满足如下要求：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 设备进行用户数据转移应按照约定目的和用途进行，传输数据之前应对双方进行身份认证和授权；</p>
</li>
<li><p>—— 若通过公共网络传输账户设置类、传感采集类、金融支付类用户个人信息时，应采用数字签名等技术手段保证数据的完整性和抗抵赖性，同时应采用密文方式传输；</p>
</li>
<li><p>—— 宜先对用户个人信息进行脱敏加工，消除能够识别特定个体的所有数据字段后再进行转移。</p>
</li></ul>

:::

(gbt-48336-101-2026-clause-11-5-5)=
### 11.5.5 用户数据的删除

:::{div}
:class: standard-paragraph

<p>销毁用户的个人敏感信息要遵循物理层面删除的原则，保证数据不可恢复。</p>

:::

(gbt-48336-101-2026-clause-11-6)=
## 11.6 安全管理

:::{div}
:class: standard-paragraph

<p>安全管理满足如下要求。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 运行安全管理服务统一进行安全管理，接收设备异常上报机制，并及时发现攻击和威胁。</p>
</li>
<li><p>—— 宜支持对设备进行安全策略管理，根据设备使用地点和安全要求进行动态配置，并支持按需</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>更新。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 对设备程序/固件等进行统一的版本管理、软件包签名、升级服务，保证软件更新的安全。</p>
</li>
<li><p>—— 安全管理和其他安全产品如防火墙、入侵检测系统、恶意代码监测等进行联动，及时发现网络攻</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>击和异常行为，并及时响应和处理。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 持续跟踪设备相关的硬件、软件漏洞公布信息和软件升级信息，并及时进行补救和缓解。</p>
</li>
<li><p>—— 定期对设备进行漏洞、病毒扫描和恶意代码检测等，检测设备内的程序、固件变动情况等，并对</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>运行日志进行异常检查等，及时发现问题并处理。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 应支持安全事件的安全日志记录功能。</p>
</li>
<li><p>—— 安全日志应进行安全存储，防止未授权的修改、删除、覆盖等。</p>
</li>
<li><p>—— 应支持如下密码算法安全要求：</p>
<ul class="standard-list">
<li><p>• 使用已验证、安全的加密算法和参数；</p>
</li>
<li><p>• 同一个密钥不复用于不同用途。</p>
</li></ul>
</li>
<li><p>—— 星闪无线通信系统使用口令时，应符合 GB/T 38626 的要求，并应满足如下要求：</p>
<ul class="standard-list">
<li><p>• 口令不能和账号或者账号的倒写一样；</p>
</li>
<li><p>• 若设置的口令不符合要求中的规则，则进行告警。</p>
<ul class="standard-list">
<li><p>——————————— </p>
</li></ul>
</li></ul>
</li></ul>

:::
