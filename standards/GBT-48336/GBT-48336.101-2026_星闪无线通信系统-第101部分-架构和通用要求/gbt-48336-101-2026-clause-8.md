# 8 基础服务层要求

(gbt-48336-101-2026-clause-8-1)=
## 8.1 设备发现

:::{div}
:class: standard-paragraph

<p>设备应通过运行设备发现功能单元的 DDP 实现设备信息的发布及扫描感知。按 GB/T 48336.301—2026 中 6.2 的要求，设备在执行设备发现过程中的角色应分为被发现方和发现方两类。具体角色由设备的设备发现主体决定并指示给基础服务层的设备发现功能单元，设备发现功能单元应负责该角色对应操作的执行。设备发现的主体可包括具备设备发现需求的基础应用层或者基础服务层功能单元。</p>

:::

:::{div}
:class: standard-paragraph

<p>当设备被设置为被发现方角色时，应根据基础应用层的要求通过设备发现功能单元公开自身的设备信息，以被其他设备发现。根据信息公开程度的差异，被发现方可被配置为不可见发现、一般可发现、优先可发现、仅允许被曾配对过的设备发现以及仅允许被指定设备发现这五种可发现等级中的一种。对于被发现方，其公开的自身设备信息可包括可发现等级、设备名称、厂商信息、媒体接入标识、服务信息等等。这些设备信息中的部分信息可通过接入层的消息承载，其他信息可通过基础服务层设备发现功能单元发送的消息承载。具体信息的发送方式可根据设备能力、使用的接入层类型及实现方案确定。</p>

:::

:::{div}
:class: standard-paragraph

<p>当设备被设置为发现方角色时，应根据设备发现主体的要求通过设备发现功能单元扫描发现其他设备。具体的，发现方的设备发现主体应向其设备发现功能单元提供过滤条件，以使设备发现功能单元过滤出设备发现需求主体感兴趣的被发现方。设备发现功能单元接收到过滤条件后，可独立执行过滤，也可配置接入层进行过滤（如果接入层支持），或者两者结合。</p>

:::

:::{div}
:class: standard-paragraph

<p>当接入层同时支持多种接入技术（例如，SLB 和 SLE）时，设备发现主体应向设备发现功能单元指示用于设备发现操作的具体星闪接入技术。</p>

:::

## 8.2 服务管理

(gbt-48336-101-2026-clause-8-2-1)=
### 8.2.1 概述

:::{div}
:class: standard-paragraph

<p>服务管理是基础服务层的核心功能单元之一，其可为基础应用层以及基础服务层提供包括服务注册、维护、删除等在内的设备内部服务管理功能。同时，不同星闪设备通过运行 SSAP 还可实现彼此之间的服务发现及交互。</p>

:::

:::{div}
:class: standard-paragraph

<p>如图 9 所示，服务管理定义了两种角色，即服务端和客户端。服务端是服务的承载方，接收和响应客户端的请求；客户端是服务的使用方，向服务端提交访问请求，获取并接收服务端返回的响应。</p>

(gbt-48336-101-2026-clause-8-2-2)=
### 8.2.2 服务的定义及表达

:::{div}
:class: standard-paragraph

<p>服务是指服务端公开的一组能力信息或功能集合。一个特定应用、原子能力或者基础服务层功能单元所能提供的完整功能可由一个或多个服务组成。例如一个家庭室内监测应用可由湿度检测服务和温度检测服务构成。</p>

:::

:::{div}
:class: standard-paragraph

<p>星闪无线通信系统定义了统一的表达格式来描述各类服务，这种表达格式称为服务结构。服务结构可由服务声明、服务引用、属性、方法、事件等结构成员构成，其中服务结构中应至少具备服务声明。各结构成员的定义见表 7。</p>

:::

:::{div}
:class: standard-paragraph

<p>服务按照类型可分为首要服务和次要服务，首要服务是可被服务端直接对外公开的服务。次要服务不能独立对外公开，需要被首要服务引用才可使用。</p>

(gbt-48336-101-2026-clause-8-3)=
## 8.3 QoS 管理

:::{div}
:class: standard-paragraph

<p>星闪无线通信系统的端到端 QoS 模型见图 11。</p>

:::

:::{div}
:class: standard-paragraph

<p>从控制面的角度，星闪无线通信系统需要维护的承载映射关系包括：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 业务流与 QoS 流的映射关系；</p>
</li>
<li><p>—— QoS 流与传输通道的映射关系；</p>
</li>
<li><p>—— 传输通道与逻辑信道的映射关系。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>其中，业务与 QoS 流之间的映射关系以及 QoS 流与传输通道的映射关系均由 QoS 管理功能单元进行维护，且 QoS 流仅为用于 QoS 管理的逻辑概念，不参与实际用户面传输的具体流程。因此，从用户面的角度星闪无线通信系统需要维护的承载映射关系包括：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 业务流与传输通道的映射关系；</p>
</li>
<li><p>—— 传输通道与逻辑信道的映射关系。</p>
</li></ul>

:::

```{image} ../../../assets/structured/GBT-48336.101-2026/regions/p0034-figure-01-93.png
:alt: 图 11　QoS 模型示意
:class: source-figure
:width: 427px
```

(gbt-48336-101-2026-figure-11)=
:::{div}
:class: standard-caption

<p>图 11　QoS 模型示意</p>

:::

:::{div}
:class: standard-paragraph

<p>为了满足业务数据传输的 QoS 需求，基础服务层应基于业务传输需求确定传输通道的 QoS 要求，并基于该要求建立相应的传输通道。QoS 功能单元应负责 QoS 要求的确定。具体的，当发送端的基础应用层或基础服务层功能单元有业务数据需要传输时，应将业务类型、端口号、业务关联的 QoS 参数等信息递交给 QoS 管理功能单元，发送端 QoS 管理功能单元基于接收到的参数与对端 QoS 管理功能单元进行传输所需的 QoS 参数协商。经过协商，每个对应的业务流（以端口号标识）都会被分配到一个QoS 流，并且获得传输所需的 QoS 参数。QoS 管理功能单元将协商后的 QoS 参数递交给连接管理功能单元，连接管理功能单元将基于该些参数启动传输通道的建立或更新。</p>

:::

:::{div}
:class: standard-paragraph

<p>QoS 流是 QoS 管理功能单元对业务数据进行管理的最小单位，以 Qos 流标识符进行标识。QoS 管理功能单元可将多个业务流配置到一个 QoS 流进行管理。其中，归属于同一个 QoS 流的业务流数据在传输层面会具备相同的 QoS 要求。QoS 流的划分属于逻辑概念，仅用于 QoS 管理单元的控制面管理使用，无需在数据传输时增加包头或者类型标识进行用户面的显示标识。从控制面管理的角度，QoS 流可用来做 QoS 映射关系管理、QoS 流监控等工作。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于星闪 5G 融合系统，QoS 管理功能单元可接收 5G 融合功能单元从 5G 网络获取的 QoS 策略，并使用该策略确定业务传输所需要的 QoS 要求。</p>

:::

(gbt-48336-101-2026-clause-8-4)=
## 8.4 连接管理

:::{div}
:class: standard-paragraph

<p>基础服务层的连接管理功能单元应负责传输通道的建立、维护、重配、释放等管理功能。</p>

:::

:::{div}
:class: standard-paragraph

<p>当 Qos 管理单元向连接管理功能单元递交 Qos 协商结果并指示建立传输通道或更新传输通道与业务流的映射关系时，连接管理功能单元应启动传输通道的建立或重配操作流程。</p>

:::

:::{div}
:class: standard-paragraph

<p>一般情况下，不同星闪设备之间可传递传输控制信令或中继控制信令（针对传输通道中继场景）来协商特定传输通道的配置信息。当基于信令协商来确定传输通道配置时，星闪设备的连接管理功能单元应在完成与对端星闪设备的信令交互后才可对指定的传输通道进行操作。</p>

:::

:::{div}
:class: standard-paragraph

<p>为了减少信令交互并提升通信效率，星闪无线通信系统还支持使用缺省方式来建立或释放传输通道。缺省方式的传输通道采用固定传输通道标识并具备默认的配置参数，可在接入层默认承载建立完成后直接激活并使用，并可在接入层链路释放后自动释放，不要求星闪设备间进行传输控制信令的交互。</p>

:::

:::{div}
:class: standard-paragraph

<p>使用缺省方式建立或释放的传输通道一般用于承载基础服务层各类功能单元的控制信令数据。</p>

:::

:::{div}
:class: standard-paragraph

<p>基础服务层可提供针对单播类业务和广播类业务的连接管理服务。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于同时支持 SLB 和 SLE 的星闪设备，基础服务层可提供基于 SLB 和 SLE 的融合传输服务。融合传输服务允许同时使用 SLB 逻辑信道和 SLE 逻辑信道为同一条传输通道中的数据进行冗余传输或分流传输、允许将一条传输通道对应的接入层技术从 SLB 切换到 SLE，或从 SLE 切换到 SLB。</p>

:::

:::{div}
:class: standard-paragraph

<p>基础服务层还可支持不同的 T 节点之间通过 G 节点进行传输通道中继通信。具体的，G 节点的基础服务层可为两个 T 节点身份的星闪设备提供数据转发服务，从而实现两个 T 节点之间的业务交互。</p>

:::

:::{div}
:class: standard-paragraph

<p>星闪基础服务层支持 T 节点与 T 节点之间通过 G 节点的数据转发形式（中继形式）实现通信。数据转发应由 G 节点基础服务层的数据与传输适配功能单元完成。</p>

:::

:::{div}
:class: standard-paragraph

<p>当 T1 节点希望通过 G 节点与 T2 节点进行传输通道中继通信时，T1 节点应先通过连接管理能力查询相关信令确认 G 节点支持中继能力。当 T1 节点确认 G 节点支持中继能力后，应通过 G 节点与 T2节点进行中继服务发现相关交互。经过中继服务发现，T1 节点和 T2 节点的基础应用层可获得彼此通信所需的端口、业务、QoS 需求等相关信息。基于这些参数信息，T1 节点、G 节点和 T2 节点基础服务层的连接管理功能单元通过中继控制信令的交互可建立 T1 节点与 T2 节点之间用于中继业务数据传输的中继业务传输通道。</p>

:::

:::{div}
:class: standard-paragraph

<p>每条中继业务传输通道应由两条子中继业务传输通道构成，分别用于承载 T1 节点和 G 节点、G 节点和 T2 节点之间的中继业务数据，见图 12。G 节点的连接管理功能单元应生成并维护传输通道映射关系表，映射关系表中的每一项记录应包括 T1 节点的媒体接入层标识、T2 节点的媒体接入层标识、TCIDx、TCIDy、TCIDi、TCIDj。</p>

:::

(gbt-48336-101-2026-clause-8-5)=
## 8.5 测量管理

:::{div}
:class: standard-paragraph

<p>在星闪无线通信系统中，测量管理功能单元应负责基础服务层以及接入层相关性能参数的测量以及状态监控。针对接入层，测量功能单元可支持采集包括 RSRP、RSSI、RSRQ、 SINR、误码率、收发速率、AoA 信息、AoD 信息、飞行时间信息等在内的物理层参数信息。针对基础服务层流模式或可靠模式下的传输通道，测量功能单元可支持测量端到端时延、抖动等性能指标。</p>

:::

:::{div}
:class: standard-paragraph

<p>测量功能单元应为其他功能单元（如 QoS 管理功能单元、5G 融合功能单元等）或授权应用提供统一的测量服务接口，应允许其他功能单元或授权应用向测量管理功能单元提供期望测量的配置信息，并对测量结果进行查询。</p>

:::

:::{div}
:class: standard-paragraph

<p>针对接入层的物理层参数，测量功能单元应通过跨层原语交互的方式触发并获取。跨层原语可包括物理层参数查询请求、物理层参数上报、物理层参数查询取消以及物理层参数查询取消确认等。</p>

## 8.6 多域协调与管理

:::{div}
:class: standard-paragraph

<p>多域协调与管理是星闪无线通信系统基础服务层为 G 节点提供的一项服务功能，可用于：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 相邻 G 节点进行通信域资源协调或管理交互，实现资源管理、干扰协调等目的；</p>
</li>
<li><p>—— 多个通信域的协同工作，例如进行联合测距等。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>多个支持多域协调与管理功能的 G 节点可组成多域组。多域协调与管理按照工作模式的不同，分为管理模式和非管理模式。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 管理模式：多域组内的 G 节点间存在从属关系，分为多域管理节点和多域成员节点。多域管理节点应具备对多域成员节点的控制管理功能，多域成员节点应严格服从多域管理节点的管理。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>多域成员节点如果无法执行多域管理节点的信令，应及时向多域管理节点进行反馈。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 非管理模式：多域组内的 G 节点之间不存在严格的从属关系，可通过协商或者建议的方式进行多域信息的协调。不要求其中一方严格服从另一方的管理。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>支持多域协调与管理功能的 G 节点应至少支持非管理模式，可选支持管理模式。</p>

:::

:::{div}
:class: standard-paragraph

<p>为了实现多域协调与管理，G 节点应执行多域设备发现，多域设备连接、多域服务发现、多域信令交互等主要步骤。</p>

:::

:::{div}
:class: standard-paragraph

<p>多域设备发现主要用于广播自身设备信息或者扫描发现周围的邻居 G 节点。当 G 节点开启多域协调与管理功能，并且接入层以 G 节点身份广播设备信息时（此时，对应的设备发现角色为被发现方），宜尽量携带可显式指示其具备多域协调与管理功能的设备信息。当 G 节点决定扫描周围 G 节点的设备信息时（此时，对应的设备发现角色为发现方），接入层应使用 T 节点身份。扫描冲突解决模式可用来避免因相邻 G 节点同时在接入层使用 T 节点身份扫描而引发多域设备发现失败。</p>

:::

:::{div}
:class: standard-paragraph

<p>多域设备连接遵循星闪无线通信系统通用的连接管理操作。设备之间的连接建立应由发起方的多域协调与管理功能单元触发，并由连接管理功能单元执行。</p>

:::

:::{div}
:class: standard-paragraph

<p>多域服务发现可用来确认对端节点是否支持多域协调与管理服务、交互多域能力以及确定多域协调与管理模式。根据多域服务发现的角色不同，G 节点可分为客户端 G 节点和服务端 G 节点。对于支持多域协调与管理的 G 节点，当作为服务端 G 节点时应按照多域协调与管理服务结构定义服务。</p>

:::

:::{div}
:class: standard-paragraph

<p>经过多域服务发现并确认多域协调与管理模式和角色后，G 节点之间可通过交互多域协调与管理信令的方式来执行多个通信域的具体协商和管理操作。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于非管理模式，本端 G 节点可将自身使用的接入层技术类型、载波信道和半静态资源信息告知对端 G 节点。此外，本端 G 节点还可向对端 G 节点发送邻区扫描指示信息，用于辅助对端 G 节点的多域设备发现。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于管理模式，多域管理节点可为多域成员节点配置可用载波信道以及不同载波信道上的半静态资源。多域成员节点应严格按照多域管理节点的配置信息进行资源配置。为了让多域管理节点更好地获知多域成员节点对应通信域的资源使用情况，多域成员节点可向多域管理节点发送通信域资源报告消息，上报当前使用的载波信道、半静态资源以及业务等信息。多域管理节点和多域成员节点之间也可执行邻区扫描信息的交互，辅助对端节点的多域设备发现。此外，管理模式下的多域管理节点和多域成员节点之间还可支持联合测距功能。</p>

:::

(gbt-48336-101-2026-clause-8-7)=
## 8.7 5G 蜂窝网络融合

:::{div}
:class: standard-paragraph

<p>星闪无线通信系统和 5G 蜂窝网构成的整体网络系统称为星闪 5G 蜂窝网络融合（简称“星闪 5G 融合”或“5G 融合”）系统。</p>

:::

:::{div}
:class: standard-paragraph

<p>根据星闪无线通信系统和 5G 蜂窝网之间交互所涉及的网元类型及功能不同，整体系统可分为如下两种。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 类型一：5G 核心网支持对星闪无线通信系统覆盖下 G 节点和 T 节点进行设备感知和交互。其中，T 节点的 5G 融合功能单元具备 NAS 功能，G 节点为可信管理节点且具备 5G 融合功能单元。</p>
</li>
<li><p>—— 类型二：5G 核心网仅支持对星闪无线通信系统覆盖下 G 节点进行设备感知和交互。其中，G节点为可信管理节点且具备 5G 融合功能单元。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>从控制面角度，5G 核心网根据能力不同，可仅管理其覆盖下的 T 节点和 G 节点之间的短距通信；也可管理其覆盖下的 T 节点或 G 节点与 5G 核心网之间的远端通信。</p>

:::

:::{div}
:class: standard-paragraph

<p>5G 核心网可为其覆盖下的一个或多个星闪无线通信网络提供统一的网络管理服务，其中每个星闪无线通信网络包含至少一个可信 G 节点和若干 T 节点。</p>

:::

:::{div}
:class: standard-paragraph

<p>5G 融合功能单元可负责所属星闪通信设备与星闪 5G 融合系统中的其他网元的控制面交互（例如注册、身份认证，Qos 策略管理和传输状态管理等），也可负责与所属星闪通信设备内的其他功能单元进行 5G 融合相关的操作交互（例如，将 5G 核心网配置的 QoS 策略推送给 QoS 管理功能单元，或触发测量功能单元执行 5G 融合所需的测量）。</p>

:::

:::{div}
:class: standard-paragraph

<p>在星闪 5G 融合系统中，T 节点为了获取 5G 融合服务，应首先选择支持 5G 融合服务的可信 G 节点进行接入。对于一个支持 5G 融合服务的 G 节点，T 节点通过服务发现操作可获得该 G 节点支持的公用陆地移动网络、移动运营商核心网连接类型、回传类型等信息。T 节点可将感兴趣的 G 节点作为候选可信 G 节点，并可从中选择优先级最高的 G 节点作为可信 G 节点。当 T 节点接入到可信 G 节点后，根据星闪 5G 融合系统类型的不同，T 节点可进行注册、去注册、会话建立、会话修改、会话释放、QoS 策略管理和状态管理等操作。</p>

:::

(gbt-48336-101-2026-clause-8-8)=
## 8.8 网络功能

:::{div}
:class: standard-paragraph

<p>网络功能位于基础服务层，可包括拓扑配置协议、无线邻居协议、多跳组网安全、无线网络协议、路由协议、网络服务发现与访问、网络错误与诊断、网络节能等内容。在具体的实施中，涉及的协议或功能可选择性的部署或实现。</p>

:::

:::{div}
:class: standard-paragraph

<p>网络功能可包括：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 无线网络接口：接入层实体（如 SLB/SLE 等）通过网络功能的输入/输出（I/O）操作对象，通过该接口进行报文收发，以及对接入层实体状态、属性、统计值（如收发报文量等）进行读写；</p>
</li>
<li><p>—— 无线网络协议：定义了星闪网络报文格式、网络地址分配、多跳转发机制、网络安全功能（认证&amp;加密）等；</p>
</li>
<li><p>—— 无线网络广播协议：定义星闪网络广播机制，可支持可靠性广播协议和非可靠性广播协议；</p>
</li>
<li><p>—— 无线网络组播协议：定义星闪网络组播机制，可支持可靠性组播协议和非可靠性组播协议；</p>
</li>
<li><p>—— 无线网络控制协议：可用于在星闪网络节点间传递控制消息，测量或诊断网络可达性、丢包、时延等，以及实现部分网络控制功能，例如路由控制；</p>
</li>
<li><p>—— 拓扑配置协议：定义星闪网络拓扑动态构建的流程，可用于待入网节点发现网络、接入网络；</p>
</li>
<li><p>—— 无线邻居协议：定义星闪网络设备间的邻居动态发现，以及维护设备邻居关系，无线邻居协议可用于发现和管理邻居节点；</p>
</li>
<li><p>—— 地址配置协议：定义星闪网络地址动态分配协议；</p>
</li>
<li><p>—— 多种路由协议，可包括静态路由协议、S⁃AODV、S⁃RPL、星闪链路状态路由协议等；</p>
</li>
<li><p>—— 无线资源预留协议：可按需为业务计算满足其 QoS 要求的端到端转发路径；</p>
</li>
<li><p>—— 服务与地址解析协议：管理服务名/服务 UUID 与星闪网络地址映射关系，可用于查询服务的网络地址信息。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>对于一个网络节点，应执行以下的步骤来完成多跳组网，实现数据传输：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 发现网络；</p>
</li>
<li><p>—— 加入网络，建立网络邻居，获取网络密钥；</p>
</li>
<li><p>—— 获取网络地址；</p>
</li>
<li><p>—— 生成路由表；</p>
</li>
<li><p>—— 完成服务发现和服务访问；</p>
</li>
<li><p>—— 传输业务流量。</p>
</li></ul>

:::

## 8.9 传输功能

:::{div}
:class: standard-paragraph

<p>传输功能可接收基础应用层向下递交的应用数据，封装传输功能报文头，并向下递交给传输承载通道。传输承载的通道支持由星闪网络功能生成的多跳路径，也可支持基础服务层传输与适配功能生成的传输通道。星闪传输功能可支持无连接的非可靠传输协议（例如，CLTP）和面向连接的可靠传输协议（例如，LWCTP）。</p>

:::

:::{div}
:class: standard-paragraph

<p>传输功能通过端口号区分不同应用，源端口号指示本设备的源应用，目的端口号指示对端设备的目的应用。其中，LWCTP 还可通过发送序列号与确认序列号，支持源应用和目的应用间的可靠传输。</p>

:::

:::{div}
:class: standard-paragraph

<p>LWCTP 可支持完整的连接状态切换和生命周期控制，数据传输的一个完整生命周期，分为传输开始、传输数据、传输结束三个阶段。LWCTP 对传输的两个方向解耦，每一个方向都可按需启动和结束数据传输，以实现单工或全双工通信。</p>

:::

:::{div}
:class: standard-paragraph

<p>LWCTP 可支持延迟确认与合并确认，批量传输数据时，接收端可分配缓存区资源，对接收的报文进行顺序缓存。接收端可在延时一定时间，对接收的报文进行确认，确认序列号填写已接收的连续报文的序列号的最大值。</p>

:::

:::{div}
:class: standard-paragraph

<p>LWCTP 可支持流量控制和过载控制，接收端将接收窗口通告发送端使发送端调整发送速率或暂停传输。</p>

:::
