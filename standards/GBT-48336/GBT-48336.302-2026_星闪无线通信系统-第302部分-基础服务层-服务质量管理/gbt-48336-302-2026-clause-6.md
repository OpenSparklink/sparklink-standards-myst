# 6 QoS管理通用处理

(gbt-48336-302-2026-clause-6-1)=
## 6.1 概述

:::{div}
:class: standard-paragraph

<p>QoS管理通用处理基于 QoS模型对接收的服务传输请求进行以下操作:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 获取用于 QoS流的星闪 QoS参数;</p>
</li>
<li><p>——— 将业务流映射到匹配的 QoS流;</p>
</li>
<li><p>——— 基于星闪 QoS参数建立、重配置或释放 QoS流,为建立、重配置或释放传输通道提供依据。</p>
</li></ul>

:::

(gbt-48336-302-2026-clause-6-2)=
## 6.2 QoS模型

:::{div}
:class: standard-paragraph

<p>星闪无线通信系统使用图1所示的 QoS模型,该模型适用于基础服务层内单播、组播或广播数据的传输。</p>

:::

:::{div}
:class: standard-paragraph

<p>QoS流是 QoS管理功能单元对业务流处理的最小单位。QoS流用于对业务流进行分类与标记,对数据包不做拆分、组装或修改。</p>

:::

:::{div}
:class: standard-paragraph

<p>多个业务流可映射到多个不同 QoS流,也可映射到同一个 QoS流,映射关系取决于 QoS规则配置。应保证最多16个业务流映射到同一个 QoS流。</p>

:::

:::{div}
:class: standard-paragraph

<p>多个 QoS流可映射到多个不同传输通道,也可映射到同一个传输通道,映射关系取决于具体实现方式。</p>

:::

:::{div}
:class: standard-paragraph

<p>每个 QoS流关联一组星闪 QoS参数,星闪 QoS参数的相关内容见第7章。可配置一组默认星闪QoS参数,满足基础服务层各功能单元的基本通信需求。</p>

:::

:::{div}
:class: standard-paragraph

<p>QoS流没有方向,但 QoS规则有方向。例如,星闪设备1与星闪设备2已建立 QoS流1,QoS流1已关联 QoS规则1,该规则包含了星闪设备2的目的端口port1。因此,所有由星闪设备1发送到星闪设备2目的端口port1的数据归属于 QoS流1,而星闪设备2发送到星闪设备1目的端口port1的数据不归属于 QoS流1。</p>

:::

(gbt-48336-302-2026-clause-6-3)=
## 6.3 QoS规则

:::{div}
:class: standard-paragraph

<p>QoS规则用于业务流与 QoS流的关联和映射,包含数据包映射规则集和默认 QoS规则。可预先配置 QoS规则,或通过 QoS管理功能单元控制信令实时生成 QoS规则。</p>

:::

:::{div}
:class: standard-paragraph

<p>数据包映射规则集由一个或多个数据包映射规则组成,各规则之间应是“或”的关系,每个规则包含以下一个或多个信息。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— AID:指示一种具体类型的应用。AID 使用方法应遵循附录 A 的规定。</p>
</li>
<li><p>——— srcPort:星闪业务流的源端口号。</p>
</li>
<li><p>——— dstPort:星闪业务流的目的端口号。</p>
</li>
<li><p>——— srcIPAddr:IP应用业务流的源IP地址。</p>
</li>
<li><p>——— dstIPAddr:IP应用业务流的目的IP地址。</p>
</li>
<li><p>——— srcIPPort:IP应用业务流的源端口号。</p>
</li>
<li><p>——— dstIPPort:IP应用业务流的目的端口号。</p>
</li>
<li><p>——— protocolType:IP应用的传输层协议标识。</p>
</li>
<li><p>——— DSCP:IP应用业务的差分服务代码点。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>多个 QoS规则可与同一个 QoS流关联。</p>

:::

:::{admonition} 示例
:class: tip

<p>一个 QoS流关联的数据包映射规则集若包含以下几个数据包映射规则,数据包满足任意一条规则即可映射到该QoS流:</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— $\mathrm{AID}=1,\mathrm{srcPort}=1,\mathrm{dstPort}=2;$</p>
</li>
<li><p>——— $\mathrm{AID}=2,\mathrm{dstPort}=2;$</p>
</li>
<li><p>——— $\mathrm{dstPort}=3;$</p>
</li>
<li><p>——— $\mathrm{srcPort}=5\text{。}$</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>当基础服务层收到两个数据包,分别包含[AID1,srcPort1,dstPort2]和[dstPort3]信息,依据上述规则,这两个数据包应归属于同一个 QoS流。</p>

:::

:::{div}
:class: standard-paragraph

<p>星闪设备应包含一个默认 QoS规则,与默认 QoS流关联,该默认 QoS流使用默认 QoS参数。默认 QoS规则在成对设备内应唯一,可允许所有数据包映射到默认 QoS流。对于不匹配任何数据包映射规则集的数据包,使用默认 QoS规则进行处理。</p>

:::

(gbt-48336-302-2026-clause-6-4)=
## 6.4 QoS流标识

:::{div}
:class: standard-paragraph

<p>QoS流通过2字节的 QFI进行标识。QoS管理功能单元负责分配和释放 QFI,应遵循以下两个规则。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 成对设备之间共享 QFI空间,不同应用的 QFI不应重复。例如在图2中,星闪设备1为应用1分配 QFI1,星闪设备2为应用2分配 QFI2和 QFI3,应用2不能使用应用1已经分配的QFI1。</p>
</li>
<li><p>——— 不同成对设备之间的 QFI空间独立分配,互不干扰。例如设备1 和设备3 之间仍可分配QFI1和 QFI2。</p>
</li></ul>

## 6.5 服务传输请求处理

(gbt-48336-302-2026-clause-6-5-1)=
### 6.5.1 服务传输请求处理流程

:::{div}
:class: standard-paragraph

<p>QoS管理功能单元针对服务传输请求的处理流程见图3,包括以下步骤。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 接收包含业务 QoS参数的服务传输请求。</p>
</li>
<li><p>b) 基于业务 QoS参数推导并获取星闪 QoS参数(见6.5.2)。</p>
</li>
<li><p>c) 如果服务传输请求指示使用独立传输通道(见10.1),则建立新的 QoS流和传输通道。</p>
</li>
<li><p>d) 否则,判断现有 QoS流是否满足该星闪 QoS流参数:</p>
<ol class="decimal-list" start="1">
<li><p>1) 如果满足,将服务传输请求指示的业务流映射到现有 QoS流;</p>
</li>
<li><p>2) 否则,建立新的 QoS流。</p>
</li></ol>
</li>
<li><p>e) 针对新建或更新的 QoS流,判断现有传输通道是否满足该 QoS流的 QoS需求:</p>
<ol class="decimal-list" start="1">
<li><p>1) 如果满足,使用相关连接管理接口原语更新该 QoS流与传输通道映射关系,或更新传输通道的星闪 QoS参数;</p>
</li>
<li><p>2) 否则,使用相关连接管理接口原语建立新的传输通道。</p>
</li></ol>
</li></ol>

:::

(gbt-48336-302-2026-clause-6-5-2)=
### 6.5.2 星闪 QoS参数获取

:::{div}
:class: standard-paragraph

<p>当接收到服务传输请求时,星闪设备的 QoS管理功能单元可通过两种方式获取星闪 QoS参数。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 当已接入5G 核心网时,可从5G 融合功能单元获取星闪 QoS参数。</p>
</li>
<li><p>——— 否则,按以下步骤推导并获取星闪 QoS参数:</p>
<ul class="standard-list">
<li><p>• 如果基础应用层或基础服务层特定功能单元提供业务 QoS参数,则根据业务 QoS参数确定星闪 QoS参数;</p>
</li>
<li><p>• 否则,根据表3将 AID 或 DSCP映射到SLQI以确定星闪 QoS参数。</p>
</li></ul>
</li></ul>

:::

:::{admonition} 注
:class: note

<p>根据业务 QoS参数推导并获取星闪 QoS参数取决于具体实现方式。例如,如果业务优先级为3,可选择星闪标准 QoS参数列表中优先级为3的SLQI作为星闪 QoS参数。</p>

:::

(gbt-48336-302-2026-clause-6-5-3)=
### 6.5.3 QoS流配置

:::{div}
:class: standard-paragraph

<p>获取星闪 QoS参数后,星闪设备应判断当前 QoS流是否满足星闪 QoS参数要求以进行 QoS流配置,可能存在以下情况和相应的处理流程。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 如果存在满足要求的 QoS流,服务传输请求所关联的业务流由该 QoS流负责传输。通过添加一条 QoS规则实现业务流映射到该 QoS流。</p>
</li>
<li><p>——— 如果没有满足要求的 QoS流,应基于该星闪 QoS参数新建一条 QoS流。</p>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 如果指示使用独立传输通道传输业务流,应新建一条 QoS流,并将业务流映射到该 QoS流。</p>
</li></ul>

:::

:::{admonition} 注
:class: note

<p>如果有多条 QoS流可同时满足星闪 QoS参数,映射到哪条 QoS流取决于具体实现方式。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于单播业务,本端设备与对端设备应通过交互 QoS管理信令以新建或重配置 QoS流,具体的信令流程见8.2。</p>

:::

:::{div}
:class: standard-paragraph

<p>对于广播或组播业务,无需与对端交互 QoS 管理信令,根据上述流程实现新建或更新 QoS 流即可。</p>

:::

(gbt-48336-302-2026-clause-6-5-4)=
### 6.5.4 传输通道建立与更新

:::{div}
:class: standard-paragraph

<p>完成 QoS流配置后,QoS管理功能单元通过连接管理接口原语建立或重配置传输通道,完成业务流到传输通道的映射关系(见8.4)。</p>

:::

(gbt-48336-302-2026-clause-6-7)=
## 6.7 QoS流监控

:::{div}
:class: standard-paragraph

<p>QoS管理功能单元对 QoS流的传输性能进行监控,传输性能参数包括但不限于传输的时延、丢包率等。</p>

:::

:::{div}
:class: standard-paragraph

<p>QoS流监控依赖于获取 QoS流的 QoS测量结果,包括但不限于时延、丢包率等。本文件规定以下三种 QoS测量方法,具体内容见8.3。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 基于 QoS测量帧的 QoS 测量:即本端 QoS 管理功能单元与对端 QoS 管理功能单元交互QoS测量请求和 QoS测量响应信令。</p>
</li>
<li><p>——— 基于增强帧的 QoS测量:即在业务传输通道数据帧中包含用于 QoS测量的字段。</p>
</li></ul>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 基于测量管理的 QoS测量:即从本端测量管理功能单元获取测量结果。</p>
</li></ul>

:::

:::{admonition} 注
:class: note

<p>QoS测量结果的测量对象粒度包括 QoS流和传输通道。例如,在本文件中使用测量功能单元获取的测量结果为传输通道粒度,如果多个 QoS流映射到同一个传输通道,则该传输通道 QoS测量结果可被近似视为多个QoS流的 QoS测量结果,不体现具体一条 QoS流的传输性能。</p>

:::

:::{div}
:class: standard-paragraph

<p>在获取到 QoS流的 QoS测量结果之后,QoS管理功能单元会基于测量结果执行以下一个或多个操作,实现动态 QoS控制。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 使用8.2中描述的步骤更新或释放某一个特定的 QoS流。</p>
</li>
<li><p>——— 使用8.4中描述的步骤更新或删除某一个 QoS流到传输通道的映射关系。</p>
</li>
<li><p>——— 使用8.4中描述的步骤释放某一个传输通道。</p>
</li>
<li><p>——— 当接入5G 核心网时,通知5G 融合功能单元某 QoS流的 QoS需求无法满足。</p>
</li></ul>

:::
