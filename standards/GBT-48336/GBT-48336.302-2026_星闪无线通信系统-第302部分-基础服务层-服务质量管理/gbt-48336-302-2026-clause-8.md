# 8 QoS管理流程

(gbt-48336-302-2026-clause-8-1)=
## 8.1 概述

:::{div}
:class: standard-paragraph

<p>QoS管理流程定义了 QoS管理功能单元实现 QoS流配置、QoS流测量和动态 QoS控制等流程。</p>

:::

:::{div}
:class: standard-paragraph

<p>不同星闪设备之间的 QoS 管理功能单元进行信令交互的方式涉及非中继场景和中继场景。例如,在非中继场景下,星闪设备1和星闪设备2可直接交互 QoS管理信令,如图5所示。在中继场景下,星闪设备1和星闪设备2通过中继设备实现 QoS管理信令的转发和交互,如图6所示。</p>

(gbt-48336-302-2026-clause-8-2)=
## 8.2 QoS流配置

:::{div}
:class: standard-paragraph

<p>在发起 QoS流配置前,接入层应已建立默认承载,基础服务层通用管理传输通道应已建立并激活。</p>

:::

:::{div}
:class: standard-paragraph

<p>QoS流配置涉及以下交互信令,交互流程见图7。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 新建一个 QoS流时,使用 Qos_Establish_Req信令和 Qos_Establish_Rsp信令(见9.2和9.3)。</p>
</li>
<li><p>——— 重配置一个 QoS流时,包括更新关联数据包映射规则或星闪 QoS参数,使用 Qos_Reconfig_Req信令和 Qos_Reconfig_Rsp信令(见9.6和9.7)。</p>
</li>
<li><p>——— 释放一个 QoS流时,使用 Qos_Release_Req信令和 Qos_Release_Rsp信令(见9.4和9.5)。</p>
</li></ul>

:::

## 8.3 QoS测量

(gbt-48336-302-2026-clause-8-3-1)=
### 8.3.1 基于 QoS测量帧的 QoS测量

:::{div}
:class: standard-paragraph

<p>QoS管理功能单元使用 QoS测量帧对通用管理传输通道进行 QoS流测量,本文件仅定义使用该方法进行 QoS流时延性能的测量流程。</p>

:::

:::{div}
:class: standard-paragraph

<p>QoS测量帧包括 Qos_Meas_Req(见9.8)和 Qos_Meas_Rsp(见9.9)。该信令应由通用管理传输通道传输,其信令交互流程见图8。QoS测量方法描述如下:</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a) 星闪设备1的 QoS管理功能单元发送 Qos_Meas_Req信令,并记录该时刻对应的时间戳1;</p>
</li>
<li><p>b) 星闪设备2的 QoS管理功能单元接收该信令后立即反馈 Qos_Meas_Rsp信令;</p>
</li>
<li><p>c) 星闪设备1的 QoS管理功能单元接收到 Qos_Meas_Rsp信令并记录该时刻对应的时间戳2,通过计算时间戳1和时间戳2的差值获得双向时延。</p>
</li></ol>

:::

:::{admonition} 注
:class: note

<p>时间戳格式不在本文件定义范围,取决于具体实现方式。</p>

:::

:class: standard-diagram

```{mermaid}

  participant B as 星闪设备2<br/>QoS管理
  A->>B: Qos_Meas_Req
  B->>A: Qos_Meas_Rsp
```

:::{div}
:class: standard-paragraph

<p>QoS流传输性能测量扩展字段的定义见图10,扩展字段具有以下结构。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 扩展字段类型:1字节,取值应符合 GB/T48336.301—2026中8.5.3的规定。</p>
</li>
<li><p>——— 扩展字段长度:1字节,指示可变字段PM Data的实际长度。</p>
</li>
<li><p>——— PM Bitmap:2字节,指示可变字段PM Data包含的信息。当某比特位为1时,表示对应信息包含在PM Data字段中;当某比特位为0时,表示对应信息不存在。具体定义如下:</p>
<ul class="standard-list">
<li><p>• bit0:前向发送LCID和前向接收LCID(2字节),发送LCID占高字节,接收LCID占低字节;</p>
</li>
<li><p>• bit1:前向帧发送序列号(4字节);</p>
</li>
<li><p>• bit2:前向帧发送时间戳(8字节);</p>
</li>
<li><p>• bit3:前向帧接收时间戳(8字节);</p>
</li>
<li><p>• bit4:反向发送LCID和反向接收LCID(2字节),发送LCID占高字节,接收LCID占低字节;</p>
</li>
<li><p>• bit5:反向帧发送序列号(4字节);</p>
</li>
<li><p>• bit6:反向帧发送时间戳(8字节);</p>
</li>
<li><p>• bit7:反向帧接收时间戳(8字节);</p>
</li>
<li><p>• bit8:节点接收队列长度(4字节);</p>
</li>
<li><p>• 其他:预留。</p>
</li></ul>
</li>
<li><p>——— PM Data:可变长度,根据PM Bitmap由低到高置1的比特位,依次包含对应信息。例如,当PM Bitmap中bit0和bit1置1时,PM Data包含的信息依次为前向发送 LCID 和前向接收LCID(2字节)、前向帧发送序列号(4字节)。</p>
</li></ul>

:::

### 8.3.3 基于测量管理的 QoS测量

:::{div}

<p>除8.3.1 和 8.3.2 定义的两种 QoS 测量方法外,星闪设备还可使用测量管理功能单元提供的QoS测量服务。QoS管理功能单元通过测量管理功能单元接口原语获得指定传输通道的性能测量结果,接口原语应符合 GB/T48336.301—2026中10.2的规定。</p>

(gbt-48336-302-2026-clause-8-4)=
## 8.4 动态 QoS控制

:::{div}
:class: standard-paragraph

<p>根据 QoS流配置结果和 QoS流监控的结果,QoS管理功能单元可进行动态 QoS控制,使用连接管理功能单元接口原语实时调整传输信道参数,接口原语和参数应符合 GB/T48336.301—2026 中9.2.3的规定。动态 QoS控制具有如下典型使用方式。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>——— 当新建 QoS流时:</p>
<ul class="standard-list">
<li><p>• 如果该 QoS流映射到已有传输通道,则 QoS管理功能单元发起传输通道映射更新请求;</p>
</li>
<li><p>• 如果新建一个传输通道,则该 QoS流映射到该传输通道,QoS管理功能单元发起传输通道建立请求(见示例1)。</p>
</li></ul>
</li>
<li><p>——— 当更新现有 QoS流关联的 QoS参数或 QoS规则时:</p>
<ul class="standard-list">
<li><p>• 如果不改变该 QoS 流到传输通道的映射关系,则 QoS 管理功能单元发起传输通道QoS更新请求(见示例2);</p>
</li>
<li><p>• 如果使用新的传输通道承载更新后的 QoS流,则 QoS管理功能单元发起传输通道映射更新请求以删除 QoS流与源传输通道的映射关系,并发起传输通道建立请求(见示例3)。</p>
</li></ul>
</li>
<li><p>——— 当释放 QoS流时:</p>
<ul class="standard-list">
<li><p>• 如果关联的传输通道与其他 QoS流无映射关系,则 QoS管理功能单元发起传输通道释放请求;</p>
</li>
<li><p>• 如果关联的传输通道与至少一条其他 QoS流存在映射关系,则 QoS管理功能单元发起传输通道映射更新请求。</p>
</li></ul>
</li></ul>

:::

:::{admonition} 注
:class: note

<p>接口原语暂不提供同时为多个 QoS流新建、重配置或释放的功能。如需同时操作多个 QoS流,应分别发起一条接口原语请求。</p>

:::

:::{admonition} 示例1
:class: tip

<p>QoS管理功能单元新建了 QoS 流1 和 QoS 流2,计划新建传输通道$\mathrm{TCID}=x$和$\mathrm{TCID}=y$来分别承载归属于QoS流1和 QoS流2的业务流数据,则 QoS管理功能单元发起两条传输通道建立请求原语来建立两条传输通道。</p>

:::

:::{admonition} 示例2
:class: tip

<p>QoS管理功能单元更新了 QoS流1的参数,QoS管理功能单元选择发起传输通道 QoS更新请求更新承载归属于QoS流1的业务流的传输通道。</p>

:::

:::{admonition} 示例3
:class: tip

<p>QoS管理功能单元更新了 QoS流1的参数,QoS流1已经映射到了传输通道$\mathrm{TCID}=i$,QoS管理功能单元选择使用新的传输通道$\mathrm{TCID}=j$来承载归属于 QoS 流1 的业务流,则 QoS 管理功能单元发起传输通道映射更新请求删除QoS流1到传输通道$\mathrm{TCID}=i$的映射。另外,QoS管理功能单元发起传输通道建立请求原语新建$\mathrm{TCID}=j$的传输通道。</p>

:::
