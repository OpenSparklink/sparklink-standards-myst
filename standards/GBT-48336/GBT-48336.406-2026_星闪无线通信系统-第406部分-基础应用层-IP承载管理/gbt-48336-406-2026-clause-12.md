### 12.1.2 IPoSL 设备能力信息查询

:::{div}
:class: standard-paragraph

<p>IPoSL 设备能力信息查询过程是 IPoSL 管理客户端读取 IPoSL 管理服务端上指定 IPoSL 节点能力属性的过程。该过程是 IPoSL 设备参数配置或重配置的前提。IPoSL 管理客户端获取 IPoSL 节点能力属性信息后，可结合自身的能力和 IP 应用的要求选择合适的参数对 IPoSL 管理服务端进行配置。</p>

(gbt-48336-406-2026-clause-12-2)=
## 12.2 IPoSL IP 报文转发流程

(gbt-48336-406-2026-clause-12-2-1)=
### 12.2.1 通则

:::{div}
:class: standard-paragraph

<p>对于单跳星闪 IP 承载场景，本文件规定的 IP 报文转发流程包含以下两种场景：</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 外网 IP 终端节点向星闪域内 IPoSL 终端节点发送 IP 报文；</p>
</li>
<li><p>—— 星闪域内 IPoSL 终端节点向外网 IP 终端节点发送 IP 报文。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>IP 报文转发在 IPoSL 网关节点上应支持 NAT（Network Address Translation）或 NAPT（Network Address Port Translation）功能。首先在 IPoSL 网关节点上配置公网地址/端口和私网地址/端口的固定映射关系。配置完成后，IPoSL 网关节点将会生成目的 NAT/NAPT 表和源 NAT/NAPT 表，存放公网地址/端口和私网地址/端口的映射关系。</p>

:::

:::{div}
:class: standard-paragraph

<p>在这个过程中，IPoSL 网关节点可将公网地址与私网地址进行一一对应转换。IPoSL 网关节点也可以用同一个公网地址来转换多个私网用户发过来的报文，并通过端口号来区分不同的私网用户，允许多台私网用户共享一个公网 IP 地址访问公网。</p>

:::

(gbt-48336-406-2026-clause-12-2-2)=

:::{div}
:class: standard-paragraph

<p>外网 IP 终端节点向星闪通信域内 IPoSL 终端节点发送 IP 报文转发见图 6。</p>

:::

```{image} ../../../assets/structured/GBT-48336.406-2026/regions/p0023-figure-01-172.png
:alt: 图 6　外网 IP 终端节点向星闪通信域内 IPoSL 终端节点发送 IP 报文转发示意图
:class: source-figure
:width: 423px
```

(gbt-48336-406-2026-figure-6)=
:::{div}
:class: standard-caption

<p>图 6　外网 IP 终端节点向星闪通信域内 IPoSL 终端节点发送 IP 报文转发示意图</p>

:::

:::{div}
:class: standard-paragraph

<p>IP 报文转发流程应符合如下要求：在网络初始建立阶段，星闪域内 IPoSL 终端节点与 IPoSL 网关节点通过设备发现与服务管理标准流程建立链接，两者间建立默认 IPoSL 传输通道。IPoSL 网关节点具有支持 IP 协议的能力，且作为 IP地址分配管理节点向 IPoSL 终端节点分配私网 IP 地址。IPoSL 网关节点建立和维护〈私网 IP 地址，L2ID〉的映射表。</p>

:::

:::{div}
:class: standard-paragraph

<p>在网络初始建立后，外网 IP 终端节点可向 IPoSL 终端节点的目的公网 IP 地址发送 IP 报文，并将外网 IP 终端节点公网 IP 地址作为 IP 报文源地址。</p>

:::

:::{div}
:class: standard-paragraph

<p>IPoSL 网关节点收到该 IP 报文后，IPoSL 网关节点通过目的 NAT/NAPT 技术将报文中的目的公网 IP 地址转换为目的私网 IP 地址。并查询〈私网 IP 地址，L2ID〉的映射表，确定目的私网 IP 地址对应的目的 IPoSL 终端节点的层二标识（L2ID，L2ID）。</p>

:::

:::{div}
:class: standard-paragraph

<p>IPoSL 网关节点根据〈目的私网 IP 地址，DSCP，目的 L2ID〉 本地查询〈IP 地址与传输通道解析表〉，从而获得向目的 IPoSL 终端节点（即目的 L2ID）转发该 IP 报文的传输通道和传输模式信息，即〈目的私网 IP 地址，DSCP，目的 L2ID，TCID，传输模式〉。当查询〈IP 地址与传输通道解析表〉时，分为如下情况。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 若有表项且满足 QoS 要求，则封装基础服务层帧头并确定基础服务层上层协议指示 PI 取值，标识上层协议类型为 IP 协议。</p>
</li>
<li><p>—— 若无表项且有 QoS 要求时（或有表项不满足 QoS 要求），则通过 QoS 协商〈DSCP〉到〈SLQI〉的映射（应遵循 GB/T 48336.302—2026 中 7.4），并根据目的私网 IP 地址查询映射的 IPoSL 终端节点 L2ID 进行传输通道的建立或更新，生成或更新 IP 与传输通道解析表项。从而，封装基础服务层帧头并确定基础服务层上层协议指示 PI 取值，PI 标识上层协议类型为 IP 协议；若传输通道建立失败，则丢弃报文。</p>
</li>
<li><p>—— 若无表项且无 QoS 要求时，则在〈IP 地址与传输通道解析表〉中增加目的私网 IP 地址与默认IP 传输通道映射表项。从而，封装基础服务层帧头并确定基础服务层上层协议指示 PI 取值，PI 标识上层协议类型为 IP 协议。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>IPoSL 终端节点收到数据帧后，通过解析基础服务层帧头携带的 PI 标识上层协议类型为 IP 协议，从而将解封装基础服务层帧头并将 payload 数据上送给 IP 应用处理。</p>

:::

```{image} ../../../assets/structured/GBT-48336.406-2026/regions/p0024-figure-01-172.png
:alt: 图 7　星闪域内 IPoSL 终端节点向外网 IP 终端节点发送 IP 报文转发示意图
:class: source-figure

```

(gbt-48336-406-2026-figure-7)=
:::{div}
:class: standard-caption

<p>图 7　星闪域内 IPoSL 终端节点向外网 IP 终端节点发送 IP 报文转发示意图</p>

:::

:::{div}
:class: standard-paragraph

<p>IP 报文转发流程如下：在网络初始建立阶段，星闪域内 IPoSL 终端节点与 IPoSL 网关节点应遵循 GB/T 48336.301—2026中 6.6.2 定义的被发现方和发现方设备发现配置流程实现设备广播和扫描发现，并建立默认 IPoSL 传输通道。IPoSL 网关节点具有支持 IP 协议的能力，且作为 IP 地址分配管理节点向 IPoSL 终端节点分配私网 IP 地址。IPoSL 网关节点建立和维护〈私网 IP 地址，L2ID〉的映射表。</p>

:::

:::{div}
:class: standard-paragraph

<p>在网络初始建立后，星闪域内 IPoSL 终端节点可向外网 IP 终端节点的目的公网 IP 地址发送 IP 应用报文，并将本设备私网 IP 地址作为 IP 报文的源地址。</p>

:::

:::{div}
:class: standard-paragraph

<p>星闪域内 IPoSL 终端节点将 IP 报文传递给星闪协议栈，根据 IP 报文携带的〈源私网 IP 地址、目的公网 IP 地址、DSCP〉信息查询〈IP 地址与传输通道解析表〉获得 IP 报文下一跳接收节点（即 IPoSL 网关节点）可使用的传输通道 TCID 和传输模式，即〈目的公网 IP 地址，DSCP，网关 L2ID，TCID，传输模式〉。当查询〈IP 地址与传输通道解析表〉时，分为如下情况。</p>

:::

:::{div}
:class: standard-list-block

<ul class="standard-list">
<li><p>—— 若有表项且满足 QoS 要求，则封装基础服务层帧头并确定基础服务层 PI 指示为 IP 协议。</p>
</li>
<li><p>—— 若没有表项，且有 QoS 要求时（或有表项不满足 QoS 要求），则根据目的公网 IP 地址和 QoS协商〈DSCP〉到〈SLQI〉的参数映射（应遵循 GB/T 48336.302—2026 中 7.4），IPoSL 终端节点与 IPoSL 网关节点间建立或更新传输通道，生成或更新 IP 与传输通道解析表项。从而，封装基础服务层帧头并确定基础服务层上层协议指示 PI 取值，PI 标识上层协议类型为 IP 协议；若传输通道建立失败，则丢弃报文。</p>
</li>
<li><p>—— 若没有表项，但无 QoS 要求时，则增加目的公网 IP 地址与默认 IP 传输通道 TCID 映射表项。</p>
</li></ul>

:::

:::{div}
:class: standard-paragraph

<p>IPoSL 网关节点收到星闪数据帧后，通过解析基础服务层帧头携带的 PI 标识上层协议类型为 IP 协议，从而将解封装基础服务层帧头得到 IP 报文，并将 IP 报文中的源私网 IP 地址通过源 NAT/NAPT转换为源公网 IP 地址，封装 IP 报文通过公网转发。</p>

:::
