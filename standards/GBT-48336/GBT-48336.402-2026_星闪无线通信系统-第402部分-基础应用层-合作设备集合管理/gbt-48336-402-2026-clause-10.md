# 10 工作流程

(gbt-48336-402-2026-clause-10-1)=
## 10.1 概述

:::{div}
:class: standard-paragraph

<p>合作设备集合工作流程包括合作设备集合组建、合作设备集合发现与连接、合作设备集合成员移除等。</p>

:::

(gbt-48336-402-2026-clause-10-2)=
## 10.2 合作设备集合组建流程

:::{div}
:class: standard-paragraph

<p>合作设备集合组建流程是集合配置器将一组没有关联的待配置设备配置为提供特定服务的统一整体的过程。进一步的，集合配置器可将待配置设备配置为集合使用者，即可配置集合使用者。可配置集合使用者拥有已知目标集合的集合信息，能够更快地发现与连接目标集合。</p>

:::

:::{div}
:class: standard-paragraph

<p>合作设备集合组建流程可分为两个阶段，阶段一是发现与连接待配置设备，阶段二是配置待配置设备组建集合。</p>

:::

:::{div}
:class: standard-paragraph

<p>阶段一，可分为两种典型方式。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a） 如图 3 所示，集合配置器发送广播，待配置设备接收广播，待配置设备发起连接，其中：</p>
<ol class="decimal-list" start="1">
<li><p>1） 集合配置器发送集合组建邀请广播；</p>
</li>
<li><p>2） 待配置设备通过扫描接收集合配置器发送的集合组建邀请广播；</p>
</li>
<li><p>3） 待配置设备通过广播中的合作设备集合服务标识字段获取待组建集合应支持的集合服务，并判断该服务自己能否支持；</p>
</li>
<li><p>4） 若能够支持，待配置设备向集合配置器发起连接，并与之建立连接。</p>
</li></ol>
</li>
<li><p>b） 如图 3 所示，待配置设备发送广播，集合配置器接收广播，集合配置器发起连接，其中：</p>
<ol class="decimal-list" start="1">
<li><p>1） 待配置设备发送待配置集合广播；</p>
</li>
<li><p>2） 集合配置器通过扫描接收待配置设备发送的待配置集合广播；</p>
</li>
<li><p>3） 集合配置器通过广播中的合作设备集合服务标识字段获取待配置设备支持的集合服务，并判断该设备能否满足待组建集合；</p>
</li>
<li><p>4） 若满足要求，集合配置器向待配置设备发起连接，并与之建立连接。</p>
</li></ol>
</li></ol>

:::

:::{div}

<p>阶段二，如图 4 所示，集合配置器配置选定的待配置设备，组建集合。</p>

:::

:::{div}
:class: standard-paragraph

<p>集合配置器通过 SSAP 协议访问待配置设备承载的合作设备集合管理服务，并通过有响应写入或者无响应写入对合作设备集合管理服务的必选属性进行配置。当所有必选属性配置完成后，待配置设备的配置过程完成，成为集合使用者或集合成员。</p>

:::

:::{div}
:class: standard-paragraph

<p>集合配置器可通过合作设备集合角色将待配置设备配置为集合使用者或集合成员。</p>

:::

:::{div}
:class: standard-paragraph

<p>集合配置器将设备配置为集合使用者时，可通过配置合作设备集合密钥、合作设备集合服务标识等信息将集合使用者与集合成员建立关联关系，使集合使用者拥有已知集合的集合信息。</p>

:::

:::{div}
:class: standard-paragraph

<p>集合配置器可通过合作设备集合设备发现模式配置设备在设备发现过程中的行为。集合使用者和集合成员应分别进行广播/扫描，或者扫描/广播，或者同时进行广播和扫描，以便两者能够相互发现和连接。集合配置器对集合使用者和集合成员行为的配置要求可由集合服务所属的应用标准进行确定，或者由具体实现进行确定。</p>

:::

:::{div}
:class: standard-paragraph

<p>合作设备集合成员可由用户选择，也可由具体实现决定。合作设备集合成员确定后，合作设备集合成员数量应被配置为相应的数值。</p>

:::

## 10.3 合作设备集合发现与连接流程

:::{div}
:class: standard-paragraph

<p>合作设备集合的发现基于设备发现。合作设备集合发现与连接流程的目的是集合使用者连接目标集合的所有集合成员。</p>

:::

:::{div}
:class: standard-paragraph

<p>定义合作设备集合的发现与连接流程的两种情形如下。</p>

:::

:::{div}
:class: standard-paragraph

<p>情形 1，集合使用者已知目标集合的集合信息。其中，集合使用者可通过带外方式（out of band）获取目标集合信息，可由集合配置器进行配置，集合配置器同时为集合使用者，或已连接和访问过目标集合。</p>

:::

:::{div}
:class: standard-paragraph

<p>该情形下，又分为以下三种方式。</p>

:::

:::{div}
:class: standard-list-block

<ol class="alpha-list" start="1">
<li><p>a） 方式 1，如图 5 所示，由集合成员发送广播，集合使用者接收广播，集合使用者发起连接。</p>
<ol class="decimal-list" start="1">
<li><p>1） 集合成员发送合作设备集合广播。</p>
</li>
<li><p>2） 集合使用者通过扫描接收集合成员发送的合作设备集合广播。</p>
</li>
<li><p>3） 发现目标集合，集合使用者通过已知目标集合的集合密钥对合作设备集合广播中携带的集合标识进行验证。如果能够验证通过，说明该集合成员属于已知目标集合。当发现集合成员的数量达到已知目标集合的集合成员数量时，该步骤结束。</p>
</li>
<li><p>4） 集合使用者连接所有目标集合成员。</p>
</li></ol>
</li></ol>

:::

(gbt-48336-402-2026-clause-10-4)=
## 10.4 集合成员移除流程

:::{div}
:class: standard-paragraph

<p>集合配置器通过 SSAP 协议将集合成员的合作设备集合密钥配置为零，将该设备移出合作设备集合。集合配置器应配置其他集合成员的合作设备集合成员数量，使该数值与移除后的集合成员数量一致。</p>
