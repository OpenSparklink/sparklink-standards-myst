# 架构、接入与服务

从一条实际业务出发，可以沿三层架构查到功能定义、消息和接入要求。选一个发送端与接收端，记下设备角色、业务数据、连接方式和服务质量要求，再沿本页追踪。

## 三层在哪里交接

| 层 | 联调时要问的事 | 从哪里查 |
| --- | --- | --- |
| 基础应用层 | 两端承担什么应用角色？要交换的是控制信令还是媒体数据？ | [GB/T 48336.101 §6.2.3 基础应用层](#gbt-48336-101-2026-clause-6-2-3) · [§9 基础应用层要求](#gbt-48336-101-2026-clause-9) |
| 基础服务层 | 如何发现对端、确定服务、建立传输并管理业务的 QoS？ | [§6.2.2 基础服务层](#gbt-48336-101-2026-clause-6-2-2) · [§8 基础服务层要求](#gbt-48336-101-2026-clause-8) |
| 接入层 | 用哪种无线接入？相关资源、帧和节点行为由哪份规范定义？ | [§6.2.1 接入层](#gbt-48336-101-2026-clause-6-2-1) · [§7 接入层要求](#gbt-48336-101-2026-clause-7) |

### 用业务流、传输通道和逻辑信道对齐术语

用三个位置标记同一条数据在系统中的状态。应用侧记录业务流及其质量需求。基础服务层记录承载它的传输通道和通道参数。接入侧记录相应逻辑信道和接入类型。复核映射关系时，从架构图和所选传输流程查实际关系。[GB/T 48336.101 §6.3.2 业务流](#gbt-48336-101-2026-clause-6-3-2) · [§6.3.3 传输通道](#gbt-48336-101-2026-clause-6-3-3) · [§6.3.4 逻辑信道](#gbt-48336-101-2026-clause-6-3-4)

## 例子 · 从发现对端到第一条业务数据

1. **先读业务的角色和拓扑。** 若在调试音视频，先明确源端、接收端和预期拓扑，再选对应流程。[音视频配置与传输](media-guide.md)
2. **核对设备发现结果。** 在发现请求和结果中对照设备角色、公开信息和过滤条件，确认上报的是要连接的对端。[GB/T 48336.301 §6.2 角色](#gbt-48336-301-2026-clause-6-2) · [§6.3 公开信息](#gbt-48336-301-2026-clause-6-3) · [§6.4 过滤](#gbt-48336-301-2026-clause-6-4)
3. **核对服务匹配。** 确认发现结果里相应服务的标识与配置，检查服务管理流程是否完成。[GB/T 48336.301 §7 服务管理](#gbt-48336-301-2026-clause-7)
4. **追踪传输通道。** 将业务、通道和所选接入方式关联起来。协商通道参数时回查建立与重配置流程。若问题表现为时延或可靠性与预期不符，再核对业务 QoS 与资源配置过程。[GB/T 48336.301 §9.4 传输控制流程](#gbt-48336-301-2026-clause-9-4) · [GB/T 48336.101 §8.3 QoS 管理要求](#gbt-48336-101-2026-clause-8-3) · [GB/T 48336.302 §6 QoS 管理框架](#gbt-48336-302-2026-clause-6)

## 联调时先找断点

| 现象 | 先拿什么证据 |
| --- | --- |
| 对端设备没有出现在发现结果里 | 发送端公开信息、接收端过滤配置和发现结果。[§6 设备发现](#gbt-48336-301-2026-clause-6) |
| 能发现设备，业务仍无法启动 | 服务匹配结果、应用会话的控制信令、通道建立记录。[§7 服务管理](#gbt-48336-301-2026-clause-7) · [§9.4 传输控制流程](#gbt-48336-301-2026-clause-9-4) |
| 通道已经建立，业务数据异常 | 首个丢失或异常的数据单元、通道参数和相应接入观测。[§8 数据传输与适配](#gbt-48336-301-2026-clause-8) · [§7 接入层要求](#gbt-48336-101-2026-clause-7) |
