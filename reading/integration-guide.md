# 星闪与 5G 融合

联调时先选定 GB/T 48336.304-2026 的融合系统类型和观察节点，再分别追踪控制面的建链、注册与会话，以及用户面的转发与 QoS。两条路径的状态可以分别记录，用同一会话和业务流关联。

## 选定融合类型和观察位置

| 场景 | 阅读入口 |
| --- | --- |
| 类型一，需要对照可信星闪接入网络和 5G 核心网的交互 | 先看系统架构图，再按 T 节点的接入、注册和会话流程读。[§5.2.1 类型一](#gbt-48336-304-2026-clause-5-2-1) · [§6.4.2 会话建立](#gbt-48336-304-2026-clause-6-4-2) |
| 类型二，需要确认 G 节点和 T 节点各自的流程 | 先看网络架构，再打开当前观察节点的会话建立条款。[§5.2.2 类型二](#gbt-48336-304-2026-clause-5-2-2) · [§6.4.3.1 G 节点](#gbt-48336-304-2026-clause-6-4-3-1) · [§6.4.3.2 T 节点](#gbt-48336-304-2026-clause-6-4-3-2) |
| 已知消息或数据，想找它经过的接口 | 在控制面或用户面协议栈图里确认位置，记下两端功能单元和接口。[§5.3.3 控制面](#gbt-48336-304-2026-clause-5-3-3) · [§5.3.4 用户面](#gbt-48336-304-2026-clause-5-3-4) |

## 沿一次接入追踪控制面

1. **可信 G 节点。** 在类型一里保留服务发现结果、候选节点和选定节点，按选择与维护条款回查切换条件。[§6.1.2 选择机制](#gbt-48336-304-2026-clause-6-1-2) · [§6.1.3 维护机制](#gbt-48336-304-2026-clause-6-1-3)
2. **接入和注册。** 对照所选类型的注册过程，区分星闪接入链路的状态和 5G 核心网侧的注册结果。需要读接入会话的请求和响应时，可从消息定义跳回流程。[§6.2 注册](#gbt-48336-304-2026-clause-6-2) · [§8.1.2 接入会话建立请求](#gbt-48336-304-2026-clause-8-1-2) · [§8.1.3 接入会话建立响应](#gbt-48336-304-2026-clause-8-1-3)
3. **PDU 会话与关联。** 按所选类型的会话建立图确认发起方和返回方。对照关联请求与响应核对字段，保留会话建立、修改或释放前后的关联状态。[§6.4 会话建立](#gbt-48336-304-2026-clause-6-4) · [§6.5 修改](#gbt-48336-304-2026-clause-6-5) · [§6.6 释放](#gbt-48336-304-2026-clause-6-6) · [§8.1.8 关联请求](#gbt-48336-304-2026-clause-8-1-8) · [§8.1.9 关联响应](#gbt-48336-304-2026-clause-8-1-9)

### 例子 · 业务中断，追踪可信 G 节点资源释放

先找 PDU 会话关联响应并核对去激活定时器是否配置。未配置时，维护条款规定默认时长为无穷大。已配置时，按图 16 和正文检查启动或重启条件，同时核对 T 节点是否检测到与 5G 核心网的连接异常。将响应、最近一次定时器事件、连接状态和实际资源释放放在同一时间线上。[图 16 可信 G 节点维护流程](#gbt-48336-304-2026-figure-16) · [§6.1.3 维护机制](#gbt-48336-304-2026-clause-6-1-3) · [§8.1.9 PDU 会话关联响应](#gbt-48336-304-2026-clause-8-1-9)

## 会话建立后追踪用户面

| 现象 | 查验顺序 |
| --- | --- |
| 会话已有，业务包未转发 | 先识别使用基于 IP 还是基于端口的转发，按相应条款对照两端的转发表和同一业务包的入口、出口。[§6.7.1 基于 IP](#gbt-48336-304-2026-clause-6-7-1) · [§6.7.2 基于端口](#gbt-48336-304-2026-clause-6-7-2) |
| 已经转发，但业务待遇不符合预期 | 按类型查 QoS 流程，再对照会话中实际使用的 QFI 和 XQI 信息元素。[§7.1.2 类型一 QoS](#gbt-48336-304-2026-clause-7-1-2) · [§7.1.3 类型二 QoS](#gbt-48336-304-2026-clause-7-1-3) · [§8.2.1 QFI](#gbt-48336-304-2026-clause-8-2-1) · [§8.2.7 XQI](#gbt-48336-304-2026-clause-8-2-7) |
| 需要区分信令失败和用户数据中断 | 分别核对两种状态监测记录，再和注册、会话、业务包时间对齐。[§7.2.4 控制面状态监测](#gbt-48336-304-2026-clause-7-2-4) · [§7.2.5 用户面状态监测](#gbt-48336-304-2026-clause-7-2-5) |
